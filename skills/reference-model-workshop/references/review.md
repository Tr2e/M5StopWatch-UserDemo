# 两轮审查与可验证证据

## 第一轮：结构

对照模型卡与参考看俯视、侧视、正面、背面和两侧斜视，先查比例／腰线／通道，再查部件、厚度、附件。记录具体偏差、部件／坐标／修改、断言与复验。修正后重看相关视角和所有 LOD。没有发现也写明实际核对项及局限。

## 第二轮：生产显示与回归

看实际选车、放大展示、各视角到位和动画过渡、最低档、玩家／近距离对手（非赛车项目选真实使用场景）。查 UV 方向、字样、埋入或浮起的贴花、遮挡、穿透、裁剪、安全区和缩小后的辨识度。修正后重跑相关测试和完整项目回归。

与修改前基线比未改模型和场景。受影响共享模块要列出全体受影响模型并复验；不要把有意变化当失败，也不能悄悄接受无关变化。先比较**解码像素**，PNG 压缩器和元数据差异不代表视觉变化。

## 证据自身的检查

- 文件名不是车型身份。驱动真实状态机确认目标模型；画面模型名／可识别结构与场景配置一起核对。不同模型截图完全一致应报警；不同哈希仍可能只是 UI 字不同，不能因此认定模型正确。
- 不用 AI 效果图、重绘图或图像修饰代替生产渲染。拼图只加标签、留白，不缩放／修饰原帧；需裁剪分析时保留原图并标注裁剪。
- 合法对手配置、清晰取景与极近裁剪压力测试两者都保留；美观截图不能替代压力用例。
- 材质生成、结构渲染、实际使用场景应取自同一生产资产。记录 commit、渲染命令、相机与 LOD，避免拿旧图当本次证据。

## 自动证据工具

依赖 Python 3.10+ 与 Pillow。复制并填写 `assets/evidence-manifest.json`：`schema=1`；每个 `models[]` 有唯一 `id`、非空 `required_views`，以及 `frames`。每个帧需唯一 `view` 和相对帧根目录的 `file`，可选 `baseline_file` 和 `expect_unchanged`。`identity_view` 指定跨模型重复图检查角色。模板只是单模型格式示例，须替换为实际清单；StopWatch 有完整八车清单。

```sh
python3 /path/to/reference-model-workshop/scripts/check_evidence.py \
  --manifest /path/to/filled-manifest.json --frames /path/to/production-frames \
  --baseline /path/to/baseline-frames --output /tmp/new-review-directory
```

输出目录必须不存在，避免覆盖旧证据。`--baseline` 可省略；但任何 `expect_unchanged: true` 的帧必须提供基线，否则失败。文件支持 Pillow 可解码格式；根目录外路径／符号链接、重复模型或视角、缺失必需视角、坏图片均失败。工具生成每模型原尺寸拼图和 `report.json`，状态字段是 **evidence_checks_passed**，不是美术验收结论。

`id`／`view` 使用 1–64 字符的小写 ASCII 字母、数字、连字符或下划线（首字母／数字）。清单拒绝未知字段，防止把 `expect_unchanged` 拼错后悄悄跳过回归；中文描述保存在模型卡，不放进字段名或视角 ID。

失败退出码 1；参数／清单无效退出码 2。即使图片存在，仍须人工看图并完成两轮记录。去重只比较指定身份视角，检测不到“模型相同、背景或 UI 不同”的情况。

运行 `python3 -m unittest discover -s /path/to/reference-model-workshop/scripts -p 'test_*.py'` 可自测坏图、漏图、路径逃逸、重复图和解码像素比较。

## 完成条件

模型卡、两轮问题与修复、生产证据、自动检查、项目编译／导出、预算均具备后才标记软件阶段完成。真机 FPS、内存余量、显示观感、控制手感应单列“待设备验收”。用户只要求检查时交付问题，不擅自进入修改、提交或发布。
