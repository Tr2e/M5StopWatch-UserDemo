# 材质、贴花与显示

## 材质卡应明确的映射

每个部件记录底色、表面类型、纹样／文字来源、UV 方向、左右策略、透明或不透明方案以及低档处理。颜色来自锁定版本；强调色与“手绘感”不能改掉官方主要配色和结构边界。

- 先分车壳、玻璃、橡胶、金属、内腔；玻璃保留框线和斜度，不给整个座舱包一层圆润高光。
- 纹样跟随表面 UV，不在世界坐标中漂移。普通贴花优先同一表面采样；确需分离 decal 时遵守引擎深度偏移方案并复查近远视角。
- 对称几何不等于所有贴图都水平镜像：火焰可以沿部件方向，文字应读得对。逐侧定义 UV 和左右专属字样，检查车库／比赛坐标变换后结果。
- 不知道字样不乱编微字；小屏优先留主要色块、边界与有证据的标识。高频条纹易锯齿；以实际比赛尺寸检查，不只看放大图。
- 网格状蛛网要有沿形体弯曲的横向连接，不是从一个点放射的星纹；进气口的深色只是内腔材质，不能替代厚度、内壁和退后的后盖。

## 方法选择

| 目标项目 | 合适资产 | 不应强加的实现 |
| --- | --- | --- |
| StopWatch 软件渲染 | RGB565 底色 + 分面明暗 + UV 程序色块／字样 | 不强行引入 PBR、外部纹理或额外透明层 |
| 常规实时引擎 | 引擎原生材质、UV 纹理与必要的法线／粗糙度 | 不照搬本项目的逐像素 C++ 分支或 2,048 面限制 |
| DCC 源模型交付 | 可编辑结构、材质节点、贴图与可重现导出设置 | 不以烘焙外观抹掉必须保留的真实开口 |

记录纹理分辨率／格式／色彩空间和 mip 策略（如适用）。程序纹样记录 UV 域、颜色精度与采样成本；不虚称已有 PNG/PBR 贴图资源。压缩或烘焙后重新看实际引擎输出。

## 渲染关联检查

新写软件渲染器时，透视 UV 需插值 `1/z, u/z, v/z` 后相除；近裁剪应先于投影，投影边界转整数前夹紧。已有引擎使用其正规管线，不另造一套。

检查车壳遮挡贴花、近景深度闪烁、视口／圆屏裁剪和桥面遮挡；不能靠“最后画车／桥”解决空间前后关系。拆 tile 的近景渲染应与整体渲染相同，附加部件不能超出既有投影包围盒后被裁掉。

动画标签独立于部件颜色。轮动相位用运动距离累计避免速度变化跳相；展示动画按当前项目交互设计执行。StopWatch 的“只有侧视图到位后转轮”是用户的局部设计，不推广成所有模型的规则。

## 性能不能只靠截图判断

每档记录几何、材质、缓存与峰值工作区成本；避免逐像素高成本重复运算、逐帧分配和大栈数组。缓存生命周期与候选模型数量分开，测试重新入场、换车型、换画质和参与者增减的失效逻辑。主机运行时间不是目标设备 FPS。
