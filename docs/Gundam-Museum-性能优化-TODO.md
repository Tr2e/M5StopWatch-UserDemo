## 1. 目标与边界

本轮目标是将 Gundam Museum 的 RX-78 拖动旋转无限接近 15 FPS，同时降低渲染工作集对 PSRAM 的依赖。在穷尽并实测完所有无损方向前，不把差距归因于 CPU 上限。

2026-09-22 决策：本计划只包含 RX-78 实体渲染，其他模型不在本轮范围内。

默认不以下列方式换取性能：

- 不删除、简化或替换模型几何与装备。
- 不改变已确认的相机包络、构图、材质和明暗。
- 不降低内部分辨率、采样率或色彩/深度精度，不引入动态画质降档。
- 不改变 RX-78 的实体着色、遮挡、边界和等深覆盖结果。
- 每个候选默认保持完整 framebuffer 逐像素一致；若仅有有限、稳定且不影响整体观感的孤立像素差异，必须量化影响帧比例、总像素、最坏帧、空间分布和连续姿态闪烁后再决定是否进入真机。
- 不将主机耗时直接宣称为真机 FPS 收益。
- 不在没有同设备、同场景 A/B 时宣称优化完成。

现有的共享顶点投影、朝向缓存、背面剔除、纯色快速路径、产品已有的 65%/100% 交互状态和按需刷新应保留；本轮以现有 65% 拖动帧为基准，不再降低其采样比例。

2026-09-21 RX-78 fast path 进度：接受 solid scanline span、trusted depth、framebuffer span transaction、native framebuffer composite 和稀疏深度清理。最后一项在整屏哈希逐字节一致的前提下，使当前 65% draw 从 123.08 ms 降至 121.89 ms，含 present 约 133.63 ms（约 7.48 FPS）。完整接受/否决证据见 [`assets/gundam-museum-rx78-fastpath-20260921/README.md`](assets/gundam-museum-rx78-fastpath-20260921/README.md)。距离 15 FPS 仍远，不能归因于 CPU 上限。

- [x] 验证在可信纯色热内核中将相邻两个像素的 depth/color 各合成一次 32-bit 事务。6,720 组主机与真机哈希一致，但双像素路径需要并行维护两套重心和通过掩码，main/worker raster 由约 32.8/34.7 增至 37.3/39.5 ms，3×96 帧周期为 76.413/76.341/76.345 ms，较 71.799 ms 基线慢约 4.56 ms，已完整回退。连续平面上的宽写不能以增加算术和寄存器压力为代价。
- [x] 验证三角形 setup 预计算的两种粒度。将两个 `1/det` 携带进每个命令会把 52 B 命令扩回 60 B、工作集增加 32 KiB，panel prepare 约 11.1→14.0 ms，5×96 帧约 76.27–76.34 ms；只为上下带共同消费的面建立独立 setup 旁路、不扩主命令时，panel prepare 仍增至约 11.62 ms，3×96 帧为 72.903/72.862/72.860 ms。两者哈希均 canonical，但都慢于 71.799 ms 基线，已回退。当前图元 setup 更适合在各核就地计算，串行预计算与旁路读取成本高于消除少量重复除法。
- [x] 实现保留 ABC→ACD 覆盖顺序、原重心深度公式和 Q13 写入语义的逐行精确四边形内核；两个三角形共享行循环，但分别求精确行区间，避免旧联合外轮廓方案的过扫描和逐像素分类。主机 6,720 组回归逐像素一致；虽然主机孤立微基准约慢 2%，真机 10×96 帧均值由 71.799 降至 70.228 ms（14.239 FPS），减少 1.571 ms，全部批次保持 `1794963570:3828763871`，已接受。MCU 结果证明，在热光栅中减少重复外层控制与改善访存/分支行为的价值可以超过额外行区间计算，不能只用桌面机微基准否决。
- [x] 在前四项仍未达 15 FPS 后启动 20 行片内微带：上半屏深度/颜色共用 22,080 B 片内工作集，带结果直接扩展到最终 framebuffer，不回写 PSRAM；下半屏仍与主核并行。真机确认微带实际启用，每帧约 2,414 个有序带成员；但重复 setup/回放使 panel prepare 约 10.1→11.4 ms、主核阶段约 32.2→36.7 ms，帧尾 composite 仅 5.15→4.04 ms，8×96 帧稳定约 75.08–75.15 ms，且哈希变为 `2103724662:3711746231`。性能与正确性均不达标，已完整回退。除非能证明跨带图元可以持久化 setup/边状态且不改变覆盖语义，否则不再重开微带回放。

完成标准：只接受真机端到端帧时可重复下降、内存与栈余量可控的改动。画质默认要求完整 framebuffer 一致；若有差异，必须量化影响帧比例、总像素、最坏帧、空间分布和连续姿态闪烁，只允许整体观感不受影响的有限孤立差异。

## 6. P3：屏幕清理与提交策略

该项与条带光栅分开验证，避免无法归因。

- [x] 量化整屏与 dirty-tile 提交边界；房间网格使 16/24/32 瓦片方案分别覆盖 86.6%/95.2%/99.5%，8 瓦片又产生约 410 个 run，已达停止门槛。
- [x] 用 48 个连续 RX-78 全帧样本量化新旧帧瓦片并集：16×16 平均覆盖 86.6%，24×24 为 95.2%，32×32 为 99.5%；8×8 虽降至 71.0%，却平均产生约 410 个水平 run。房间线使每个 tile row 的单 bbox 都扩成全屏宽，已达到“超过 80% 或事务过多”停止门槛，不实现 HAL 多矩形提交。
- [x] 用旧房间线段擦除 + 上一帧模型占用位图验证稀疏 framebuffer 恢复；零散写显著慢于连续整屏填充，已否决。
- [x] 在满足原生 RGB565、rotation 0、偶数宽度、4-byte 对齐与 stride guard 时使用 32-bit 成对连续清屏；收益很小但稳定且整屏哈希一致。
- [x] 验证 CPU0/CPU1 各清一半完整 framebuffer；哈希一致，但 80 MHz PSRAM 顺序写带宽已经饱和，周期最多仅改善约 0.1–0.2 ms，复杂度不值得保留，已回退。
- [x] 将旧网格擦除进一步改成复刻 M5GFX Bresenham 规则的原生 framebuffer 直写；哈希仍为 `1794963570:3828763871`，但稀疏模型恢复加网格擦除的 background 仍约 14.3 ms，高于整屏连续清理约 12.3–12.7 ms，周期约 90.6 ms，整条稀疏 framebuffer 清理路线已回退。
- [x] 为直接渲染 App 增加可选双 framebuffer 异步整屏提交；上一帧的 QSPI DMA 在 CPU1 常驻任务中发送，下一帧在独立 PSRAM 缓冲上渲染，退出时等待传输并恢复最后已提交缓冲。6,720 组主机回归及 14×96 帧真机哈希一致；同步 `present` 11.9 ms 降至约 0.095 ms，传输与清屏的 PSRAM 争用使 background 12.4→17.9 ms，但稳态周期仍从 85.49 降至 79.10 ms（11.70→12.64 FPS），净省约 6.39 ms，已接受。
- [x] 将异步面板提交从每行一次 DMA 改为每 4 行打包一次；10×96 帧哈希一致，panel tx 约 18.00→17.55 ms，周期 78.63→78.52 ms（约 12.74 FPS）。额外约 5.6 KiB 片内 DMA 缓冲，最大连续块仍为 9 KiB。8 行仅到约 17.51 ms 却把 internal free 压到 15.9 KiB，因此保留 4 行并回退 8 行。
- [x] 根因化 PSRAM framebuffer 直连 GDMA。32/64 行分批的真实 80 MHz 版本将周期从 74.43 降至 69.22 ms，但 AMOLED 花屏。加入 SPI2 `outfifo_empty_err` 硬件采样和正确 cache msync 后，证实 80 MHz 几乎每个 DMA 批次 TX underflow；此前仅调用 `setClock(40 MHz)` 的尝试后来确认没有改动底层 SPI2 时钟，因此不能作为 40 MHz 证据。进一步实现 128 行批次、欠载后重设窗口并最多重传三次、最终 SRAM bounce 的可靠性版本：26.67 MHz 在同优先级双核渲染负载下每 96 帧出现 169–181 次欠载，周期 82.18–82.73 ms；20 MHz 三批 96 帧仅 0/0/1 次欠载，但周期仍为 78.91–79.05 ms。两者帧缓冲哈希均保持 canonical，重传机制也没有换回性能收益。结论是花屏根因确为 PSRAM→GPSPI/GDMA 供数断流，不是像素排列/行描述符计算错误；69.22 ms 是未完整传输时的无效收益。一旦可靠送达，直连慢于 4 行 bounce 的 74.42 ms，当前实现已回退。未来只在硬件/仲裁条件改变，或有新的背压实现能经实际面板验收且端到端快于 74.42 ms 时重开。

预期：仅将整屏缩到 424×424 的最大面积收益约 18%，实际收益还要扣除房间线和多矩形事务开销。

## 8. 决策门槛

### 无损候选停止门槛

任一成立即回退：

- 真机帧时无可重复改善；
- 面片重复处理抵消了 internal RAM 收益；
- internal RAM 分配破坏任务栈、驱动或其他 App 的安全余量；
- 候选出现可见轮廓/遮挡破坏、连续姿态闪烁、或未经量化证明的帧缓冲差异。

### 继续门槛

候选必须同时通过主机画质回归（逐像素一致或符合上述有限差异门槛）、真机整屏哈希/差异稳定性、同场景多批 A/B 和内存/栈余量验收；局部阶段变快但整帧无收益时不保留。

## 9. 每轮证据清单

每个候选至少保留：

- commit 和固件 SHA-256；
- 测试命令与退出码；
- ASan/UBSan 结果；
- 逐像素比较结果；
- RX-78 关键视角拼图；
- 真机原始日志；
- 解析后的 draw/present/阶段/FPS 表；
- 内存、栈和退出回收数据；
- 候选与基线的明确结论，包括被否决的试验。
