## 1. 问题结论

M7 碰撞代数本身可重复，但它与屏幕中的战机和悬崖不在同一视觉坐标系，因此会出现明显“隔空碰撞”。基线诊断数据：

| 场景 | 碰撞瞬间视觉误差 |
| --- | ---: |
| 左侧事件中心 | 机翼与墙缘约 `235 px` |
| 右侧事件中心 | 机翼与墙缘约 `202 px` |
| `alt=0.19, pitch=-12°` 触地 | 战机中心与最近谷底线纵向错开约 `82 px` |

根因不是一个阈值，而是四个不一致：

1. 战机以 `12 px/世界单位` 横移，地形在战机附近约为 `180…220 px/世界单位`；
2. 相机不跟随横移，但完整跟随 `±12°` 俯仰；战机则只做极弱的俯仰位移；
3. 碰撞读取相机所在的 `playerWorldS`，屏幕战机实际代表相机前方的一段纵向包络；
4. `leftWidth/rightWidth` 是谷底边缘，视觉墙面随高度向外倾斜，碰撞却把谷底边缘当成垂直墙。

## 2. 统一几何设计

### 2.1 追尾相机

- 相机横向位置跟随 `FlightState::lateralOffset`；
- 战机屏幕中心不再重复应用横移；
- 相机只跟随战机俯仰的 `12%`，保持第三人称追尾构图稳定；
- 战机自身线框使用真正的局部 3D pitch 旋转，roll 继续作用于完整轮廓。
- 第三轮把战机中心从 `y=335` 上移至 `y=320`：距 466 px 屏幕底部 `146 px`（31.3%），位于峡谷中部偏下；
- 航道偏差标尺从 `y=294` 上移至 `y=278`，与战机中心保留 `42 px`，避免姿态变化时叠压。

### 2.2 战机碰撞包络

相机前方使用三个纵向站位，表示当前屏幕战机占据的世界空间：

| 站位 | 前向距离 | 横向半宽 |
| --- | ---: | ---: |
| 尾部/发动机 | `1.10` | `0.10` |
| 主翼 | `1.85` | `0.24` |
| 机鼻 | `2.45` | `0.07` |

碰撞只检查这三个当前机体站位。机鼻之后的 `4.8` 单位仍只用于预警，不直接触发 IMPACT。

### 2.3 高度相关墙面

墙面横向位置按显式截面的高度分段线性插值：

```text
高度:   0.00   0.38   1.06   3.34   3.80
外扩:   0.00   0.20   0.49   0.86   1.14
```

碰撞使用 `floorWidth + wallOutset(altitude)`，与屏幕实际绘制的 Toe / FaceLow / FaceHigh / Cap 共用同一几何含义。

### 2.4 地面阴影

首轮错误地把三个碰撞站位连接成实心投影。低视角透视把纵深 `0.96…2.45` 拉成长条并覆盖大片谷底网格；该候选经真机截图 Review 明确否决。

第二轮把阴影与碰撞包络解耦：

- 只绘制战机正下方的扁平椭圆投影，不再连接纵深站位；
- 最大范围严格限制为 `32 × 8 px`，高空缩小到 `20 × 4 px`；
- 随战机上移后中心纵坐标同步限制在 `355…379`，不会向远端峡谷延伸或压住底部 HUD；
- 高度越低越靠近战机下缘、亮度越高；高度升高时稍向下移动、缩小并淡出；
- 阴影仍在地形之后、战机之前绘制，但只遮盖极少量地面网格。

## 3. HUD 调整

- `ALT` 改为 `AGL`，显示机腹对地净空而非抽象中心高度；
- 前视警告细分为 `PROX LEFT`、`PROX RIGHT`、`PULL UP`；
- 实际碰撞细分为 `IMPACT LEFT/RIGHT/FLOOR`；
- 只有 `impactHazard` 才显示重开提示；前视 warning 不锁死战机；
- 姿态梯继续显示真实 pitch/roll，与动态战机线框一致。
