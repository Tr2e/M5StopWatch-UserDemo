# R25：模型制作资产提取

日期：2026-09-09。目标是回顾建模、贴图与逐车优化全过程，形成以后可执行、可编辑、可检查的制作资产，不再重做八台车外形。

统一入口：[模型制作资产库](模型制作资产库.md)。模型历史基线为 `8c47448`；执行期间仓库加入外设输入／音频修复 `4d2d477`，本轮完整回归与固件构建包含该提交。外设相关工作保留，不纳入本轮模型资产提交。

## 1. 提取了什么

- 版本化技能 `skills/reference-model-workshop/`，并安装到个人技能目录同名文件夹；后续可以 `$reference-model-workshop` 调用，仓库副本不会自动同步到安装副本。
- 通用结构方法、材质／显示方法、两轮审查与证据规范；StopWatch 坐标、缓存、面数、交互单独放适配页。
- 可填写的结构／材质／CR／预算制作卡；通用证据清单模板和已填好的八车 × 11 帧清单。
- `model/car_mesh_builder.h`：从现有生产文件机械提取共用 Builder，八台车仍实际使用它。独立车型函数、坐标、材质采样器、面片顺序未改变。
- 自动证据工具：图片存在／解码、必需视角、展示身份帧重复、解码像素基线、原尺寸拼图和 JSON 报告；带 13 项行为测试。
- 在车型规范和本 App `AGENTS.md` 接上固定入口。第九台新增的掩码／存档迁移风险已明确标注。

当前涂装是 RGB565 + 表面 UV 程序采样，不是外部 PNG 贴图或 PBR 材质包。保留 `car_paint.h` 与 `car_surface_raster.h` 为生产单一来源，以索引与契约复用，不复制出第二份会失步的实现。没有打包田宫参考照片。

## 3. CR1：结构与复用契约

检查共用代码提取边界、八车调用、缓冲区和部件契约，复核方法是否将局部经验错误泛化。

- 纠正复用边界：`wheel`／`roller` 带本项目尺寸，`box` 无底面，`tube` 无端盖，`duct` 固定朝 +z 且 `shell=0` 有哨兵含义；均写入适配契约。部件库不是任意外部文件解析器。
- 明确截面至少两行、z 递增／非零跨度、合法 12／18／24 段和有效缓冲区；保留原算法，未为抽取擅自改变造型或参数。
- 把通用 LOD 原则与本项目三档容量分开，品牌／私人用途与工具方法分开，采样无穿透与解析证明分开。
- 新增独立头文件测试：空容量与单面容量溢出、镜像轮罩 UV、三档凹口深度和壳色、零长／竖直管体；ASan／UBSan 通过。
- 全八车几何测试通过，面数和缓存未改变；不对轮胎包络放宽容差。

## 4. CR2：证据工具与实际画面

逐台打开八份 11 帧拼图，确认选车／展示模型名与结构匹配、视图排布完整、比赛玩家和对手主体存在；这次只做提取回归，不声称重新认证照片还原精度。

- 工具第一版会接受未知字段，拼错 `expect_unchanged` 可静默跳过不变门禁。修正为严格字段校验，加入故意拼错字段的测试。
- 对 PNG 不同压缩级别、PNG／PPM 跨格式做解码像素一致测试；对真实像素变化验证失败，对已声明有意变化保留差异而不误报。
- 覆盖缺图、坏图、缺必需视角、重复身份帧、缺基线、路径逃逸／符号链接、重复 ID／视角、错误类型及已存在输出目录。
- 验证拼图中的原帧像素没有缩放或重绘。身份去重只报警完全相同的指定帧；不同哈希不证明不同模型，仍保留状态机与人工检查。
- 补技能源目录 Python 缓存忽略规则，安装时排除缓存。默认 Python 无 PyYAML，改用已有 ESP-IDF Python 执行技能校验，未改全局依赖。

## 6. 后续使用与未验收项

新增模型先复制制作卡、锁版本与参考，然后结构 → 材质 → CR1 修复 → CR2 修复 → 完整门禁 → 按本次授权阶段提交。跨项目改用目标引擎的原生资产与预算，不强制采用这里的 C++ 格式。

真实设备 FPS、PSRAM 实时余量、AMOLED 观感和操作手感仍待设备验收；手工参数模型仍非官方 CAD。此次不公开发布、不烧录、不 push；外设规范与其他工作区改动不混入模型资产提交。
