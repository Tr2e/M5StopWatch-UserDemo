# SDEX v3：嵌入式大眼

## 本轮合同

用户指出眼睛“像是贴在面罩上”，并明确补充：“我倒是喜欢之前的大眼睛风格，但是要求大眼睛不要贴到面罩上”。因此保留 SDEX009 命运 / SDEX002 强袭与各自绿/黄眼配色，**大眼风格以用户本次要求为准**；撤回 v2 将狭长眼窗当作目标及其眼高宽比上限。不是更换官方产品版本，也不借此修改其他身体、装备、尺度和共享渲染器。

从 pipeline G4/G5 进入局部返修；依次命运→强袭，每台两轮。基线为 `c4b6125` 及 `docs/assets/gundam-sd-{destiny,strike}-v2` 的同相机生产图。官方图在 v2 已实际查看，本轮复用其眼眶/眉檐/颊框分件依据；眼睛大小按用户偏好风格化，不将新尺寸写成官方实测。

## 根因

旧实现用 `cover(黑眼框)`、`cover(彩色眼片)` 前后叠加。彩色片比眼框更靠前，黑色只有平面边框，缺少从眼眶口沿向内部退入的四壁；眼片和面罩上缘的高度与深度未统一安排。v2 缩眼只改变轮廓，不能修复这一拓扑问题。

新实现使用独立的口沿→内壁→镜片斜边连续网格，镜片嵌于凹腔内；移除旧叠片，面罩上缘与下眼眶直接回接，鼻梁保留在双眼之间。镜片不是悬空在眼窝里：它与内壁共享斜边顶点。模型全程使用原有不透明 RGB565/生产光栅，无透明或后绘覆盖技巧。

## 命运：CR1 / CR2

CR1 删除叠片并建立大眼凹腔，观察正、斜、侧近景：侧视镜片随眼窝边缘遮挡，前后关系成立。首轮口沿下边过低导致面罩被压短，随后把下眼眶提高到内角 y=2.385、外角 y=2.415，保留大眼面积同时恢复面罩高度；红泪痕跟随下眼眶移回面甲，不横跨镜片。

CR2 首次检查中心和内缩55%的四角通过，但随后在强袭斜视发现颊甲伸入眼角，扩大采样到内缩90%的近角点并回跑命运，实际拦截了眉檐压住镜片上角（x=-0.066564、y=2.50564，镜片z=0.4397，前方头面z=0.529037）。因此撤回首次“眼部检查充分”的结论；中心采样和小图审阅不足以排除边角遮挡。

补修把命运眉檐下缘与眼窗口沿对齐，颊甲内缘移到窗口外，并补上眉檐/外眼眶连接面；镜片尺寸不变。重新生成全部生产证据并查看正、两斜、侧面、仰/俯眼部放大、原生静止、完整装备65%与全部48帧旋转。镜片在口沿后方，低俯仰可见上/下内壁、斜视可见内侧壁；前视中心及近四角不再被旧头面遮住。原生大眼仍可辨，未观察到明显悬空、跳面或眼色跑到面罩上。放大诊断仅聚焦眼区，天线可能出画；完整装备裁剪另行通过。

命运最终3576面（v2为3590，首次v3为3568）；镜片距口沿平面最小Z退入0.064，镜片正面高宽包围盒比0.60。864组ASan/UBSan通过；内部/埋面/局部刷新差异0，边界差异累计10、单例2；整机边界0，既有装备相交门禁未放宽。新增测试：镜片退入、口沿/内壁/镜片共享连接、完整头部前向射线中心及两组内缩角点无遮挡，以及镜片前移/额外白盖遮眼的受控负例。数字验证结构，不等于用户外观认可。

证据：[命运同相机前后](assets/gundam-sd-destiny-v3-eyes/destiny-before-after.png)、[仰视眼窝](assets/gundam-sd-destiny-v3-eyes/study-eyes-below.png)、[旋转](assets/gundam-sd-destiny-v3-eyes/destiny-orbit.gif)。
