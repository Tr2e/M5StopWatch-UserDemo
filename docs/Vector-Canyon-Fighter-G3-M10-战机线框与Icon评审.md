## 1. 实现边界

- Launcher Icon 使用已确认的 `200 × 200` RGB PNG，经离线工具转换为 LVGL RGB565 固件图片；
- 游戏内战机不加载 PNG、不使用 Sprite、不使用透明贴图；
- 游戏内只使用三维顶点、结构参数和屏幕透视线段实时绘制；
- 地形、HUD、尾焰、阴影、姿态和碰撞仍保持相互独立。

这使启动器保留高辨识度图片，同时保证游戏内战机可以进行真正的 pitch / roll 三维姿态变化，线框内部也能继续透出峡谷。

## 2. 新战机结构

新模型依据已确认 Icon 中的工程线稿结构重构，不尝试逐像素临摹：

| 部件 | 结构 |
| --- | --- |
| 机身 | 9 个渐变剖面、4 条连续纵梁；形成针状机鼻、座舱隆起和收窄尾段 |
| 主翼 | 左右各 5 个翼展站位 × 4 个翼弦站位；同时绘制翼展线和翼弦线 |
| 翼厚 | 后缘增加下表面与连接支柱，避免主翼退化成平面三角形 |
| 发动机 | 4 具独立圆筒；每具 3 个六边形截面并由 6 条纵向导轨连接 |
| 座舱 | 独立青色六点笼式结构，与白色机身形成层级 |
| 动态效果 | 4 路尾焰和冲击菱形继续绑定对应发动机中心 |

静态主体约产生 `277` 条结构线段；Boost 状态最多增加 `32` 条冲击菱形线段。

## 3. 性能控制

旧投影函数会为每条边的每个端点重复计算 pitch / roll 三角函数。M10 引入帧级 `AircraftPoseProjector`：

1. 每帧只计算一次 pitch 的 sin/cos；
2. 每帧只计算一次 roll 的 sin/cos；
3. 每个线段端点只执行局部旋转、透视除法和屏幕偏移。

战机仍无堆分配、无额外帧缓冲、无图片解码和图片常驻 RAM。

## 9. 第三轮真机否决与第四轮相机重构

第三轮虽然在静态包围盒宽高比上接近参考图，但真机证明“包围盒相近”并不等于“透视正确”。短焦距投影使最近的机尾相对最远的机鼻放大约 `2.8×`；同时过大的俯视分量把发动机圆截面压缩到约 `1–2 px` 高。密集母线、环线和翼面线在相邻像素形成高亮带，最终表现为尖刺机鼻和四根发白的纵向柱。

第四轮调整：

- 用规范化相机基底替代经验斜率公式，固定约 `52°` 的追尾俯视角；

- 拉长真实机身纵轴和机翼弦向尺寸，靠模型本身而非投影畸变获得目标宽高比；
- 机翼横向站位重新沿直线后掠分布，避免翼缘呈弧形或伞形；
- 发动机下沉并扩大截面，恢复与机翼之间的负空间；
- 发动机前两道环只画相机可见的上半面，每具发动机仅保留三条可见母线；

## 10. 第四轮视频否决与第五轮美学自查

第四轮真机视频逐帧 Review 后否决。核心错误不是单个参数，而是设计方法：战机采用独立的 `52°` 展示型俯视相机，而峡谷采用接近水平的追尾相机。两套透视同时出现，使水平飞行的战机看起来持续带有不合理仰角。

### 10.1 美学自查

| 维度 | 第四轮问题 | 第五轮约束 |
| --- | --- | --- |
| 场景关系 | 战机像悬浮在地形上的俯视图 | 战机与地形共享追尾相机俯仰逻辑 |
| 第一轮廓 | 长针机鼻加规则三角翼，近似纸飞机 | 分段机鼻、肩部折点、裁切翼尖、双垂尾 |
| 结构可信度 | 发动机作为尾缘装饰环悬挂 | 进气肩、连接支架、舱体和尾喷口形成连续结构 |
| 线条层级 | 网格平均铺满，形成梳齿纹 | 外轮廓、承力结构、内部刻线使用三级亮度和密度 |
| 体积 | 中央机身缺乏座舱和背脊质量 | 独立座舱笼、渐变截面和垂尾建立三维体积 |
| 动态 | 投影后进行二维旋转 | roll / pitch 在三维模型坐标中旋转后再投影 |
