# Vector Canyon Fighter G3：曲面峡谷重构方案

## 1. 本轮目标

把当前“折板式通道”重构为连续、崎岖、可高速穿梭的线框山脉峡谷：

- 运动节奏参考用户提供的视频：镜头基本稳定，地形从远方生成并高速向近景展开；
- 几何形态参考 P1：圆润山肩、连续峰脊、自然谷地，横纵网格均随曲面弯曲；
- 不使用贯穿画面的长直墙、垂直挤出墙或矩形跑道；
- 保持第三人称构图，战机位于画面下部，占圆屏直径约 14%–16%；
- 先完成无交互的视觉基线，再恢复 IMU、按键和未来外设输入。

## 2. 参考拆解

### 2.1 视频中保留的部分

- 远景开口稳定存在，近景从左右两侧快速掠过；
- 深度线向消失点收束，横向截面随距离快速拉开；
- 速度变化主要体现在地形流速，不依赖大幅移动相机；
- 近景允许被圆屏大幅裁切，以建立山体尺度感。

### 2.2 视频中舍弃的部分

- 垂直直墙和箱形截面；
- 长距离不弯曲的墙顶线、墙脚线；
- 重复的等高矩形环；
- 只有谷底有网格、两侧山体呈黑色空面的处理。

### 2.3 P1 中采用的部分

- 整幅地形是一张连续高度场，谷底、山坡和峰顶属于同一张网格；
- 横向网格描述山体截面，纵深网格描述山脉走势；
- 山峰由多段平滑折线逼近，不依赖真正的曲线绘图 API；
- 两侧山体不完全对称，前中后景存在不同峰高与山肩宽度。

## 3. 地形数学模型

### 3.1 从正弦叠加改为骨架脊线场

参考 `Yosmos0427/3d-terrain-generator` 的“骨架脊线 + 距离衰减 + 微噪声”思想，独立实现适合 ESP32 的固定容量版本，不复制原仓库代码。

任意世界坐标 `(x, z)` 的高度定义为：

```text
H(x,z) = base(x,z)
       + Σ ridge_i(x,z)
       - valley(x,z)
```

单条骨架的贡献：

```text
contribution = amplitude × max(0, 1 - distance_to_polyline / radius)^sharpness
```

- `base`：两层确定性 value noise，只提供低幅微起伏；
- `valley`：沿飞行方向延伸的负贡献骨架，控制峡谷主通道；
- `ridge`：左右各 2–3 条正贡献骨架，形成主峰、山肩和次级峰；
- 多条骨架叠加处自然升高，避免单一坡面和孤立折板。

### 3.2 峡谷中心线

- 使用固定容量控制点描述中心线；
- 控制点由固定种子随机游走生成，但限制最大转角和宽度变化；
- 用 Catmull–Rom 插值或两轮 Chaikin 切角得到平滑中心线；
- 左右主脊沿中心线法线偏移，并分别加入独立的缓慢漂移；
- 峡谷宽度沿纵深连续变化，不允许相邻行突然缩放。

### 3.3 连续性约束

- 所有高度只依赖世界坐标、固定种子和骨架，不依赖当前数组索引；
- 新地形行进入远端时只计算一次并缓存；
- 近端行回收不会改变尚在画面中的任何顶点；
- 骨架控制点以环形缓冲区滚动，新增点继承上一段方向；
- 禁止逐帧随机数，避免山体抖动和接缝跳变。

## 4. 网格与投影

### 4.1 固定容量

初始目标：

| 项目 | 数量 |
| --- | ---: |
| 横向采样列 | 31 |
| 纵深采样行 | 22 |
| 投影顶点 | 682 |
| 横向网格边 | 660 |
| 纵深网格边 | 651 |
| 总网格边 | 1311 |

- 坐标缓存使用 `int16_t`，投影缓存约 2.7 KB；
- 高度、骨架和投影均使用 `std::array`，帧内禁止堆分配；
- 若真机帧率不足，优先降低远景行数或隔行绘制远景，不能先删除山体纵线。

### 4.2 曲线视觉的实现

屏幕最终仍由短线段绘制，但不再出现一根跨越整面山体的长直线：

- 每条横向等高轮廓由 30 段短线组成；
- 每条纵深山脊线由 21 段短线组成；
- 顶点来自连续高度场，线段会自然形成圆润折线；
- 山脚、山肩、峰顶不单独画直线轮廓，全部由同一网格产生。

### 4.3 投影与构图

- 相机保持第三人称、低俯视角，消失点位于屏幕中心略上；
- 近景山体必须越过左右圆屏边缘，远景保留约 18%–28% 的峡谷开口；
- 谷底不能成为规则矩形跑道，应随中心线横移并有轻微横坡；
- 不绘制黑色遮挡三角形；使用颜色衰减表达远近关系；
- 远景线不得低于真机可见亮度阈值。

## 5. 动态穿梭

### 5.1 地形运动

- 维护连续的 `worldDistance`；
- 每帧只更新每行相对相机的 `z` 并重新投影；
- 最近日形越过相机后回收到最远端，并采样新的世界坐标；
- 速度变化只改变 `worldDistance` 增量，不改变地形拓扑；
- 行回收必须发生在屏幕外，不能看到整行跳变。

### 5.2 速度视觉

- 慢速：近景横线位移清晰，远景稳定；
- 快速：近景行快速展开，远景仍能辨认峡谷走向；
- 加速不通过扩大整个网格模拟，避免“画面呼吸”；
- 可在后续阶段为最近 2–3 行增加短促余辉，但不是本轮验收条件。

## 6. 渲染顺序

```text
1. 清屏
2. 投影缓存中的全部地形顶点
3. 从远到近绘制横向曲面轮廓
4. 从远到近绘制全部纵深网格线
5. 绘制战机
6. 绘制极简 HUD
7. 提交 Canvas
```

规则：

- 地形阶段禁止任何覆盖网格的黑色填充；
- 横线与纵线使用相同的近、中、远亮度层级；
- 主山脊可追加一条低亮度偏移线模拟荧光，但不得让总帧率跌破门槛；
- HUD 不得遮挡远景开口和主要峰脊。

## 7. 软件接口

保持现有上层接口不变：

```text
InputProvider -> FlightInput -> FlightModel -> TerrainStream -> Renderer
```

本轮只替换 `TerrainStream` 内部生成器与 Renderer 的地形部分：

- `FlightModel` 不感知骨架算法；
- 碰撞继续查询峡谷中心、有效半宽和局部地面高度；
- 未来 Joystick2 与 Unit Dual Button 接入时不需要修改地形生成器；
- 可增加只读 `TerrainFrame`/`TerrainRow` 数据结构，禁止 Renderer 反向生成地形。

## 8. 分阶段实施与 Review

### R1：离线静态高度场

- [ ] 生成 31×22 固定网格；
- [ ] 有一条连续谷线和左右至少两条主脊；
- [ ] 三张不同纵深位置截图均呈连续山脉；
- [ ] 不出现箱形截面、直墙或左右镜像；
- [ ] P1 的圆润山肩和网格弯曲特征可辨认。

失败即停止：若静态图仍像隧道或折板，不进入动画阶段。

### R2：真机静态渲染

- [ ] 横向与纵向网格均可见；
- [ ] 两侧山体内部不存在大面积纯黑空面；
- [ ] 近景裁切、远景开口、山体比例符合构图；
- [ ] 远景最暗线在亮度 80 设置下仍可辨认；
- [ ] 战机占比保持 14%–16%。

### R3：低速连续运动

- [ ] 连续运行 30 秒无接缝、闪变、整行跳跃；
- [ ] 山脊前后连贯，不像独立山块轮流出现；
- [ ] 峡谷中心缓慢转向，战机前方始终存在可读通道；
- [ ] 帧率目标 ≥ 24 FPS，目标值 30 FPS；
- [ ] 无栈溢出、看门狗或动态内存增长。

### R4：快速穿梭与整机构图

- [ ] 快速模式具有参考视频的向前展开感；
- [ ] 高速时远景路线仍可判断；
- [ ] 战机与地形之间有明确尺度关系；
- [ ] HUD 不抢画面主体；
- [ ] 录制真机视频，与视频运动/P1 几何两个参考分别对照。

### R5：回接输入与碰撞

- [ ] IMU/按钮临时输入无需修改地形接口；
- [ ] Joystick2/Dual Button provider 可直接替换；
- [ ] 碰撞边界来自同一骨架峡谷数据，不依赖屏幕像素；
- [ ] 输入切换不改变种子与地形连续性。

## 9. 明确拒绝项

出现任一项不得提交视觉阶段：

- 两侧只有外轮廓，内部纵向网格不可见；
- 山体由少量大三角形或大四边形构成；
- 左右墙接近垂直且长距离保持直线；
- 谷底像平直跑道或规则梯形；
- 地形回收时出现跳变、裂缝或形态重置；
- 通过增加 HUD、粒子或发光掩盖地形结构问题；
- 为提高帧率优先删除纵向网格。

## 10. 本轮决策

当前多层正弦高度函数仅保留为可回退实验，不继续调参。下一实现阶段从 R1 开始，以固定容量骨架脊线场替换现有地形生成核心；R1 静态 Review 通过前不烧录动态版本，也不提交当前未验收视觉代码。
