# Vector Canyon Fighter · G3-R2 实机静态评审

## 结论

R2 于 2026-09-01 经 StopWatch 实机检查后暂时通过，允许进入 R3 低速动态连续性验证。

本结论是“阶段性接受”，不是最终视觉定稿。后续动态画面仍需继续校准山脉的连续起伏、透视节奏和圆屏构图。

## 本轮确认

- 37 × 26 曲面网格能够在实机完整绘制，纵深线和横向等高线均可见。
- 中央深槽保留，并扩大了可辨识宽度。
- 左右山体采用独立骨架、连续低频起伏与分层峰体，不使用逐帧随机噪声。
- 水平视场扩大，近中景能够同时容纳谷底、侧坡和山脊。
- 地形初始化由“每个网格点重复计算骨架距离”改为“每切片采样一次骨架并复用”，实机不再触发任务看门狗。
- 固件烧录及写入哈希校验通过。

## 实机发现与处理

初版实机画面呈规则漏斗感，原因包括：

1. 水平视场过窄，近景左右山峰落在圆屏外；
2. 垂直投影使近处峰顶被裁切；
3. 多层宽峰互相叠加，右侧容易形成平台；
4. 山体纵向低频变化不足，静态帧难以读出前后起伏。

本轮已通过扩大水平视场、收窄峰体作用半径、加强连续山体起伏和恢复完整横向等高线进行修正。

## 性能记录

- 修正前静态渲染：平均 54 ms，最大 57–59 ms。
- 骨架采样优化后：平均 53 ms，最大 68 ms。
- 初始化看门狗：由触发变为不触发。

删除约四分之一横向线段对总帧耗时几乎没有收益，说明当前主要瓶颈是 450 × 450 全画布传输，而非地形线段计算。因此恢复完整网格，避免以明显视觉损失换取无效优化。

- [x] 纵深线可见
- [x] 横向等高线可见
- [x] 中央深槽宽度可辨识
- [x] 山脊进入圆屏主要视野
- [x] 写入哈希校验通过
- [x] 用户阶段性接受当前效果
- [ ] 最终山脉视觉定稿（留待 R3/R4 动态评审）
- [ ] 达到 24 FPS（转为 R3 屏幕刷新策略风险项）

## R3 入口条件

R3 应移除静态冻结与临时统计字段，恢复低速地形流动，并检查：

- 连续切片回收时无跳变、断线或突然换形；
- 18–20 FPS 的实机节拍是否仍能形成可接受的穿梭感；
- 左右山峰在运动中是否比静态帧更容易辨识；
- 沟壑宽度在弯道中不发生视觉塌缩；
- IMU 与按键输入只作为临时输入层，不侵入地形和飞行模型接口。
