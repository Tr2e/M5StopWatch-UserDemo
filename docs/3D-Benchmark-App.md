# 3D Benchmark App

`3D Benchmark` 是一个独立的四段式全帧真机性能演示，不再借用 Gundam Museum 的交互循环。FPS 的 frame time 包含场景绘制和 framebuffer 提交调用；异步面板 DMA 的完整物理传输可与下一帧重叠，不能把该数值解读成“每帧都等待面板扫描完成”。测试过程中不显示 HUD，完整演示结束后只绘制一次静态结果页，后续按键等待不持续重绘或提交 framebuffer。

## 测试路线

1. **Cube Pair（3 秒）**：显示两个六面异色立方体，分别使用不同配色、大小、远近、旋转轴和透视姿态。
2. **Rigid Assembly（3 秒）**：只显示 4 个 64 共享顶点、48 四边形、8 刚性骨骼的 rigid chain；四条链分别使用独立调色板、大小、深度和空间姿态。
3. **Mixed Load（3 秒）**：组合 4 个第一阶段的异色立方体与 2 个第二阶段的刚性链，继续保持独立配色、尺度、深度和姿态。
4. **RX-78 Final（10 秒）**：释放程序场景工作区，再打开生产 Gundam Museum 渲染器，以所选内部采样、Z-buffer 和双核路径显示 RX-78 单体转台，按 10 秒周期旋转并额外渲染一帧精确 `2π` 终点，避免阶段判定使画面总是少一帧；空间线框和导航控件关闭，背景为 RGB565 `0x0000`。

前三段沿用《ESP32-S3 高性能 3D 渲染框架提炼与模型接入规范》已实现的 S0/S1 公共路径：模型只在场景工作区建立一次，之后以不可变 `ModelAsset` 常驻；两套立方体和四套刚性链的配色都在资产构建、校验和 seal 之前写入，seal 后不再修改。资产显式携带共享索引、三角/四边形拓扑、法线、anchor、bounds、groundY、确定性顺序、S0 纯色材质与内存报告；刚性链另带 8 个刚性分件。帧循环只更新轻量 `ModelInstance.world` 并引用预分配 `BoneTransform`，静态与刚性实例统一经 `renderSceneCachedIndexed` 进入 solid fast path，不进行逐帧建模、堆分配或任务栈大对象构造。刚性路径会为每个实例缓存 64 个已变换、已投影共享顶点，并将 8 组 `world × pose[rigidPart]` 仿射矩阵各合成一次。固定 pitch/roll 的正余弦只在工作区初始化时计算，每帧只计算各实例变化的 yaw，不为固定姿态重复调用三角函数。

100% 模式使用 424×424 内部颜色/深度平面并原尺寸合成；60% 模式使用 254×254 内部平面，通过占用像素驱动的稀疏最近邻放大到中央 424×424 输出。两种模式都使用稀疏深度清理，并在原生 RGB565 framebuffer guard 成立时直接写入 framebuffer。纯黑背景和配色变化不改变资产拓扑。

四段在一次测试中统一使用当前选择的 100% 或 60% 内部采样，RX-78 是最终阶段。阶段资源构建完成后才设置起始时间，随后 300 ms 为预热，避免把分配/建模时间吃掉预热窗口或把冷首帧纳入结果。结束页不再计算综合评分，主要显示每段的 `TOTAL TRI`、平均 `DRAW TRI` 和平均 FPS，并以小号次级信息补充 `TOTAL QUAD / DRAW QUAD`。TRI 仍是主负载口径，四边形在 TRI 中按两个 triangle 计数；QUAD 用于表示保留原生四边形拓扑、可利用 solid-quad 快速路径的数量，不代替像素成本指标。前三段的 TOTAL/DRAW 都由公共 Soft3D 前端在已解析 topology 上顺手累计，在单面背面、近裁剪可见性和完整屏外检查前后分别记录，不额外遍历资产、不由结果页硬编码或反推；被 Z-buffer 遮挡但已提交的图元仍计入 DRAW，与 RX-78 的 submitted 统计保持同一语义。

### 结果口径

屏幕 FPS 为 `1 / 平均帧时`，用于阶段成果展示，不是 P95 认证。前三段只有 3 秒且扣除 300 ms 预热，不报告 P95、最大帧、温升、内存水位或长时间稳定性。任何 30/24/20/15 FPS 产品等级仍必须使用独立的连续帧真机流程签署，不能从本结果页直接推导。

## 操作

- A：在运行中或结果页重新开始完整测试，保留当前渲染比例。
- B：在 100% 与 60% 内部渲染之间切换，并立即重新开始完整测试，避免结果混用两种分辨率。
- 同时长按 A + B：退出到 Launcher。

## 生命周期与内存

程序资产与 RX-78 不同时驻留。前三段结束后先释放两种立方体配色资产、四个刚性链资产和 424×424 光栅工作区，再创建 MuseumRenderer；结果页前再次释放 RX-78 工作区。内部 RAM 先申请每像素访问的 occupancy，再申请实例/pose/cache hot state，并一次性日志记录两者是否成功；失败时使用常驻回退存储。Wi-Fi 在测试打开时按已有 Museum 策略暂停，退出后恢复。Gundam Museum 自身保持正常交互，不自动运行旧的临时批处理基准。

## RX-78 高性能经验审计

阶段 1–3 已逐项复核 RX-78 中可通用的优化，不能只凭 fast-path 开关存在就视为接入：

| 项目 | 阶段 1–3 状态 |
| --- | --- |
| 不可变资产、共享索引、四边形拓扑、S0 纯色 | 已命中 |
| 静态/刚性唯一顶点 camera transform 缓存 | 已命中 |
| 唯一顶点投影缓存 | 已命中；静态立方体和刚性链均走相同 indexed scratch |
| 刚性 `world × pose[rigidPart]` 预合成 | 已命中；`Bone.parent` 不由 runtime 求值 |
| 背面、近裁剪、屏外提交前剔除 | 已命中，并输出真实 TOTAL/DRAW |
| compact solid、span、trusted depth、solid quad | 已命中；不再只是打开未被调用路径的开关 |
| 稀疏深度清理与 span clear | 已命中 |
| 100% 原生模式 deferred occupancy record | 已命中；60% 缩放模式保留光栅期记录 |
| 60% 占用像素驱动稀疏放大 | 已命中 |
| native RGB565 framebuffer、32-bit 黑屏清理、异步提交 | RGB565/rotation/full clip/stride/alignment guard 全部成立时命中，失败正确回退显示 API |
| occupancy、实例、pose、变换/投影 scratch 内部 RAM 优先 | occupancy 优先级高于 hot state；成功项可从 `3DBenchMemory` 日志核对，失败回退常驻工作区 |
| 固定姿态与结果页 | pitch/roll 三角函数移出帧循环；结果页只绘制/提交一次 |
| 生产 FPS 去除逐像素诊断计数 | 已命中；前三段使用非 measured raster |
| 生命周期、Wi-Fi、工作区互斥释放 | 已命中 |

双核行带、12 B indexed command stream 和 split color/depth 没有无条件复制：当前前三段使用 common 单核即时提交路径，提交图元显著低于 RX-78，F4 同机标定中 crate 与单 rigid chain 也选择 single。但 F4 数据不是当前多实例 Demo 的 A/B；只有采集本 Demo 的 prepare/raster/composite/present 分段真机数据，并证明 worker 同步、命令构建和内部 RAM 争用后端到端仍获益，才能接入。全屏黑色 framebuffer 清理仍是可见的固定成本；若要改成脏区/覆盖清理，必须正确跟踪双 framebuffer 各自的历史覆盖并做端到端 A/B，不在本轮凭静态推测替换。

另有两个已识别但未冒然接入的候选：公共即时前端会在遍历图元时缓存首次出现的投影顶点，不像 RX-78 两阶段前端那样先完成全部面分类，因此可能为随后被剔除的面做少量无效投影；增加预分类也会带来第二次遍历和命令存储，需真机 A/B。同时，两套 cube/四套 chain 为了独立调色板复制了几何资产；后续可评估“共享几何 + 实例材质表”，但它主要影响常驻内存/缓存，不应在没有数据时宣称会直接提升 FPS。

## 当前验证

- ESP-IDF 5.5.4 / ESP32-S3 目标构建、链接及分区检查通过。
- 当前四阶段、100%/60% 双模式、全程纯黑背景固件大小：`0x4e0e30`；最小应用分区剩余 `0xf1d0`（约 1%）。
- Soft3D 资产 ABI / GLB 编译器门禁与 Gundam Museum 渲染回归均通过；静态/刚性缓存路径与原始参考路径的主机像素哈希一致，并验证刚性实例只变换、投影 64 个唯一顶点且只合成 8 组矩阵。实例数组、pose 和 indexed scratch 常驻场景工作区并优先申请内部 RAM，程序资产构建不占用帧循环任务栈；前三段实例数依次为 2、4、6。
- 已烧录至 StopWatch `/dev/cu.usbmodem83301`，所有写入区域 Hash 校验通过并完成硬复位。
- 历史 crate / rigid-chain 单实例 192×192 数据不再作为本场景的目标帧率；本轮结果需重新实测。
