# Racer framebuffer 专项整治：评估与实施计划

日期：2026-09-11。原评估基线：`dac7744`。实施基线：`6375162`。状态：P1–P2 已实现并通过主机与目标编译门禁，等待真机交互验收和同设备 A/B 性能采样。

## 1. 结论与边界

先复用 Vector Run 已验证的显示端 framebuffer 直绘和单帧事务边界，移除 Racer 的重复全屏中转；经同设备 A/B 确认收益后，再处理 Racer 自身的光栅、画质预算和慢帧问题。不要把框架抽取、降画质和算法重写捆成一次改动。

保持玩家车型、涂装、HUD、音频、外设语义和当前交互分辨率策略。比赛半分辨率场景、车辆颜色/深度工作块、材质与小地图缓存有实际用途，不等同于多余 framebuffer，不在第一阶段删除。

本轮不将 Launcher/LVGL 改成直绘，也不释放 HAL 的公共 canvas。它仍被其他 App 使用；绕过其热路径不等于节省该画布的常驻内存。全局按需分配应另立生命周期任务。

## 2. 已核对的事实

- `main/hal/hal_display.cpp` 的 `enableFrameBuffer(true)` 已启用显示驱动 framebuffer；HAL 又创建 PSRAM 全屏 Sprite，`updateCanvas()` 调用其 `pushSprite()`。
- Vector Run 使用 `getDisplay()`，持有最外层 `startWrite/endWrite`，集中提交一帧。Racer 使用 `getCanvas()`，绘制后复制到显示端；选车/欣赏页已局部提交，不应退回每帧全屏。
- Racer 的 UI、赛道和车辆合成函数多处接受 `LGFX_Sprite&`；比赛放大路径直接使用 `canvas.getBuffer()`，不能机械替换 getter 或把设备强转成 Sprite。
- AMOLED 驱动拥有脏范围，送显前执行偶数边界扩展，再按行复制到 DMA 缓冲。直绘不是全链路零复制，也不能免去 QSPI 传输。
- Racer 已有 33ms 显示节拍、60Hz 仿真、最多 5 步追赶、异步输入、缓存和分段统计；公共性能组件仍是指南建议，仓库尚无 `common/performance/` 实现。
- 现有帧预算按连续帧计数，恢复要求完整绘制/呈现不超过 29ms。在既有约 31ms 全刷条件下不现实；但直绘迁移后必须重新测量，不能提前搬用 Vector Run 的绝对阈值。

历史真机数据只作为定位依据：欣赏缩小交互约 106ms 绘制 + 18.5ms 呈现；比赛第三轮实验约 23ms 几何准备、46ms 光栅，整帧约 156ms。它们来自不同固定序列，不能互相拼接，也不是最新 Grand Spiral 或真人操作的性能承诺。

## 3. 分阶段实施

### P0：建立可重复基线与提交计数

固定当前代码、编译参数、设备身份和输入脚本。增加测试专用的帧提交计数，分别记录绘制/合成、提交、总帧时间、呈现区域、实际后端与分辨率；有必要时进一步拆出驱动复制与总线等待。

覆盖选车、欣赏、三条赛道、玩家单车和最大参赛车数；基准至少覆盖八车型。固定序列用于新旧画面与耗时对照，真人触屏/摇杆、音频并行另作实操测试。

记录每帧原始时间后计算整体 P95/最大值，不平均多个分组 P95。完整呈现耗时是主比较口径：原 `present` 含 Sprite 复制，新后端可能把部分成本移入 draw，不能只比较单个阶段。

交付：基线日志、逐帧 CSV、画面校验及环境信息。设备不可用则停在主机验证，不填真机收益。

### P1：最小可复用显示契约

优先抽取一个小型帧事务 RAII 封装和绘制目标契约，而非一次实现指南全部五组件。绘制函数通过公共绘图接口或轻量适配器接受 Sprite/设备目标，保留主机测试后端。

验证直绘模式下嵌套绘图不提前提交、异常/提前返回关闭事务、无变化时不传屏。最终由最外层帧边界呈现；计数指物理帧刷新，不是 DMA 行数或绘图函数调用数。

第一步用现有驱动绘图/按行写图接口，不直接访问或假设私有 framebuffer 地址、行跨度和字节序。对不支持的设备/格式/分配状态显式回退旧路径，并记录原因。Vector Run 若接入抽取后的封装，需要同场景像素和性能回归；不改其业务渲染。

交付：公共显示小组件、主机契约测试、小范围目标验证。暂不改变 Racer 仿真与预算阈值。

### P2：先迁移选车与欣赏，再迁移比赛

选车/欣赏先作为试点：保留现有几何缓存、动态采样、高清恢复与静态 UI 复用，只将最终目标换成显示端 framebuffer。验证局部脏范围仍覆盖上一帧和本帧车身、阴影及状态变化；换车、切页、重入时完整刷新。返回 Launcher 前必须使旧 canvas 内容失效并由 Launcher 正确重绘，不能把旧 Sprite 再推回屏幕。

比赛第二批迁移：保留小场景绘制与放大，改为向显示目标按行写入；保留原生玩家、遮挡顺序、桥面关系、边缘修整和 HUD。原 `getBuffer()` 快路径与设备按行路径单独比较，防止省下最终复制却在放大阶段引入更大开销。

结果/暂停/倒计时/输入检查等页面一起核对，不只测试 Racing 主画面。每批均保留可独立选择的新旧后端用于 A/B；不新增第二块全屏 framebuffer。

交付：两个独立迁移提交及各自证据。任一批退化则先保留旧路径，不把后续算法收益拿来掩盖迁移退化。

### P3：只在迁移稳定后处理 Racer 自身不足

1. 按新的 draw/compose/present 比例选择热点。优先试验车辆内循环增量插值、保守的无效工作排除等，每次只引入一项。涉及覆盖/深度/UV 浮点变化时，必须定位像素差异；未获画质变更确认不得以“看起来差不多”放行。
2. 复用窗口统计与滞回原则，重新设定赛车降级/恢复阈值。保护玩家主体与 HUD，优先调整远景/对手/装饰；保持用户已选择的预览采样策略。
3. 用实际 `simulationClampCount` 和丢弃时间诊断仿真。5 步仅覆盖约 83ms，若长帧持续发生，另行评估逻辑/绘制解耦；不能先增大追赶上限或改变时间倍率。物理与比赛公平性修改单独验证。

此前 UV 倒数、64×64 玩家材质缓存、欣赏条带/排序方案缺乏足够稳定收益，不列为默认采纳项。异步 DMA、多核并行和全局 canvas 释放也不放入第一轮。

## 4. 验收与采纳门槛

- 功能：触屏、Joystick2、Dual Button、复位/返回/退出、失联恢复不变；Launcher → Racer → Launcher → Vector Run 连续至少 20 轮，无旧帧覆盖、资源占用或残音。
- 图像：相同输入/姿态/质量下，在屏幕等价 RGB565 格式比较最终画面；迁移目标为逐像素一致。CRC 必须校验最终目标，不只校验已经绕过的旧 canvas。覆盖八车、三赛道、桥下遮挡、局刷、高清恢复及各质量档。
- 显示：每个有变化的帧最多一次物理刷新；局部刷新不意外扩成全刷。裁剪、字节序、屏幕 offset、偶数边界及退出后的显示状态全部正确。
- 性能：同设备交错 A/B、预热后每关键场景至少 100 个样本并重复三轮；实操各连续 30 秒，再执行 10 分钟带音频/外设运行。固定序列和实操结果分开报告。
- 采纳：所有正确性门禁先通过；关键场景均值/P95不得出现可重复的明显退化。建议以整帧均值至少改善 5%，或 P95/复制成本有稳定可解释改善作为首轮收益目标；该数值是实验目标，不是预测。低于目标时公开数据，说明是否仅有维护价值，不宣称流畅度显著提升。
- 资源：报告内部 RAM/PSRAM、最大连续块、任务栈及实际回退；热路径不新增分配。公共 canvas 仍保留时，不声称省下约 426KiB 常驻内存。
- 交付：每个阶段独立可回退，记录源提交、BIN/ELF 校验、设备身份与实测状态；无临时基准入口残留正常固件。

## 5. 推荐执行边界

建议先批准 **P0–P2：单 framebuffer 直绘专项**。先取得保持现有画质的真实收益，再决定 P3 的优先项。第一轮不承诺 20/30 FPS，不修改模型细节或降低用户选定分辨率，不扩展到全系统显示改造。

参考：`StopWatch-高性能渲染与App优化规范.md`、`Lets-And-Go-Racer-VIEW-CAR-流畅度分析与优化方案.md`、`ESP32-S3-贴图与软件渲染优化实证方案.md`；实际迁移以当时可复现的驱动版本和新基线为准。

## 6. 2026-09-11 实施记录

已按可独立回退的批次完成：

1. `377b930`：HAL 显式报告显示 framebuffer 是否可用；增加单帧事务/裁剪 RAII 和主机提交计数测试。初始化失败或 framebuffer 分配失败时保留 Canvas 回退。
2. `7a9b2ef`：车库、赛道、车辆、HUD 等绘制函数改用公共 `LGFXBase` 目标；Sprite 兼容入口不变。半分辨率场景仍是 Sprite，只有 Sprite 目标才能使用原始缓冲区快拷贝；显示目标使用逐行 `pushImage`。
3. `a5f472a`：输入、车库、选车、欣赏、对手与赛道页改为显示 framebuffer 直绘。选车和欣赏的刷新矩形在绘制前即设置为 clip，提交后恢复，避免静态标题和页脚扩大脏区。
4. `b226184`：结果页先独立迁移并验证通用目标画面一致性。
5. `247b68e`：倒计时、赛中、暂停和冲线页迁移；`kDirectFramebuffer` 保留同一固件配置下切换旧 Canvas 后端的 A/B 能力。

本轮自检结果：

- 公共事务测试验证嵌套绘制期间不提前提交、外层结束时恰好一次提交、局部 clip 限制写入且提交后恢复。
- 主机生产渲染器覆盖八车型、三赛道、桥下遮挡、车库视角、半分辨率放大、原生玩家和结果页；Sprite 与通用目标最终 RGB565 像素一致。
- 完整主机套件通过，包括 192 组确定性、单组 180 秒上限的三赛道场景，以及 Vector Run/Launcher 回归。
- ESP-IDF 5.5.4、ESP32-S3、O3 目标固件编译通过；当前 BIN 大小 `0x4bb590`，最小应用分区余量 `0x34a70`（约 4%）。

尚未用主机结果代替真机结论：帧时间收益、触控/Joystick2/按键手感、连续 App 往返、音频并行和真实物理刷新范围必须在烧录后验收。HAL 公共 Canvas 仍常驻，不能宣称节省约 426 KiB；帧预算阈值也未在缺少新真机分布时提前调整。
