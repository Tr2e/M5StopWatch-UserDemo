# R5 控制器适配与玩家动力学评审

## 本轮交付

- 新增赛车领域输入契约，不向赛车模型暴露飞行游戏的 `pitch/throttle` 语义。
- 复用 Vector Run 已验证的 Joystick2 I2C 与 Dual Button GPIO 驱动，不重复初始化总线和引脚实现。
- Joystick X 支持带滞回和定时连发的菜单导航；Blue 确认/Boost，Red 取消/刹车、长按暂停，双键组合退出。
- 新增自动油门、曲率限速、Boost 能量、连续刹车、转向走线、护墙减速/回弹和短暂转向抑制。
- Joystick2 样本失效时立即输出零转向、零 Boost，并对赛车施加安全减速。

## 自审 A：正确性与架构

发现并修正：

1. 设备检测成功后若同一帧继续使用旧的 Ready 状态，可能刚请求校准就直接完成校准；把两个状态转移改成互斥分支，下一帧必须重新读取状态。
2. 原飞行按钮映射没有暴露 Red 的连续按住状态，赛车无法实现“按住刹车”；在共用动作位中增加 `ThrottleDown` held，不改变 Vector Run 对点击降油门的既有消费方式，并扩充其回归测试。
3. 映射层拒绝 NaN 和任一无效来源；失联帧不会复用上一帧转向或按钮。
4. 复用驱动的双键事件原本是短按组合；赛车退出契约要求长按。新增独立 800 ms、可回绕、单次锁存的组合检测，避免误退 App。

## 自审 B：性能与失败路径

1. 菜单导航使用常量状态，无队列、无分配，并验证 `millis()` 回绕。
2. 输入、状态和单车动力学分别设置 20/20/32 字节编译期上限。
3. 玩家动力学将单步时间限制为 50 ms，拒绝非有限时间，避免慢帧造成位置爆跳。
4. Dual Button 为被动开关，只能报告 GPIO 已配置，不能声称检测到实体线缆；最终设备验收必须人工确认两键。

## 验证结果

- 输入映射与菜单连发严格编译：通过。
- 输入 AddressSanitizer + UndefinedBehaviorSanitizer：通过。
- 玩家动力学严格编译及 sanitizer：通过。
- Vector Run 输入契约回归：通过。
- ESP-IDF 首轮构建：通过，镜像 `0x494320`，应用分区剩余 `0x5bce0`（7%）。
- 两轮修正后的最终构建：通过，镜像 `0x4943c0`，应用分区剩余 `0x5bc40`（7%）。

## 真机延后项

- Joystick2 中心稳定性、X 极性、真实满量程、RGB 提示和 I2C 拔插恢复。
- Dual Button GPIO 3/4 的物理颜色对应、去抖和长按手感。
- 护墙碰撞减速、转向灵敏度、Boost 消耗速度需要实机调参。
