# 科技 UI 设计规范

> 适用于小尺寸嵌入式屏幕、圆形显示器、仪表界面、结构示意与技术可视化。
> 本规范强调“可读的系统状态”，而不是用发光、扫描线和随机字符模拟科技感。

## 1. 设计目标

科技 UI 应让用户在 3 秒内识别当前对象、关键状态和可执行动作，并在继续观察时发现可信的结构与数据细节。

设计必须同时满足：

- **清晰**：主对象、主状态、主操作具有稳定且明确的视觉优先级。
- **可信**：结构、比例、连接、运动和着力关系符合对象本身的工作逻辑。
- **克制**：装饰不能抢占信息层级，也不能伪装成不存在的功能。
- **一致**：颜色、线宽、文字、状态和动画具有固定语义。
- **可降级**：关闭特效或降低细节后，轮廓、状态和交互仍然成立。

## 2. 先建立信息模型

绘制界面前，先用一页信息表定义以下内容：

| 类别 | 必须回答的问题 | 典型呈现 |
| --- | --- | --- |
| 身份 | 这是什么？当前位于哪个视图？ | 名称、编号、视角、模式 |
| 输入 | 用户或系统向它提供什么？ | 控件、传感器值、目标值 |
| 输出 | 它正在产生什么结果？ | 状态、趋势、反馈、告警 |
| 组成 | 哪些部件决定其功能与轮廓？ | 主结构、连接点、活动件 |
| 约束 | 哪些关系不能被画错？ | 轴线、支点、接触面、运动范围 |
| 证据 | 哪些信息来自真实资料，哪些只是概念？ | 来源、版本、`CONCEPT`、`NOT TO SCALE` |

无法验证的数据不得包装成精确事实。概念图、示意比例和模拟状态必须明确标注。

## 3. 信息层级

界面从强到弱分为五层；任何时刻只允许一个一级视觉焦点。

1. **主对象 / 核心状态**：决定首屏识别结果。
2. **主操作 / 当前阶段**：告诉用户能做什么或正在发生什么。
3. **关键参数**：支撑判断的少量数值和状态。
4. **结构标注**：解释部件、关系和局部变化。
5. **环境纹理**：网格、扫描线、颗粒、微型刻度等可移除装饰。

身份区应安静、稳定，不与主对象争夺亮度。留白是层级的一部分，不应用无意义文字或刻度填满。

## 4. 布局与安全区

### 4.1 通用布局

- 主对象占据视觉中心，但要为状态、控制和标注留出完整的阅读路径。
- 标签尽量靠近对应结构，连线不得横穿核心轮廓或主要数值。
- 同一页面的对齐基准不超过三条，避免局部模块各自建立坐标系。
- 状态栏保持位置稳定；页面切换时不应让身份信息跳动。
- 控件必须与装饰在形状、亮度或反馈上明显区分。

### 4.2 圆形屏幕

- 以可见圆为硬边界，再向内建立内容安全区；关键文字和点击区域不得贴圆弧。
- 水平排版宽度随纵向位置收缩。半径为 `r`、距圆心纵向距离为 `y` 时，可用弦长 `2√(r²-y²)` 估算可用宽度。
- 顶部和底部优先放短身份信息或单一状态，长文本放在中部较宽区域。
- 所有旋转、缩放和展开状态都必须单独检查圆周裁切，不能只验证静态首帧。

## 5. 视觉语法

### 5.1 颜色是状态，不是皮肤

建议从近黑背景、单一主结构色和少量语义色开始。具体色值由产品主题定义，但含义不得随页面改变。

| 令牌 | 含义 | 使用约束 |
| --- | --- | --- |
| `surface.base` | 背景与负空间 | 不使用纯黑吞噬暗部层次 |
| `structure.primary` | 主结构、主要轮廓 | 默认最高结构对比度 |
| `structure.secondary` | 次级结构、参考线 | 明显弱于主轮廓 |
| `state.active` | 已选、运行、锁定 | 同屏仅保留一个主要强调色 |
| `state.caution` | 需要关注但仍可继续 | 不用于普通装饰 |
| `state.fault` | 失败、危险、不可继续 | 必须同时配合文字或形状 |

界面必须通过灰度检查：失去颜色后，层级、选中态和告警仍应可辨。

### 5.2 线条层级

| 级别 | 用途 | 相对表现 |
| --- | --- | --- |
| L0 | 背景网格、扫描参考 | 最细、最低对比，可隐藏 |
| L1 | 内部结构、辅助尺寸 | 细、连续或规则虚线 |
| L2 | 主轮廓、模块边界 | 清晰稳定 |
| L3 | 当前选择、活动机构 | 更亮或更粗，不同时滥用两者 |
| L4 | 告警、瞬时反馈 | 最醒目，仅短时出现 |

发光必须从已有线条派生，不能靠光晕替代几何。线条交点、端点和断点都应具有结构含义。

### 5.3 字体与数值

- 标签使用紧凑无衬线字体；编号、计时和测量值优先使用等宽或表格数字。
- 全大写仅用于短标签、模式名和状态码，正文保留正常大小写与词间距。
- 数值必须包含单位；同组数值统一小数位、对齐方式和单位位置。
- 小字号不承担关键状态。最小字号应在目标设备真机上以正常观看距离验证。
- 文案短而确定：使用“已连接”“校准中”“故障”等状态，不使用含糊的氛围词。

## 6. 主对象与结构绘制

先完成剪影，再补充结构，最后添加材质和特效。合格的主对象在纯单色填充、无标注、无光效时仍能被识别。

- 建立主轴、基准面、受力点、连接点和活动范围，再绘制外观。
- 用至少三个具有辨识度的真实结构特征避免“通用图标化”。
- 展开件、舵面、铰链、支架和接触件必须围绕可信的枢轴运动。
- 接地结构应区分支腿、关节、缓冲或连接结构、脚垫与接触面。
- 脚垫的底面才是接触基准；透视、阴影和接触线必须共享同一地平面。
- 局部特写应通过放大比例、裁切、视角和标注密度体现，不应只是主视图的居中缩放。
- 结构不确定时降低细节并标注为示意，不凭想象制造高精度零件。

## 7. 标注系统

标注是界面的一部分，而不是事后添加的字幕。

- 一条标注只解释一个对象、状态或关系。
- 端点必须落在可识别的结构特征上，不能悬空或指向模糊区域。
- 技术走线可使用正交折线；编辑式说明可使用平缓曲线，但同屏保持一种主风格。
- 标签结构建议为：`编号 / 名称 / 状态或规格`，缺少的信息不补假数据。
- 重要标签靠近对象，次级说明推向外围；交叉连线通过重新排版解决。
- 概念、比例失真、模拟值和未校准状态必须可见地说明。

微型技术标记只可来自有限语义集合：`结构`、`连接`、`控制`、`状态`、`注意`。它们不能作为随机填充纹理。

## 8. 组件与状态

每个组件至少定义 `default`、`focus`、`active`、`disabled`、`fault` 五种状态，并明确输入反馈。

- **状态胶囊**：短文本 + 语义色或图形，宽度变化不能推动核心布局。
- **参数行**：名称、值、单位三列对齐；异常值必须说明原因或状态。
- **动作控件**：静止时可被识别，触发时有即时反馈，完成后回到可预测状态。
- **结构标记**：只随对应部件移动，不漂浮在屏幕坐标中。
- **告警模块**：包含问题、影响和可采取动作；不能只有闪烁红框。

组件命名使用 `领域.组件.变体.状态`，例如 `telemetry.value.compact.active`。视觉令牌与业务状态分离，避免在业务代码中散落色值和线宽。

## 9. 动效与交互

动画只用于解释状态变化、空间关系或操作结果。

- 启动：由整体轮廓到关键状态，避免随机字符雨或长时间不可操作的片头。
- 聚焦：相机、裁切和标注共同强调目标；周边信息降级但不突然消失。
- 展开 / 收拢：遵守同一枢轴、方向和行程，反向播放应自然可逆。
- 锁定 / 确认：使用一次明确的收束反馈，不持续抖动或脉冲。
- 空闲：保持低振幅、低频率；不能让用户误判设备仍在执行操作。
- 错误：先给出状态变化，再提供原因和恢复动作；颜色闪烁不作为唯一提示。

输入到可见反馈应尽可能即时。过渡时长按“状态是否被理解”决定，不按追求戏剧性决定。尊重减少动态效果设置。

## 10. 特效与材质

扫描线、CRT 畸变、辉光、噪点和色差均属于可选表现层。

- 关闭全部特效后，信息层级和几何关系必须完整。
- 同一像素区域不叠加多种高强度效果。
- 噪点不覆盖小字号、细线端点、单位或告警文本。
- 光源、阴影和高光应共享一致方向；接触阴影只出现在真实接触面。
- 材质差异优先使用明度、线密度和局部结构表达，不依赖照片纹理。

## 11. 性能与细节等级

定义高、中、低三个细节等级，并保证功能语义一致。

| 等级 | 保留内容 | 优先移除内容 |
| --- | --- | --- |
| High | 完整结构、关键标注、有限材质与特效 | — |
| Medium | 剪影、功能结构、关键状态 | 微型刻度、次级纹理、部分光效 |
| Low | 主轮廓、活动关系、主状态与控件 | 内部细节、环境纹理、装饰动画 |

- 为每帧的线段、文本、粒子和离屏缓冲设定固定预算。
- 避免逐帧分配内存；几何、文本宽度和静态路径尽量缓存。
- 降级顺序固定为：装饰特效 → 环境纹理 → 次级标注 → 内部细节。主状态、主操作和核心轮廓不得降级消失。
- 性能验收必须覆盖最复杂状态、过渡中间帧和低电量或受限模式。

## 12. 可访问性与设备适配

- 颜色不是唯一信息载体；配合文字、图形、线型或位置编码。
- 确保关键内容在灰度、低亮度和强环境光下仍可识别。
- 不使用持续高频闪烁；告警动画应有停止条件。
- 文本、触控区和细线以真机像素密度和观看距离验收，不只看桌面预览。
- 屏幕裁切、字体缺字、数值溢出和本地化长度必须纳入边界测试。

## 13. 交付物与验收流程

每个界面至少交付：

1. 信息模型与真实性说明。
2. 视觉令牌、组件状态和布局基准。
3. 正常、聚焦、操作中、完成、故障、低细节、关闭特效七类基准画面。
4. 关键动效的首帧、中间帧、末帧和反向路径。
5. 目标设备截图或录像，以及帧率、内存和输入延迟记录。

验收顺序固定为：

1. **结构审查**：比例、轴线、连接、活动与接触关系是否可信。
2. **信息审查**：3 秒内是否看懂对象、状态和动作。
3. **一致性审查**：颜色、线型、字体、术语和状态是否遵守令牌。
4. **视觉对比**：基准画面差异是否来自预期修改。
5. **真机审查**：裁切、亮度、可读性、性能和交互反馈是否达标。

## 14. 常见反模式

- 用大量随机数字、网格和扫描线填满留白。
- 所有元素使用同一亮度、线宽或发光强度。
- 把装饰边框画得比主对象和状态更醒目。
- 以“像某种设备”为由虚构规格、接口或警告。
- 结构展开后支点漂移，接触面与地平面不一致。
- 所谓特写只是整体等比放大，没有新的结构信息。
- 动画改变形状但不遵守枢轴、刚体或约束关系。
- 低性能模式直接删掉关键状态或控件。
- 只在模拟器截图上验收，不检查目标设备。

## 15. 发布前检查表

- [ ] 3 秒内能识别主对象、主状态和主操作。
- [ ] 单色剪影仍具辨识度，关闭特效后仍可使用。
- [ ] 所有颜色、线型、标注和动画都有明确语义。
- [ ] 比例、连接、枢轴、着力点和接触面经过结构审查。
- [ ] 特写提供了更高的信息密度，而非简单缩放。
- [ ] 数值含单位，概念和模拟信息被明确标注。
- [ ] 圆屏安全区、极端数值、长文本和所有组件状态均已验证。
- [ ] 高、中、低细节等级保留相同的核心功能。
- [ ] 基准画面、视觉差异和真机结果均已审查。
- [ ] 文档、设计令牌与实现使用同一版本号并同步更新。

---

本规范是跨主题的设计基线。具体项目可增加领域规则，但不得改变既有视觉语义；若确需改变，应记录原因、影响范围和迁移方式。
