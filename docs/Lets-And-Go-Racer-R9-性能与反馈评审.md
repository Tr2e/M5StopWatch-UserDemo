# R9 性能、反馈与故障处理评审

## 本轮交付

- 车库与比赛使用彼此独立的 `FrameBudgetController`，持续高于 39 ms 时逐级削减纸纹、远山、机械线、路面横线和护栏支撑。
- 细节恢复使用更长的健康帧窗口，避免高/低画质在临界负载下反复跳变。
- 分别统计车库与比赛的渲染帧数、最后/峰值耗时和细节切换次数，并在 App 关闭时写入日志。
- 倒计时、GO、Boost、撞墙、最后一圈和冲线加入短音效与振动；全部遵循系统按钮音效/震动开关。
- 新增长时间仿真门禁，覆盖四辆玩家车、0～3 名对手、64 个固定种子、间歇输入失联和非法时间输入。

## 自审 A：正确性与架构

发现并修正：

1. 首版反馈直接调用扬声器与振动器，会绕过系统偏好；现在打开 App 时读取 `ButtonConfig`，所有游戏反馈统一经过受控入口。
2. 持续贴住护墙时 `wallImpact` 会连续保持高值，原逻辑可能每 300 ms 重复反馈；现在只在碰撞状态上升沿触发，并保留重入冷却。
3. 性能控制器原本只改变细节等级，无法留下可审计数据；现在保留定长统计，不做逐帧动态分配。
4. 车库与比赛各自拥有状态，切换页面不会让车库纹理负载污染比赛画质判断。

## 自审 B：性能、失败路径与边界

发现并修正：

1. 首轮预算测试的总帧断言少计一帧；按每段输入重新核算后修正为 290 帧，并同时断言四次细节切换。
2. 慢帧除了渲染耗时，还可能造成模拟补步截断；比赛预算同时观察 `simulationClampCount`，严重慢帧也会触发降级。
3. 新增 64 组最长 180 秒的压力场景，每步检查速度、横向位置、圈数、名次和全部浮点状态；间歇失联时输入按安全刹车处理。
4. High/Medium/Low 只改变装饰和对手细节，不删 HUD、玩家车、赛道边缘或护栏，因此低细节仍保留驾驶必要信息。

## 验证结果

- 渲染预算严格编译测试：通过。
- 比赛回归严格编译测试：通过。
- 64 组长时间仿真：通过，全部在上限内完成三圈。
- 渲染预算与长时间仿真 ASan/UBSan：通过。
- ESP-IDF 首轮构建：通过，镜像 `0x497890`，应用分区剩余 `0x58770`（7%）。
- 两轮修正后的最终构建：通过，镜像 `0x497c60`，应用分区剩余 `0x583a0`（7%）。

## 真机延后项

- 466×466 AMOLED 上 High/Medium/Low 的真实 FPS、降级阈值和恢复窗口。
- 蜂鸣器音量、振动强度、连续事件的体感与系统静音设置联动。
- Joystick2 实体拔插、Dual Button 线路、长时间运行温升和米白背景功耗。
