# Vector Canyon Fighter：G4-H1 HUD 世界参考系评审

> 日期：2026-09-04
>
> 目标：消除第三人称追尾相机、战机姿态与 HUD 地平线混用坐标系的问题。
> 依据：NASA HUD 资料要求人工地平线覆盖真实世界地平线，俯仰梯保持相对地平线的空间关系。

## 原问题

旧实现以 `150 + flight.pitch × 1.25` 设置零度线 Y，并以 `-flight.roll` 旋转整套俯仰梯。与此同时，峡谷追尾相机仅跟随 8% 战机俯仰且不跟随滚转，导致 HUD 和地形不在同一观察坐标系：最大爬升时约有 22 px 纵向误差，左右滚转时则产生最多约 30° 的直接角度冲突。

旧圆形标记只读取未来峡谷中心的 X，Y 固定为 150，因此也不是严格的飞行速度矢量。

## 实现

- 新增 `CanyonHudReferenceFrame`，用当前 `CanyonCamera` 对世界水平前向及左右探测方向做消失点投影。
- 零度线由同一相机矩阵计算，不再直接读取战机 `roll/pitch`。
- ±5°、±10°梯级由世界仰角方向投影，保持与零度线一致；标签继续直立以适应小屏阅读。
- 当前追尾相机保持 world-up，故零度线恒为屏幕水平；未来如果相机加入滚转，投影斜率会自然反映真实背景旋转。
- 固定航向框、速度/AGL 带、机体基准和滚转刻度不移动；滚转仍由战机本体及滚转指针反馈。
- 圆形标记改为同时使用峡谷远端中心的投影 X/Y，并在代码中明确命名为 route cue。真正 velocity-vector 标记留待 FlightState 暴露实际横向/垂直速度后实现。
- 战机显示模式继续使用 world-up 稳定追尾相机；K1 隐藏战机后不再只关闭图层，而是进入机体随动 cockpit camera：使用完整 pitch、roll、turnYaw，并把固定机体基准移至相机主点。两种模式的地平线都由各自实际相机投影，因此不会出现 HUD 与峡谷分离。

## 数值门禁（468 × 466）

- [x] 第三人称中立世界地平线 `Y ≈ 140.74`；G4-H3 将第一人称中立地平线独立调整为屏幕中心 `Y = 233`，不改变第三人称构图。
- [x] 只改变相机高度时，地平线 Y 不变。
- [x] 首轮 8% 跟随实机反馈位移不明显；将相机与 HUD 共用的俯仰跟随提高至 18%，没有单独放大 HUD 破坏共形关系。

- [x] 战机 `-18°` 俯冲时，地平线向上移动超过 21 px。
