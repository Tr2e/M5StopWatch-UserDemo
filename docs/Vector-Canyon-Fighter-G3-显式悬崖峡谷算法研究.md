# Vector Canyon Fighter G3：显式悬崖峡谷算法研究

> 状态：算法研究 / 尚未进入实现
> 日期：2026-09-02
> 目标：复刻参考图的几何语言，而不是继续调校现有高度场

## 1. 研究结论

参考图的核心不是“崎岖山脊”，而是一条沿弯曲路线延伸的、具有明确横截面的峡谷：

- 谷底是平面；
- 山顶是平面台地；
- 主要视觉信息集中在谷底边缘到台地之间的陡峭侧壁；
- 左右侧壁沿行进方向形成突出、后退、收窄和错位，构成躲避玩法；
- 网格的两族线分别遵循“峡谷行进方向”和“当前位置的横截面方向”；
- 画面中的线不需要保持屏幕上的 90°，但它们在世界坐标中必须来自同一个正交局部坐标系。

因此，目标不能再用“全幅高度场 + 山脊噪声”逼近。推荐的基础模型是：

```text
二维中心线 C(s)
    + 沿中心线的局部切线 T(s) / 法线 N(s)
    + 左右独立的可通行半宽 W_left(s), W_right(s)
    + 固定语义的显式悬崖横截面 Profile(u, h)
    = 沿路线扫掠的峡谷网格
```

这是一张有明确拓扑的“扫掠曲面”，而不是一张由随机高度决定形状的地毯。

## 2. 参考图真正值得复刻的部分

### 2.1 地形由三个简单区域组成

```text
左侧平顶台地  \ 陡峭左壁 /  平坦谷底  \ 陡峭右壁 /  右侧平顶台地
───────────────\__________/───────────────
```

参考图的真实感并不来自高频细节，而来自区域之间清楚且连续的关系：

1. 谷底平面给出稳定的速度参照；
2. 悬崖立面给出压迫感、距离和障碍边界；
3. 平顶台地终止侧壁，使轮廓像被侵蚀或切割的地貌，而不是无限上升的山峰；
4. 悬崖沿路线的宽度变化形成岩壁突出，成为玩家真正需要读取的信息。

### 2.2 不应复刻的表面现象

- 不需要追逐连续波浪形山脊；
- 不需要让谷底产生噪声起伏；
- 不需要用随机山峰填满左右画面；
- 不需要强迫投影后的横线、纵线在屏幕上垂直；
- 不需要把水印、文字或素材本身作为画面组成部分。

复刻目标是其几何组织、空间阅读和网格节奏。

## 3. 当前实现为何无法靠调参达到目标

当前 `TerrainStream` 的基本思路仍是按深度采样一组高度列，并用：

```text
worldX = sliceCenter + columnX
```

让每一排横向列随峡谷中心平移。这有三个结构性问题：

1. 横截面只发生平移，没有随中心线方向旋转；
2. 同列顶点连接出的纵线并不是中心线的真实偏移曲线；
3. 山体信息仍然主要来自高度变化，而不是显式的侧壁拓扑。

当中心线转弯时，横排仍朝全局 X 轴，因而它并不垂直于当前位置的行进方向。继续调相机角度、噪声振幅或横线密度，只会改变错误结构的外观，不能消除网格“斜着贴上去”的感觉。

本研究结论取代《Vector-Canyon-Fighter-G3-曲面峡谷重构方案》中以下基线：

- 不再以连续高度场作为目标图的基础表示；
- 不再以骨架脊线和微噪声作为主要地形生成器；
- 不再把圆润山峰、峰顶变化作为视觉验收核心。

原方案中的固定容量、世界坐标连续性、流式回收、接口隔离和真机性能门槛继续保留。

## 4. 世界坐标与两族网格线

### 4.1 中心线参数

令 `s` 表示沿峡谷路线累计的世界距离，中心线位于水平面：

```text
C(s) = (Cx(s), 0, Cz(s))
```

中心线的单位切线：

```text
T(s) = normalize(dC/ds)
```

水平面内的单位法线：

```text
N(s) = (-Tz(s), 0, Tx(s))
```

所以在世界坐标中：

```text
dot(T(s), N(s)) = 0
```

任意横截面顶点由下式生成：

```text
P(s, u, h) = C(s) + N(s) * u + Up * h
Up = (0, 1, 0)
```

其中 `u` 是相对中心线的横向距离，`h` 是高度。

### 4.2 横线的正确方向

固定 `s = s_i`，依次连接该截面的各个 `(u, h)` 顶点，即得到参考图中横跨谷底并爬上左右侧壁的“横向肋线”。它在谷底沿 `N(s_i)`，到侧壁后沿剖面向上，最后进入平顶台地。

它不是固定朝屏幕水平方向，也不是固定朝世界 X 轴。

### 4.3 纵线的正确方向

固定同一个剖面语义索引 `j`，连接：

```text
V[i][j] -> V[i+1][j]
```

得到沿峡谷延伸的纵向导轨。例如：

- 谷底中心线；
- 谷底左/右分道线；
- 左右墙脚线；
- 左右悬崖中段线；
- 左右崖顶线；
- 左右台地外沿线。

由于每一排都使用自己的 `N(s_i)`，这些纵线自然成为中心线的偏移曲线，不会在转弯时和横排发生剪切。

### 4.4 为什么屏幕上看起来不会是 90°

透视投影一般不保持角度。即使世界空间中的 `T` 与 `N` 严格垂直，投影后两条线在二维屏幕上的夹角也会随深度、相机俯仰和道路转向变化。参考图本身的网格交点也不是处处 90°。

正确验收指标不是“屏幕量角器测得 90°”，而是：

- 所有纵线具有一致、连续的局部消失方向；
- 横向肋线不会相对地形左右滑动；
- 路线弯曲时，整排横截面会随中心线转向；
- 局部坐标不会突然翻转；
- 墙脚、崖顶与谷底网格在同一个截面处准确相接。

为让局部坐标稳定，平面路线只需使用上述二维切线/法线。若未来加入真正三维中心线或相机翻滚，应改用平行移动标架（parallel transport frame），不使用容易在低曲率处翻转的 Frenet 标架。

### 4.5 必须区分“标架正交”和“每个网格交点垂直”

本方案要求的是中心线切线 `T(s)` 与横截面法线 `N(s)` 正交。横截面在侧壁上的切向量为：

```text
dP/dq = N(s) * du/dq + Up * dh/dq
```

因为 `T` 同时垂直于 `N` 和 `Up`，所以整条横向肋线所在的剖面都垂直于中心线方向。

但当悬崖正在突出或退后时，固定剖面层的纵线还包含边界变化量：

```text
dP/ds = centerlineTerm + N(s) * dW/ds + Up * dH/ds
```

因此纵线在收窄区会自然向内斜，在放宽区会自然向外斜；它与横向肋线未必在世界空间中保持精确 90°。这不是错误，而是“侧壁真的正在横向变化”的几何证据。参考图的突出岩壁处也存在这种斜交。

所以应分别检查：

- **方向基准是否正确**：横排必须使用当前中心线的 `N(s)`，不能使用全局 X；
- **边界变形是否连续**：纵线的斜向变化必须来自连续的 `W(s)`，不能来自列错接或投影补丁；
- **透视是否统一**：所有点经过同一相机变换，不在屏幕空间单独掰直。

若强行让每一个变宽/变窄区域仍保持网格交点 90°，需要求解另一族正交轨迹，而且会使剖面采样与碰撞边界失去直观对应。目标参考并不需要这种处理。

## 5. 中心线生成

### 5.1 曲线选择

建议使用向心 Catmull–Rom 曲线（centripetal Catmull–Rom，`alpha = 0.5`）连接稀疏控制点。与均匀参数形式相比，它更适合控制点间距不完全一致的流式场景，并能避免单段内的尖点和自交。

第一版也可以使用受限三次 Hermite 曲线；关键不是曲线名称，而是必须同时满足：

- 一阶切线连续；
- 转角有上限；
- 不产生回头弯；
- 可以按世界距离采样。

### 5.2 必须按弧长重采样

不能直接用样条参数 `t` 等间隔生成网格排。弯道与控制点间距会导致排线忽密忽疏。

推荐流程：

1. 对当前曲线段做 4–8 倍密度的临时采样；
2. 累计相邻点距离，得到近似弧长表；
3. 按固定世界间距 `deltaS` 反查插值位置；
4. 用相邻弧长点求切线并归一化；
5. 生成局部法线与横截面。

### 5.3 防止内侧偏移曲线折叠

当路线弯得太急、峡谷又太宽时，内侧的墙脚线和崖顶线会互相穿过。必须约束：

```text
curvature(s) * maxOuterOffset(s) < 1
```

实现上无需实时计算精确微分曲率，可以使用离散门槛：

- 限制相邻截面切线夹角；
- 限制连续控制点的转角；
- 峡谷变宽时自动降低允许曲率；
- 生成后检测相邻四边形朝向，不允许翻面。

## 6. 显式悬崖横截面

### 6.1 固定语义层，而非随机高度列

每一侧至少包含以下剖面节点：

```text
谷底边缘 -> 墙脚 -> 下部陡面 -> 上部陡面 -> 崖肩 -> 平顶台地外沿
```

归一化示例（右侧，左侧镜像）：

| 节点 | 横向位置 | 高度 | 作用 |
| --- | ---: | ---: | --- |
| floor-edge | `W` | `0` | 可通行边界 / 碰撞边界 |
| toe | `W + 0.08H` | `0.10H` | 很短的墙脚过渡 |
| face-low | `W + 0.13H` | `0.28H` | 下部陡面 |
| face-high | `W + 0.24H` | `0.88H` | 主悬崖面 |
| cap | `W + 0.36H` | `H` | 崖肩收口 |
| plateau | `W + P` | `H` | 平顶台地 |

这些数值是首轮静态原型的起点，不是最终美术参数。主陡面的水平退距可以由目标坡角直接计算：

```text
retreat = verticalRise / tan(cliffAngle)
```

- `78°`：水平退距约为垂直高度的 `0.21`；
- `82°`：约为 `0.14`；
- `85°`：约为 `0.09`。

参考图的主体应从 `78°–85°` 区间试验，保留极短墙脚与崖肩，避免整面墙成为绝对垂直的矩形板。

### 6.2 平顶和谷底必须真的平

复刻基线中：

- 谷底所有节点 `h = 0`；
- 同一段台地所有节点 `h = H`；
- `H` 只允许非常缓慢或稀疏的台阶式变化；
- 不向平面叠加微噪声；
- 不用峰顶起伏制造视觉丰富度。

真实感来自边界形状、陡面分层、透视密度和左右不对称，而不是表面颠簸。

### 6.3 侧壁不能只有轮廓

每侧建议使用 5–6 个高度/剖面层。每层沿 `s` 连成纵线，截面肋线把它们连接起来。这样即使不填充面，观众仍能读出悬崖的坡度和体积。

侧壁四边形可以添加一条确定性对角线，以接近参考图的低多边形结构：

```text
diagonalDirection = (sliceIndex + profileIndex) & 1
```

但对角线只用于悬崖主面，谷底和台地保持正交网格；否则小屏幕会变成无法辨认的线团。

## 7. 突出悬崖：地形变化即玩法

### 7.1 左右边界独立生成

令 `W_left(s)` 和 `W_right(s)` 分别表示中心线到左右谷底墙脚的距离。它们不能只是一个对称宽度值。

单个悬崖突出事件可表示为：

```text
intrusion(s) = amplitude * bump((s - center) / halfLength)
W_side(s) = baseWidth + slowDrift(s) - sum(intrusion(s))
```

`bump(q)` 使用有限支撑的平滑函数，在 `|q| >= 1` 时严格为零，例如：

```text
x = clamp(1 - abs(q), 0, 1)
bump(q) = x*x*x * (10 + x*(-15 + 6*x))
```

有限支撑保证一个障碍只影响明确的世界距离区间，便于布局、碰撞和复现。

### 7.2 推荐的障碍语法

| 事件 | 左右边界变化 | 视觉/玩法作用 |
| --- | --- | --- |
| shoulder | 单侧宽而缓的突出 | 基础躲避和空间阅读 |
| spur | 单侧较短、较深的突出 | 明确的急转压力 |
| S-gate | 左突出后接右突出 | 连续横移 |
| squeeze | 两侧同时中度收窄 | 居中与速度管理 |
| recovery | 宽度稳定、近乎直线 | 视觉休息与重建预判 |

第一版只需要 `shoulder + S-gate + recovery`，先验证参考图式连续壁面，不应立即堆叠随机障碍。

### 7.3 所有剖面层必须一起成为悬崖

突出事件首先改变墙脚边界 `W_side(s)`，然后整个侧壁剖面随之移动。墙脚、陡面、崖肩与台地必须仍然相接，不能只把谷底边缘拉进来而让崖顶留在原处。

初版可以让整套剖面刚性平移。后续为了产生岩柱感，可以让突出量随高度轻微变化：

```text
offset(s, profileLevel) = W_side(s) + retreat(profileLevel)
                        + intrusion(s) * shapeWeight(profileLevel)
```

但 `shapeWeight` 必须连续，且崖顶突出不能与墙脚完全脱节；首轮复刻不做悬挑和洞穴。

### 7.4 可玩性硬约束

每次生成事件后必须检查：

- 任意 `s` 的有效通道宽度不小于战机碰撞宽度加双侧安全余量；
- 相邻截面的边界横移不超过上限；
- 左右事件不会无意中重叠成死路；
- 玩家以当前最大横移能力可以从上一个安全区到达开口；
- 视觉边界与碰撞边界使用同一个 `W_left/right(s)`，不做屏幕像素碰撞。

这样地形生成器本身就能输出可玩的路线，而不是画完后再猜哪里可以飞。

## 8. 推荐网格拓扑

每个截面使用固定、带语义的顶点索引。第一版预算建议：

| 区域 | 顶点/导轨数量 |
| --- | ---: |
| 左平顶台地 | 2 |
| 左悬崖剖面 | 5 |
| 平坦谷底 | 9–13 |
| 右悬崖剖面 | 5 |
| 右平顶台地 | 2 |
| 每排总计 | 23–27 |
| 深度截面 | 28–36 |

该预算约为 `644–972` 个投影顶点，与现有约千点级预算相当，但每个点都承担明确的结构信息。

### 8.1 绘制规则

1. 固定 `s` 连接整条横截面，形成横向肋线；
2. 固定剖面索引连接相邻截面，形成纵向导轨；
3. 只在悬崖主面添加稀疏三角对角线；
4. 墙脚线和崖顶线允许略高亮，其他线按深度衰减；
5. 不使用黑色填充遮挡缺失网格；
6. 近裁剪面必须做线段裁剪，不能让越过相机的点拉出长线。

### 8.2 LOD 顺序

若真机性能不足，按以下顺序减负：

1. 远景取消悬崖对角线；
2. 远景隔一条绘制谷底内部导轨；
3. 中远景合并部分侧壁中间层；
4. 最后才减少深度截面数量。

不能优先删除所有侧壁纵线，因为它们正是用户目前最需要的悬崖体积信息。

## 9. 相机与投影

### 9.1 先把世界点变换到相机坐标

不能继续假设世界 Z 永远等于镜头前方。对于世界点 `P`：

```text
relative = P - cameraPosition
cameraX = dot(relative, cameraRight)
cameraY = dot(relative, cameraUp)
cameraZ = dot(relative, cameraForward)
```

然后才做透视投影：

```text
screenX = cx + focal * cameraX / cameraZ
screenY = cy - focal * cameraY / cameraZ
```

镜头可以沿中心线切线缓慢转向，也可以保留少量观察滞后；无论哪种选择，地形顶点必须先经过统一的相机变换。

### 9.2 目标构图起点

首轮静态复刻建议：

- 视平线位于有效圆屏高度的约 `30%–38%`；
- 相机略高于谷底，低于墙高的三分之一；
- 向下俯仰约 `6°–10°`；
- 垂直视场约 `52°–62°`，避免极端广角把悬崖拉成扇形；
- 最近的谷底横线应明显展开，远端仍保留可读开口；
- 左右近景悬崖允许被圆屏裁切，建立尺度感；
- 战机保持第三人称、画面下部小比例，不参与地形几何校准。

首轮算法截图必须关闭 HUD、发光拖影和复杂战机，只检查网格；视觉特效不能帮助地形通过验收。

## 10. 建议的数据接口

```cpp
struct CanyonSlice {
    float worldS;
    Vec2 center;
    Vec2 tangent;
    Vec2 normal;
    float leftFloorHalfWidth;
    float rightFloorHalfWidth;
    float leftWallHeight;
    float rightWallHeight;
    std::array<Vec3, kProfileCount> vertices;
};

struct CanyonObstacleEvent {
    Side side;
    float centerS;
    float halfLength;
    float amplitude;
    ObstacleShape shape;
};
```

对外继续保留现有链路：

```text
InputProvider -> FlightInput -> FlightModel -> TerrainStream -> Renderer
```

但 `TerrainStream` 应向渲染器提供已经位于世界坐标的截面顶点。Renderer 只负责相机变换、裁剪、投影和连线，不再反向制造地形。

碰撞模块查询同一份 `leftFloorHalfWidth/rightFloorHalfWidth` 和事件数据。未来从 IMU/机身按钮切换到 Joystick2/Dual Button 时，地形与碰撞接口均不改变。

## 11. 分阶段复刻计划与 Review 门槛

### A0：算法冻结

- [ ] 确认采用显式剖面扫掠，不再调现有高度场；
- [ ] 确认平谷底、平台地、陡侧壁是视觉基线；
- [ ] 确认横截面使用局部法线，而非全局 X；
- [ ] 确认首轮只做静态离线预览，不烧录。

通过后才允许修改生成器。

### A1：直线静态峡谷

- [ ] 一条完全笔直的中心线；
- [ ] 左右各 5 个以上悬崖剖面层；
- [ ] 谷底与台地严格平坦；
- [ ] 一眼可区分谷底、陡面、台地；
- [ ] 无噪声、无障碍、无 HUD、无战机；
- [ ] 网格密度与参考图同量级，而非少量大折板。

失败即停：若直线版本仍读不出陡峭悬崖，不进入弯道。

### A2：弯曲中心线与正交标架

- [ ] 使用弧长等距截面；
- [ ] 每排在世界坐标中满足 `dot(T,N)` 接近零；
- [ ] 调试视图可显示中心线、切线和法线；
- [ ] 横截面随路线旋转，无左右滑动；
- [ ] 墙脚线、崖顶线连续，无翻面和交叉；
- [ ] 不用屏幕空间修正假造 90°。

### A3：单侧突出悬崖

- [ ] 仅左侧生成一个宽缓 shoulder；
- [ ] 仅右侧生成一个宽缓 shoulder；
- [ ] 墙脚到崖顶整体连续变形；
- [ ] 突出前后严格回到基准宽度；
- [ ] 无山脊噪声仍具有明确地貌和躲避方向；
- [ ] 可视边界与碰撞查询结果一致。

### A4：障碍语法与流式连续性

- [ ] 加入 `S-gate` 与 `recovery`；
- [ ] 固定种子可完全复现；
- [ ] 连续推进 60 秒无接缝、跳排、形态重算；
- [ ] 所有通道通过最小宽度和可达性检查；
- [ ] 近景、中景、远景网格 LOD 无突变；
- [ ] 离线截图通过后再烧录真机。

### A5：真机视觉与性能

- [ ] 真机侧壁纵线可辨认，不出现大片黑面；
- [ ] 平谷底提供稳定速度感；
- [ ] 左右突出能提前被读取并指导躲避；
- [ ] 圆屏裁切后仍保留远端通道；
- [ ] 帧率不低于现有阶段门槛；
- [ ] 通过实机录像 Review 后，才恢复完整 HUD 和战机细节。

每个阶段遵循：输出证据 -> 对照本清单 Review -> 修正 -> 确认无误 -> 单独 commit -> 下一阶段。

## 12. 自动化编码的硬性否决条件

出现任一项即判定路线偏移，不允许用调色、发光或 HUD 掩盖：

- 继续以山脊高度或噪声参数作为主要优化对象；
- 横截面仍沿全局 X 轴排列；
- 直接连接错误列索引，导致纵线不遵循同一剖面语义；
- 为了“看起来垂直”而在屏幕空间扭曲网格；
- 谷底或台地出现逐点随机高度；
- 只有墙体外轮廓，内部缺少沿路线延伸的剖面层；
- 侧壁只由一两个巨大三角形表示；
- 左右边界共用单一对称宽度，无法形成独立障碍；
- 视觉障碍与碰撞边界来自两套数据；
- 曲线按参数等距而非世界弧长采样；
- 偏移曲线翻面、自交或穿过中心线；
- 在静态拓扑未通过前提前恢复完整游戏功能。

## 13. 推荐的最小验证输出

每一版离线预览同时输出三张图：

1. **透视主视图**：接近参考图相机，判断整体空间语言；
2. **俯视调试图**：显示中心线、左右墙脚、切线/法线，判断横纵线方向；
3. **横截面图**：显示谷底、左右陡面和平顶，标出坡角与有效宽度。

主视图好看但俯视图不正交，或主视图好看但横截面不满足可玩宽度，都不得通过 Review。

- Andrew J. Hanson、Hui Ma：*Parallel Transport Approach to Curve Framing*。用于理解沿曲线构建稳定局部标架的方法：<https://scholarworks.iu.edu/dspace/items/39fbe931-c2c8-43a1-9c9d-a207b92d551e>
- Stanford CS248：*Perspective Projection*。用于相机坐标和透视投影关系：<https://graphics.stanford.edu/courses/cs248-01/persp/persp2.html>
- Bauhaus-Universität Weimar：*Viewing and Projections*。透视投影不保持长度与角度，因此不能以屏幕 90° 作为世界正交性的判据：<https://www.uni-weimar.de/fileadmin/user/fak/medien/professuren/Computer_Graphics/course_material/Graphics_and_Animation_2015/3-viewingMG15.pdf>

## 15. 最终判断

目标图可以在 StopWatch 的线框预算内接近复刻，而且新方案未必比现有高度场更重：它减少了无意义的山体高度采样，把同等数量的顶点集中到谷底、墙脚、陡面和崖顶这些真正可读的结构上。

难点不在“画更多线”，而在三项基础工作必须一次做对：

1. 中心线必须按弧长采样并建立稳定局部法线；
2. 地形必须使用显式、带语义的横截面拓扑；
3. 左右障碍必须由受约束的边界事件生成，并同时服务渲染与碰撞。

若这三项通过静态 Review，后续流式运动、战机、HUD 和输入都可以在不改变地形核心的前提下恢复。
