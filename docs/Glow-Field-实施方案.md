# Glow Field 实施方案（StopWatch）

## 1. 目的与范围

Glow Field 是 M5Stack StopWatch 圆形 AMOLED 上的全屏触摸光场：黑色背景上铺设低亮度蜂窝点阵，手指触摸和滑动向附近点注入能量，形成彩色光晕与会自然消散的轨迹。

它是面向 StopWatch 圆形屏幕、触觉反馈和低功耗特性设计的独立互动体验。本项目只定义自身的视觉语言、交互节奏和实现策略，不以任何外部产品作为实现或命名依据。

首个可玩版本只交付：

- 单指触摸、路径插值与首帧视觉反馈；
- 固定蜂窝点阵、距离场能量注入与时间衰减；
- 预计算 Glow 图样或等效的轻量合成；
- 首次触摸的短振动与触觉冷却；
- 黑屏待机与回到应用启动器的按键退出。

首版不包含 Wi-Fi、设置页面、多主题、多点触摸、音频或 IMU 重力效果。IMU 倾斜和摇动清屏将在触摸体验、帧率及功耗通过验证后单独加入。

## 2. 基线与应用集成

本分支从 `feat/ruview-sentinel` 创建，以 RuView 的应用生命周期和硬件调用方式为集成基线，但不复用其 LVGL 视图结构。

RuView 证明了下列现有能力可用：

- `mooncake::AppAbility` 生命周期和 `KeyManager` 的退出行为；
- `GetHAL().getTouchPoint()` 的 CST820 单指坐标；
- `GetHAL().vibrate(duration, strength)` 的非阻塞振动；
- `GetHAL().updateImuData()` 及 BMI270 数据接口；
- 466px 圆形 UI 的布局约束。

Glow Field 的逐帧绘制不适合用大量 LVGL 对象表示。应用打开时暂停 LVGL 刷新，直接使用 `M5GFX` 的 AMOLED 面板帧缓冲绘制；关闭时清屏、恢复自动提交和 LVGL。这样既保留现有应用生命周期，也能按脏区域提交画面。

建议文件布局：

```text
main/apps/app_glow_field/
  app_glow_field.h/.cpp       应用生命周期、输入、待机状态机
  glow_field_engine.h/.cpp    点阵状态、注入、衰减和后续 IMU 模拟
  glow_field_renderer.h/.cpp  面板帧缓冲、调色板、Glow 合成、局部刷新、帧率统计
```

后续接入还需在 `main/apps/apps.h` 和 `main/main.cpp` 注册 `AppGlowField`，并复用现有 `icon_typhoon` 暂作开发图标；最终图标独立设计，不阻塞 Phase 0。

## 3. 渲染与内存策略

屏幕逻辑尺寸必须从 `getDisplay().width()` / `height()` 读取，而不是硬编码 466。现有 CO5300 配置为 468×466（带偏移），因此所有点阵、圆形裁切和触摸坐标必须依赖运行时尺寸。

目标是先稳定 30 FPS。当前触摸采样限制为 100Hz，模拟采用 16ms 固定步长（约 62.5Hz），显示与输入、模拟解耦；若真机压力较大，显示允许降至稳定 24FPS，但触摸路径插值不能降级。

当前 HAL 已有：

- 面板帧缓冲；
- 放在 PSRAM 的全屏 `LGFX_Sprite` Canvas；
- AMOLED 面板自身的 PSRAM 帧缓冲和局部 `display(x, y, w, h)` 提交能力；
- `GetHAL().updateCanvas()` 的通用全屏提交路径。

全屏 RGB565 缓冲约 424KiB，当前帧缓冲与 Canvas 共存仍远低于 8MB PSRAM。真机首轮证明 Canvas 全屏拷贝会同时承担几何合成、Canvas 到面板帧缓冲复制及整屏提交，Interactive 只能达到约 15.5FPS。因此正式实现改为直接绘制面板帧缓冲，并关闭 Glow Field 生命周期内的自动整屏提交：

- 静态基准场景只合成一次，后续复用帧缓冲内容，持续测量整屏传输上限；
- Interactive 按 19px 高度划分脏带，仅在能量量化档或模式提示发生变化时清除、重绘并提交受影响的连续脏带；
- 关闭应用时清屏并恢复面板自动提交，避免影响 Launcher 和其他应用。

该路径没有新增全屏双缓冲，也没有改变现有颜色常量。

### Glow 合成原则

不能把“预乘到黑色背景”的不透明 RGB565 Sprite 直接逐张覆盖到 Canvas：后绘制 Sprite 的黑色区域会擦掉已有光晕，多个触点相遇时视觉会出错。

Phase 0 依次验证：

1. M5GFX 透明 Sprite 的实际帧率和叠加效果；
2. 以透明色跳过黑色像素的预计算 RGB565 Sprite；
3. 若仍不足，针对 Glow 包围盒在 Canvas 像素上执行饱和加色或逐通道最大值合成。

优先选择能稳定达到目标帧率、且能保留重叠光晕的最简单方案。颜色和能量均量化为 8～16 档；调色板和径向衰减曲线在启动时生成，禁止逐像素 HSV 转换和实时高斯模糊。

## 4. 数据与交互模型

```cpp
struct Dot {
    int16_t x;
    int16_t y;
    uint8_t energy;       // 0..255
    uint8_t hue_index;    // 主题内的离散颜色档
    bool visible;         // 圆形区域内
};
```

- 蜂窝网格采用 22px 横向、19px 纵向间距，奇偶行错开 11px；468×466 下生成约 392 个可见点。
- 触摸半径当前为 62px；距离影响采用平方距离与二次曲线，避免在逐点注入时使用 `sqrtf`。
- 采样点间距不超过点阵间距的一半；每次拖动在前后坐标间线性插值。
- 能量以固定步长和小数余量累计进行线性衰减，速率为每秒 180 个能量单位；满能量约 1.4 秒归零，且不受主循环调用频率影响。
- 首次按下立刻注入能量并在下一次显示时绘制；只在按下沿触发一次 25～40ms 振动，并设置 75ms 冷却。

速度映射、颜色漂移和“松手后短暂增强”均作为 Phase 2 的调参项，不能阻塞固定半径的核心体验。

## 5. 运行循环与电源状态

```text
onOpen:  停止 LVGL/自动整屏提交，清空面板帧缓冲，建立点阵
running: 100Hz 读取触摸 -> 约 62.5Hz 模拟 -> 到 30FPS 帧时间则渲染并提交脏带
onClose: 清屏，恢复自动提交和 LVGL
```

待机状态在核心绘制稳定后加入：

```text
ACTIVE  -- 10 秒无触摸 --> AMBIENT（降低亮度、极弱点阵）
AMBIENT -- 30 秒无触摸 --> SLEEP（熄屏）
SLEEP   -- 触摸/按键/IMU --> ACTIVE
```

亮度恢复与触摸唤醒需要按 CST820 的真实睡眠/中断能力进行真机验证；首版先实现应用内的亮度降低和非深睡黑屏，不将深睡作为验收前置条件。

## 6. 分阶段计划与验收

### Phase 0：显示基准（第一个代码交付）

实现最小 Glow Field 应用和串口统计，分别运行 10 秒后报告稳定 FPS、平均帧时和最大帧时：

1. 纯黑/纯色全屏提交；
2. 约 400 个普通蜂窝点；
3. 约 400 个不同强度的 Glow 点；
4. 连续触摸时的完整路径与 Glow 叠加。

当前实现通过长按 A 键循环切换以下基准场景：

```text
INTERACTIVE -> SOLID -> IDLE DOTS -> ENERGIZED DOTS -> INTERACTIVE
```

每次切换会清空统计窗口，串口先输出当前 `scene`，保持场景 10 秒后输出该场景的 FPS、平均帧时和最大帧时。短按 A 仍用于清空光场，短按 B 切换 Ripple / Paint，A+B 长按退出应用。

通过条件：第 3、4 项达到稳定 30FPS，且没有撕裂、触摸明显断线或 PSRAM 分配失败。当前已通过串口性能和运行稳定性检查；撕裂与主观触摸连续性仍需人工观察确认。

### Phase 0 真机结果（2026-08-26）

测试设备为 ESP32-S3 StopWatch，逻辑显示尺寸 468×466，8MB PSRAM，蜂窝点数 392。临时测试固件每 12 秒自动切换场景，并在 Interactive 场景以 100Hz 合成连续轨迹；自动测试入口未保留在正式代码中。

| 场景 | 稳定 FPS | 平均帧时 | 最大帧时 | 结论 |
| --- | ---: | ---: | ---: | --- |
| Solid | 29.8 | 12.23ms | 25.15ms | 达标 |
| IdleDots | 30.2 | 12.29ms | 35.21ms | 达标 |
| EnergizedDots | 30.1 | 12.37ms | 60.24ms | 达标；最大值包含首次静态帧合成 |
| Interactive | 29.5–29.7 | 23.69–24.05ms | 31.95–37.02ms | 达标；连续三个统计窗口稳定 |

优化前的同设备首轮数据为 20.7 / 16.7 / 11.0 / 15.5 FPS。直接面板帧缓冲、静态帧复用和 19px 脏带提交解决了主要带宽与重复合成开销；测试期间未出现崩溃、看门狗复位或 PSRAM 分配错误。

### Phase 1：核心触摸体验

加入路径插值、距离场、时间衰减、首触振动和调色板。通过条件是快速划线连续、松手后轨迹自然消散、连续涂画 10 分钟无崩溃或内存增长。

### Phase 2：完成度

根据手感加入速度映射、轻微色相漂移、松手后 100～200ms 的视觉峰值延迟，以及 ACTIVE / AMBIENT / SLEEP 状态机。完成持续互动、静止点阵与熄屏状态的功耗测量。

### Phase 3：IMU 扩展（可选）

对残余点能量添加低通滤波后的重力漂移；摇动清屏只在明确阈值和冷却时间下触发。此阶段不得降低直接触摸响应，也不得造成静止时抖动。

## 7. 当前决策与风险

| 事项 | 决策 | 风险控制 |
| --- | --- | --- |
| UI 框架 | 直接 M5GFX 面板帧缓冲，暂停 LVGL | 关闭时恢复自动提交和 LVGL |
| 性能目标 | 先验收 30FPS | 真机统计而非主观估计 |
| Glow | 离散能量与预计算径向图样 | 先验证正确叠加，不使用黑底覆盖 |
| 输入 | CST820 单指轮询 + 路径插值 | 将采样和显示解耦 |
| 视觉 | 黑底、单一蓝青主题、蜂窝网格 | 先固定参数，避免设置页蔓延 |
| IMU | 后置 | 不影响 MVP 的触摸体验 |

本方案不将概念文档中的所有要求直接视作已确认实现；显示帧率、透明合成路径、触摸采样率、功耗和深睡唤醒均以 Phase 0/真机测试结果为准。

## 8. 当前实现状态

截至 `feat/glow-field` 当前版本：

- 已完成独立应用注册、LVGL/面板帧缓冲生命周期、单指触摸、路径插值、Ripple、Paint、首触振动和 30FPS 渲染节流；
- 已完成真正的蜂窝点阵、固定步长模拟以及与主循环频率无关的能量衰减；
- 已完成四种 Phase 0 基准场景、分场景串口统计、静态帧复用和 Interactive 脏带刷新；
- 颜色与现有视觉方案保持不变，后续作为独立需求处理；
- 已完成四种场景的真机自动基准并达到约 30FPS；尚待人工确认触摸手感与撕裂，并完成 10 分钟稳定性和功耗测试；
- ACTIVE / AMBIENT / SLEEP、独立图标和 IMU 扩展尚未实施。
