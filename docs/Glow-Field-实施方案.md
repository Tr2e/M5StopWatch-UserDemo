# Glow Field 实施方案（StopWatch）

## 1. 目的与范围

Glow Field 是 M5Stack StopWatch 圆形 AMOLED 上的全屏触摸光场：黑色背景上铺设低亮度蜂窝点阵，手指触摸和滑动向附近点注入能量，形成彩色光晕与会自然消散的轨迹。

首个可玩版本只交付：

- 单指触摸、路径插值与首帧视觉反馈；
- 固定蜂窝点阵、距离场能量注入与时间衰减；
- 预计算 Glow 图样或等效的轻量合成；
- 首次触摸的短振动与触觉冷却；
- 黑屏待机与回到应用启动器的按键退出。

首版不包含 Wi-Fi、设置页面、多主题、多点触摸、音频或 IMU 重力效果。IMU 倾斜和摇动清屏将在触摸体验、帧率及功耗通过验证后单独加入。

## 2. 基线与应用集成

本分支从 `feat/ruview-sentinel` 创建，以 RuView 的应用生命周期和硬件调用方式为集成基线，但不复用其 LVGL 视图结构。

RuView 证明了下列现有能力可用：

- `mooncake::AppAbility` 生命周期和 `KeyManager` 的退出行为；
- `GetHAL().getTouchPoint()` 的 CST820 单指坐标；
- `GetHAL().vibrate(duration, strength)` 的非阻塞振动；
- `GetHAL().updateImuData()` 及 BMI270 数据接口；
- 466px 圆形 UI 的布局约束。

Glow Field 的逐帧绘制不适合用大量 LVGL 对象表示。应用打开时将暂停 LVGL 刷新，直接用 `M5GFX` 的 PSRAM Canvas 绘制；关闭时清屏并恢复 LVGL。Typhoon 应用已采用这一模式，可作为直接实现参考。

建议文件布局：

```text
main/apps/app_glow_field/
  app_glow_field.h/.cpp       应用生命周期、输入、待机状态机
  glow_field_engine.h/.cpp    点阵状态、注入、衰减和后续 IMU 模拟
  glow_field_renderer.h/.cpp  Canvas、调色板、Glow 合成、帧率统计
```

后续接入还需在 `main/apps/apps.h` 和 `main/main.cpp` 注册 `AppGlowField`，并复用现有 `icon_typhoon` 暂作开发图标；最终图标独立设计，不阻塞 Phase 0。

## 3. 渲染与内存策略

屏幕逻辑尺寸必须从 `getDisplay().width()` / `height()` 读取，而不是硬编码 466。现有 CO5300 配置为 468×466（带偏移），因此所有点阵、圆形裁切和触摸坐标必须依赖运行时尺寸。

目标是先稳定 30 FPS。物理和触摸可维持约 60Hz，显示与物理解耦；若真机压力较大，显示允许降至稳定 24FPS，但触摸路径插值不能降级。

当前 HAL 已有：

- 面板帧缓冲；
- 放在 PSRAM 的全屏 `LGFX_Sprite` Canvas；
- `GetHAL().updateCanvas()` 的显示提交路径。

全屏 RGB565 缓冲约 424KiB，当前帧缓冲与 Canvas 共存仍远低于 8MB PSRAM。Phase 0 不新增双缓冲，先测量现有路径，避免无依据的内存和带宽复杂化。

### Glow 合成原则

不能把“预乘到黑色背景”的不透明 RGB565 Sprite 直接逐张覆盖到 Canvas：后绘制 Sprite 的黑色区域会擦掉已有光晕，多个触点相遇时视觉会出错。

Phase 0 依次验证：

1. M5GFX 透明 Sprite 的实际帧率和叠加效果；
2. 以透明色跳过黑色像素的预计算 RGB565 Sprite；
3. 若仍不足，针对 Glow 包围盒在 Canvas 像素上执行饱和加色或逐通道最大值合成。

优先选择能稳定达到目标帧率、且能保留重叠光晕的最简单方案。颜色和能量均量化为 8～16 档；调色板和径向衰减曲线在启动时生成，禁止逐像素 HSV 转换和实时高斯模糊。

## 4. 数据与交互模型

```cpp
struct Dot {
    int16_t x;
    int16_t y;
    uint8_t energy;       // 0..255
    uint8_t hue_index;    // 主题内的离散颜色档
    bool visible;         // 圆形区域内
};
```

- 蜂窝网格初始间距：20px；基础半径：4px；预计 300～450 个可见点。
- 触摸半径初始值：36～44px；距离影响采用平方距离与二次曲线，避免 `sqrtf`。
- 采样点间距不超过点阵间距的一半；每次拖动在前后坐标间线性插值。
- 能量以基于时间的指数衰减更新，主要可见残影持续 0.8～2 秒，低于阈值归零。
- 首次按下立刻注入能量并在下一次显示时绘制；只在按下沿触发一次 25～40ms 振动，并设置 75ms 冷却。

速度映射、颜色漂移和“松手后短暂增强”均作为 Phase 2 的调参项，不能阻塞固定半径的核心体验。

## 5. 运行循环与电源状态

```text
onOpen:  停止 LVGL，清空 Canvas，建立点阵，记录显示尺寸和内存
running: 读取触摸 -> 插值注入 -> 衰减 -> 到帧时间则渲染并提交
onClose: 清屏，停止振动，恢复 LVGL
```

待机状态在核心绘制稳定后加入：

```text
ACTIVE  -- 10 秒无触摸 --> AMBIENT（降低亮度、极弱点阵）
AMBIENT -- 30 秒无触摸 --> SLEEP（熄屏）
SLEEP   -- 触摸/按键/IMU --> ACTIVE
```

亮度恢复与触摸唤醒需要按 CST820 的真实睡眠/中断能力进行真机验证；首版先实现应用内的亮度降低和非深睡黑屏，不将深睡作为验收前置条件。

## 6. 分阶段计划与验收

### Phase 0：显示基准（第一个代码交付）

实现最小 Glow Field 应用和串口统计，分别运行 10 秒后报告稳定 FPS、平均帧时和最大帧时：

1. 纯黑/纯色全屏提交；
2. 约 400 个普通蜂窝点；
3. 约 400 个不同强度的 Glow 点；
4. 连续触摸时的完整路径与 Glow 叠加。

通过条件：第 3、4 项达到稳定 30FPS，且没有撕裂、触摸明显断线或 PSRAM 分配失败。若未通过，按“减小 Glow 半径 → 降低强度档位 → 24FPS 显示 → 局部刷新”的顺序优化。

### Phase 1：核心触摸体验

加入路径插值、距离场、时间衰减、首触振动和调色板。通过条件是快速划线连续、松手后轨迹自然消散、连续涂画 10 分钟无崩溃或内存增长。

### Phase 2：完成度

根据手感加入速度映射、轻微色相漂移、松手后 100～200ms 的视觉峰值延迟，以及 ACTIVE / AMBIENT / SLEEP 状态机。完成持续互动、静止点阵与熄屏状态的功耗测量。

### Phase 3：IMU 扩展（可选）

对残余点能量添加低通滤波后的重力漂移；摇动清屏只在明确阈值和冷却时间下触发。此阶段不得降低直接触摸响应，也不得造成静止时抖动。

## 7. 当前决策与风险

| 事项 | 决策 | 风险控制 |
| --- | --- | --- |
| UI 框架 | 直接 M5GFX Canvas，暂停 LVGL | 复用 Typhoon 的打开/关闭模式 |
| 性能目标 | 先验收 30FPS | 真机统计而非主观估计 |
| Glow | 离散能量与预计算径向图样 | 先验证正确叠加，不使用黑底覆盖 |
| 输入 | CST820 单指轮询 + 路径插值 | 将采样和显示解耦 |
| 视觉 | 黑底、单一蓝青主题、蜂窝网格 | 先固定参数，避免设置页蔓延 |
| IMU | 后置 | 不影响 MVP 的触摸体验 |

本方案不将概念文档中的所有要求直接视作已确认实现；显示帧率、透明合成路径、触摸采样率、功耗和深睡唤醒均以 Phase 0/真机测试结果为准。
