# Vector Canyon Fighter：战机与 HUD 补充设计

## 1. 参考结论

战机采用用户参考图所表达的结构语言，但设计为项目自己的线框宇宙战机：

- 细长机鼻与前置座舱，建立高速截击机比例；
- 中央厚实机身，而不是纸片三角形；
- 四发推进器形成清晰的尾部体积；
- 上下分离的四片翼面形成 X 型后视轮廓；
- 翼端短武器吊舱强化辨识度，但不使用过长炮管占据画面；
- 默认后上方第三人称视角必须同时看见机背、座舱、发动机和翼面厚度；K1 第一人称全屏 HUD 模式不绘制战机本体。

战机不是对参考型号的逐线复刻。有限像素下优先保留比例、轮廓和体块关系，省略蒙皮铆钉、内部机械和重复细线。

## 2. 真机线框分层

目标占圆屏直径 14%–16%，预计有效宽度约 64–72 像素。线框分为三层：

| 层级 | 内容 | 视觉 |
| --- | --- | --- |
| 主轮廓 | 机鼻、机身、四翼、尾部发动机 | 高亮冷白，必要时双像素 |
| 结构线 | 翼梁、机身分段、发动机连接 | 低亮蓝绿，单像素 |
| 识别色 | 座舱、四个喷口、推进尾焰 | 座舱青色、尾焰橙色 |

计划模型规模：约 40–48 个三维顶点、70–84 条结构边。若细线在真机上聚成白块，优先删内部结构线，不能删除四翼、四发、长机鼻和机身厚度。

## 3. 姿态表现

- Roll：整架战机绕画面纵轴旋转，四翼轮廓必须明显改变；
- Pitch：机鼻与尾部产生相对透视变化，不能只做屏幕上下平移；
- Yaw/横移：战机只做小幅跟随，峡谷视线承担主要方向感；
- Boost：四个喷口同时出现短尾焰，长度受速度状态控制；
- 战机永远不遮挡远景开口或中央飞行路径标记。

## 4. 圆屏 HUD 安全区

HUD 只参考航空平显的信息层级，不照搬完整仪表。规划区域：

```text
             [顶部弧区]
            航向 / 姿态

 [左侧速度]   [中央净空]   [右侧高度]
              峡谷与航迹

        [战机：下部中央]

 [模式/输入]             [告警/升降率]
```

- 中央净空：`x=88..362, y=82..310`，原则上不放常驻文字；
- 顶部弧区：显示三位航向和短姿态刻度，限制在 `y=38..76`；
- 左侧：速度数字 + 3–5 段短刻度，限制在 `x=36..84`；
- 右侧：高度数字 + 升降趋势，限制在 `x=366..414`；
- 底部左：输入源或巡航/加速状态；
- 底部右：碰撞、地形或校准告警；
- 战机区域：约 `x=185..265, y=315..382`。

## 5. 最小信息集

常态只显示：

- `SPD`：速度；
- `ALT`：相对谷底高度；
- `HDG`：峡谷方向或航向；
- 小型 Roll/Pitch 姿态标；
- `CRUISE/BOOST`；
- 输入源状态。

仅在事件发生时显示：

- 地形接近警告；
- 撞击/重试提示；
- IMU 校准；
- 外设断开或回退输入源。

删除大型标题、常驻说明文字、重复数字和完整航空速度/高度带。HUD 的目标是提供姿态反馈，而不是模拟真实民航仪表。

## 6. R4 验收条件

- [ ] 不看细节也能从轮廓识别长机鼻、四翼和四发；
- [ ] 后上方视角具有机身厚度，不像纸飞机；
- [ ] Roll/Pitch 在战机模型和 HUD 姿态标上保持一致；
- [ ] 战机占比在 14%–16%，不压过峡谷；
- [ ] 中央净空区没有常驻数字遮挡；
- [ ] HUD 在圆屏边缘无裁字，且信息可在一眼内读取；
- [ ] 简化后仍保留速度、高度、航向和姿态四类核心反馈；
- [ ] HUD 和战机不能被用来掩盖地形结构问题。
