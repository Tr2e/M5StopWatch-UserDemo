# 缩小拖动与选车手势修复（2026-09-10）

交互档为 65% 内部绘制（229×187）／85% 屏幕区域（299×245），两者均以原生 352×288 为基准，保持原模型细节与程序涂装。释放或摇杆回中 150ms 后请求 82% 绘制／93% 显示，300ms 后请求完整原生画面；实际呈现时间还需绘制和传输。慢帧可跳过中间档，恢复中再次操作立即回交互档。触控区域、角度与 UI 不缩小。正常帧缓冲分配不增加。

选车页修正竖向符号及累计越界量，向下拖动增加 pitch，限位后的反向 1px 立即响应；保留选车页松手返回预设。VIEW CAR 松手仍保留角度。

## 验证

- `host-tests.log`：完整 ASan/UBSan 游戏、设备／外设、Vector Run、Launcher 和生产渲染回归。
- `renderer-tests.log`：修正测试姿态生成器的 dy 符号后再次运行生产渲染 ASan/UBSan，确保依旧覆盖预期俯仰角，而不是重复采到限位。
- `frame-comparison.json`：340 张原有画面均未改变。选车拖动截图的输入 dy 已按新方向转换，使其仍代表原来的指定观察角度。
- `comparison-0/3/7.png`：生产画面，从左到右为前版 77% 全尺寸、新交互 65%／85%、恢复 82%／93%、原生静止。已检查 MAGNUM 与 BROCKEN 的外形、阴影和 UI。
- 八车型 × 18 方位 × 横竖双向验证选车模型最近表面跟随拖动；四种预设验证限位反向、释放恢复和切换取消。
- 八车型 × 80 姿态检查两档新尺寸的背景复用与完整绘制逐像素一致，所有变化像素位于原局刷区域内。原生及前版比例仍保持基线画面。

## 真机对照口径

`compact_device_benchmark.cpp` 在同一进程内比较 77%／100% 显示、65%／85%、82%／93%、100%／100% 四种状态，使用一个 GarageRenderer 和正常 RaceRenderer 分配，轮换执行顺序。每车 13 个相同姿态，首帧预热，记录其余 12 帧的绘制与真实局部传输时间。`p95_us` 是单车单档绘制＋传输的最近秩 P95；12 个样本时等于最大值，不能视为稳定长时统计，也不能平均各车 P95 当整体 P95。

新交互的尺寸和采样率有意不同，因此不做新旧画面 CRC 相等判断。固定序列对照没有真人触屏／摇杆任务或比赛音频，不能直接等同实操帧率或输入端到端延迟。选车页的真人手感、恢复动画节奏、长拖和跨 App 重入仍待试用。

复现临时测试时将 benchmark 复制回生产 view 目录，在 HAL 初始化后、安装 App 前调用 `compactDeviceBenchmark()`，使用 `-O2 -fno-builtin-memset` 并重新配置构建。完成后必须移除入口与源文件，重新构建正常固件。仅使用已核验 StopWatch 83401、303A:1001、44:1B:F6:C1:8A:00 的应用分区 0x20000；PaperColor 83301 不参与。
