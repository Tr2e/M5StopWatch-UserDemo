# RX-78 无损 fast path 真机证据（2026-09-21）

硬件：ESP32-S3，240 MHz，8 MiB 80 MHz Octal PSRAM，CO5300 468×466 framebuffer 面板。  
基线 commit：`ffc6717`；测试分支：`feat/gundam-arena`。  
每个真机 A/B 档位交错运行 24 帧，姿态序列相同；65% 和 100% 分开统计。

## 接受项

### Solid scanline span + trusted depth

实体三角形逐行用原重心公式确认左右边界，保证内部覆盖后省略重复 coverage 判断；三角形级验证逆深度范围后，内部像素省略有限值、正值和 clamp 检查。

| 分辨率 | 参考 raster | 候选 raster | 参考 draw | 候选 draw |
| --- | ---: | ---: | ---: | ---: |
| 65% | 88.187 ms | 85.166 ms | 150.463 ms | 147.260 ms |
| 100% | 142.947 ms | 132.828 ms | 205.211 ms | 194.822 ms |

结论：raster 分别降低 3.4%/7.1%，整帧 draw 分别降低 2.1%/5.1%。

### Native framebuffer composite

为 CPU 可寻址 framebuffer 增加可选行访问与脏区标记接口。仅在 RGB565、rotation 0、完整 clip 和真实 framebuffer 均成立时，光栅器直接合成到 framebuffer 行；其他设备和布局回退原 span API。面板存储为 byte-swapped RGB565，写入前显式转换。

同姿态整屏 FNV-1a 哈希：

- 65%：reference `548123638`，native `548123638`，exact=true。
- 100%：reference `3299443075`，native `3299443075`，exact=true。

| 分辨率 | 参考 blit | native blit | 参考 draw | native draw | 含 present 周期 | 估算 FPS |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 65% | 37.340 ms | 12.920 ms | 149.370 ms | 124.626 ms | 136.472 ms | 7.33 |
| 100% | 24.426 ms | 13.452 ms | 190.424 ms | 179.575 ms | 191.547 ms | 5.22 |

结论：65% blit 降低 65.4%、draw 降低 16.6%；100% blit 降低 44.9%、draw 降低 5.7%。这是本轮最大且逐字节等价的单项收益。

### Framebuffer span transaction

在 native framebuffer 路径出现前，受保护的 `startWrite/endWrite + setAddrWindow/writePixels` 使 blit 稳定减少约 1.1–1.2 ms，总 draw 改善约 0.7–0.8%。保留为 native 条件不满足时的回退优化。

### Sparse depth clear

RX-78 最终只占活动深度平面的约 17.8%。光栅器现在可接收调用方提供的占用 bitset；下一帧只清零上帧实际非零的深度项，而不是向整个 PSRAM 深度平面写零。存储是显式可选的，Museum 提供约 22 KiB，其他共享光栅器实例不增加大块工作集。Nu 的 65% 隐藏线会原地扩展深度布局，因此保持原始完整清理。

两个独立 renderer 交错 24 帧，避免 A/B 互相破坏上一帧占用状态：

| 分辨率 | 基线 clear | 稀疏 clear | 基线 draw | 稀疏 draw | 稀疏 present |
| --- | ---: | ---: | ---: | ---: | ---: |
| 65% | 22.318 ms | 19.367 ms | 123.082 ms | 121.891 ms | 11.740 ms |
| 100% | 28.781 ms | 22.086 ms | 178.608 ms | 176.054 ms | 11.771 ms |

65%/100% draw 分别降低 1.0%/1.4%。固定姿态整屏 FNV-1a 均为 `2718444083`，逐字节一致。

随后单独比较“光栅首次写入时记录占用”与“合成可见像素时记录占用”。后者从光栅热循环移除了一个分支和 bitset 写入：100% 的 raster 从 142.246 ms 降至 138.554 ms，尽管 blit 从 14.439 ms 增至 16.035 ms，draw 仍从 183.264 ms 降至 181.164 ms（-1.15%）。65% 因最近邻放大会重复遍历源样本，draw 从 127.251 ms 增至 127.977 ms，因此生产实现采用混合策略：65%/90% 保持光栅阶段记录，只有 100% 1:1 合成融合记录。该组 A/B 固定姿态哈希同为 `2718444083`。

混合策略最终正常 Launcher 固件 SHA-256：`2643c218abd823bb900f3688effaf8e7c86c51a73127c08d34e17084f386f333`；已刷入同一台 ESP32-S3 并完成 Launcher 启动验证。

### RX-78 双核行分区光栅

将已投影、已裁剪的 RX-78 面片按原始顺序保存一次，两个 CPU 核分别处理互不重叠的上下行区间。分界行对齐到稀疏占用 bitset 的字节边界，因此颜色、深度和占用记录都没有跨核写冲突；每个分区仍严格遵守原面片顺序和等深覆盖语义。CPU1 使用随 renderer 生命周期创建的常驻 worker，退出 Museum 时同步停止并回收。

同一固件、同一姿态序列、基线/双核交错 24 帧：

| 分辨率 | 单核 raster | 双核 raster | 单核 draw | 双核 draw | 双核 present | 双核周期/FPS |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 65% | 88.462 ms | 69.293 ms | 127.133 ms | 107.972 ms | 11.797 ms | 119.769 ms / 8.35 |
| 100% | 138.390 ms | 100.476 ms | 181.188 ms | 143.229 ms | 11.815 ms | 155.044 ms / 6.45 |

65%/100% 的 raster 分别下降 21.7%/27.4%，完整周期分别下降 13.8%/19.7%。固定姿态整屏 FNV-1a 均为 `2718444083`，exact=true。40%/50%/60%/70% 分区扫描显示 50% 明显最优；这也说明当前上限同时受双核共享 PSRAM 带宽与重复 triangle setup 约束，并非简单的单核算力二等分。

移除启动基准后的正常 Launcher 固件 SHA-256：`4bd27390f0473356256895c403ffbf75f084d75431bef73900bab41bf9451a0a`。

### 紧凑双核面片列表

RX-78 当前全部是纯色材质。双核回放列表不再保存透视 UV、横向 bounds 和通用材质字段，只保留四顶点 xyz、纵向 bounds、RGB565 与光照；若未来出现非纯色面片，会按原顺序冲刷已缓存纯色面片并安全回退通用单核路径。`MuseumRenderer::workingBytes()` 从 1,755,440 B 降至 1,575,216 B，减少 180,224 B。

相同 24 姿态真机序列中，65% draw/raster 从 107.972/69.293 ms 降至 106.355/66.882 ms，含 present 周期为 118.102 ms，即约 8.47 FPS；100% draw/raster 从 143.229/100.476 ms 降至 140.634/97.906 ms，周期为 152.402 ms，即约 6.56 FPS。固定姿态整屏哈希仍为 `2718444083`。

移除基准后的正常 Launcher 固件 SHA-256：`7e559ead20c26eb1892c0822bd3bf7e03875ec92c79ea10f0c89c6deea21a1b6`。

## 否决项

- 交错 `[depth16|color16]`：100% blit 29.72→23.84 ms，但 32-bit 清屏抵消收益；65% draw 143.25→151.63 ms，100% 194.58→199.69 ms。
- 最近邻重复行缓存：bitset 扫描和分支抵消读取节省，真机无稳定收益。
- 直接重关联深度平面：6,720-case 中出现 1 个 framebuffer 像素差，否决。
- 带量化边界回退的深度平面：6,720-case 精确一致，但 RX-78 主机 65% 从约 950 µs 退化到 1,062 µs，未刷真机。
- 保守 early-Z 深度平面：像素一致，但真机 raster 在 65%/100% 分别慢 4.7%/5.6%。
- 8-bit 索引色平面：110 色、无溢出，但 65% draw 150.114→154.953 ms，100% 188.431→202.495 ms。
- 无像素中心面片跳过：整屏哈希一致；65% draw 125.339→125.047 ms（噪声级），100% 180.248→180.499 ms（略慢）。
- front-to-back 中心深度排序：首个 RX-78 姿态改变 88 像素；部件级排序改变 14 像素；加入严格深度区间约束仍改变 4 个 Q13 等深边界像素，全部回退。
- 4-bit 片内粗深度：完整 88 KiB 在正常 App 创建后的最大连续 internal block（69,632 B）下无法分配；缩为 65% 专用约 37 KiB 后可分配且哈希一致，但 65% draw 124.299→129.623 ms，回退。
- 2% 量化边界回退深度平面：6,720-case 与真机哈希一致，但 65% raster 83.361→85.570 ms、100% 131.240→136.891 ms，回退。

## RX-78 光栅工作量

诊断构建覆盖 288 个姿态/配置样本，每帧平均：

| 分辨率 | triangles | rows | covered | depth rejected | written | final covered | writes/final |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 65% | 2,953 | 12,226 | 41,468 | 10,881 | 30,587 | 13,566 | 2.255 |
| 90% | 2,953 | 18,139 | 79,463 | 20,867 | 58,596 | 25,987 | 2.255 |
| 100% | 2,953 | 20,519 | 97,901 | 25,708 | 72,193 | 32,020 | 2.255 |

三档深度拒绝率均约 26.3%，说明 overdraw 确实存在，但等深覆盖顺序是硬约束；后续应优先研究保序的四边形内核，而不是继续尝试全局排序。

## 正确性与剩余差距

- `tools/test_gundam_museum_perf.sh`：`pixel_identical_cases=6720`。
- `tools/test_gundam_museum.sh`：几何、构图、控制和重入通过。
- ASan/UBSan 两套测试通过。
- 65% 当前约 7.3 FPS，距离 15 FPS 的 66.7 ms 周期仍约差 69.8 ms；当前主要剩余项是约 85 ms 的 project+raster，而不是约 13 ms 的 blit。

下一阶段应围绕实际覆盖像素和 overdraw 建立计数，验证可保持等深语义的 front-to-back/HZB 组合，或设计专用的实体四边形/凸多边形光栅内核；不再重复已否决的单项 early-Z、索引色和 strip 路线。
