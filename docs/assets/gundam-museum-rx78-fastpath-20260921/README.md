# RX-78 无损 fast path 真机证据（2026-09-21）

硬件：ESP32-S3，240 MHz，8 MiB 80 MHz Octal PSRAM，CO5300 468×466 framebuffer 面板。  
基线 commit：`ffc6717`；测试分支：`feat/gundam-arena`。  
每个真机 A/B 档位交错运行 24 帧，姿态序列相同；65% 和 100% 分开统计。

> 2026-09-22 显示链追加结论：PSRAM framebuffer 直连 GPSPI-DMA 的真实 80 MHz 版本虽把周期降到 69.22 ms，但 SPI2 硬件 `outfifo_empty_err` 证实花屏源于 PSRAM 供数断流。此前仅调用 `setClock(40 MHz)` 的尝试后来确认底层仍工作在 80 MHz，不能作为 40 MHz 证据。随后补做“128 行批次、欠载后重设窗口并最多重传三次、最终 SRAM bounce”的可靠性版本：26.67 MHz 每 96 帧出现 169–181 次欠载且周期 82.18–82.73 ms；20 MHz 三批仅 0/0/1 次欠载，但周期仍为 78.91–79.05 ms。69.22 ms 因未完整传输而不是有效收益；可靠直连均慢于 4 行片内 bounce 的 74.42 ms，当前已回退。只在硬件/仲裁条件改变，或新的背压实现经实际面板验收且端到端更快时重开。

## 接受项

### Solid scanline span + trusted depth

实体三角形逐行用原重心公式确认左右边界，保证内部覆盖后省略重复 coverage 判断；三角形级验证逆深度范围后，内部像素省略有限值、正值和 clamp 检查。

| 分辨率 | 参考 raster | 候选 raster | 参考 draw | 候选 draw |
| --- | ---: | ---: | ---: | ---: |
| 65% | 88.187 ms | 85.166 ms | 150.463 ms | 147.260 ms |
| 100% | 142.947 ms | 132.828 ms | 205.211 ms | 194.822 ms |

结论：raster 分别降低 3.4%/7.1%，整帧 draw 分别降低 2.1%/5.1%。

### Native framebuffer composite

为 CPU 可寻址 framebuffer 增加可选行访问与脏区标记接口。仅在 RGB565、rotation 0、完整 clip 和真实 framebuffer 均成立时，光栅器直接合成到 framebuffer 行；其他设备和布局回退原 span API。面板存储为 byte-swapped RGB565，写入前显式转换。

同姿态整屏 FNV-1a 哈希：

- 65%：reference `548123638`，native `548123638`，exact=true。
- 100%：reference `3299443075`，native `3299443075`，exact=true。

| 分辨率 | 参考 blit | native blit | 参考 draw | native draw | 含 present 周期 | 估算 FPS |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 65% | 37.340 ms | 12.920 ms | 149.370 ms | 124.626 ms | 136.472 ms | 7.33 |
| 100% | 24.426 ms | 13.452 ms | 190.424 ms | 179.575 ms | 191.547 ms | 5.22 |

结论：65% blit 降低 65.4%、draw 降低 16.6%；100% blit 降低 44.9%、draw 降低 5.7%。这是本轮最大且逐字节等价的单项收益。

### Framebuffer span transaction

在 native framebuffer 路径出现前，受保护的 `startWrite/endWrite + setAddrWindow/writePixels` 使 blit 稳定减少约 1.1–1.2 ms，总 draw 改善约 0.7–0.8%。保留为 native 条件不满足时的回退优化。

### Sparse depth clear

RX-78 最终只占活动深度平面的约 17.8%。光栅器现在可接收调用方提供的占用 bitset；下一帧只清零上帧实际非零的深度项，而不是向整个 PSRAM 深度平面写零。存储是显式可选的，Museum 提供约 22 KiB，其他共享光栅器实例不增加大块工作集。Nu 的 65% 隐藏线会原地扩展深度布局，因此保持原始完整清理。

两个独立 renderer 交错 24 帧，避免 A/B 互相破坏上一帧占用状态：

| 分辨率 | 基线 clear | 稀疏 clear | 基线 draw | 稀疏 draw | 稀疏 present |
| --- | ---: | ---: | ---: | ---: | ---: |
| 65% | 22.318 ms | 19.367 ms | 123.082 ms | 121.891 ms | 11.740 ms |
| 100% | 28.781 ms | 22.086 ms | 178.608 ms | 176.054 ms | 11.771 ms |

65%/100% draw 分别降低 1.0%/1.4%。固定姿态整屏 FNV-1a 均为 `2718444083`，逐字节一致。

随后单独比较“光栅首次写入时记录占用”与“合成可见像素时记录占用”。后者从光栅热循环移除了一个分支和 bitset 写入：100% 的 raster 从 142.246 ms 降至 138.554 ms，尽管 blit 从 14.439 ms 增至 16.035 ms，draw 仍从 183.264 ms 降至 181.164 ms（-1.15%）。65% 因最近邻放大会重复遍历源样本，draw 从 127.251 ms 增至 127.977 ms，因此生产实现采用混合策略：65%/90% 保持光栅阶段记录，只有 100% 1:1 合成融合记录。该组 A/B 固定姿态哈希同为 `2718444083`。

混合策略最终正常 Launcher 固件 SHA-256：`2643c218abd823bb900f3688effaf8e7c86c51a73127c08d34e17084f386f333`；已刷入同一台 ESP32-S3 并完成 Launcher 启动验证。

### RX-78 双核行分区光栅

将已投影、已裁剪的 RX-78 面片按原始顺序保存一次，两个 CPU 核分别处理互不重叠的上下行区间。分界行对齐到稀疏占用 bitset 的字节边界，因此颜色、深度和占用记录都没有跨核写冲突；每个分区仍严格遵守原面片顺序和等深覆盖语义。CPU1 使用随 renderer 生命周期创建的常驻 worker，退出 Museum 时同步停止并回收。

| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 65% | 88.462 ms | 69.293 ms | 127.133 ms | 107.972 ms | 11.797 ms | 119.769 ms / 8.35 |
| 100% | 138.390 ms | 100.476 ms | 181.188 ms | 143.229 ms | 11.815 ms | 155.044 ms / 6.45 |

65%/100% 的 raster 分别下降 21.7%/27.4%，完整周期分别下降 13.8%/19.7%。固定姿态整屏 FNV-1a 均为 `2718444083`，exact=true。40%/50%/60%/70% 分区扫描显示 50% 明显最优；这也说明当前上限同时受双核共享 PSRAM 带宽与重复 triangle setup 约束，并非简单的单核算力二等分。

### 紧凑双核面片列表

RX-78 当前全部是纯色材质。双核回放列表不再保存透视 UV、横向 bounds 和通用材质字段，只保留四顶点 xyz、纵向 bounds、RGB565 与光照；若未来出现非纯色面片，会按原顺序冲刷已缓存纯色面片并安全回退通用单核路径。`MuseumRenderer::workingBytes()` 从 1,755,440 B 降至 1,575,216 B，减少 180,224 B。

相同 24 姿态真机序列中，65% draw/raster 从 107.972/69.293 ms 降至 106.355/66.882 ms，含 present 周期为 118.102 ms，即约 8.47 FPS；100% draw/raster 从 143.229/100.476 ms 降至 140.634/97.906 ms，周期为 152.402 ms，即约 6.56 FPS。固定姿态整屏哈希仍为 `2718444083`。

移除基准后的正常 Launcher 固件 SHA-256：`7e559ead20c26eb1892c0822bd3bf7e03875ec92c79ea10f0c89c6deea21a1b6`。

### 房间绘制与几何准备重叠

细分计时显示 65% 的 background/room/depth-clear/cull 分别约为 12.99/5.08/2.15/4.15 ms。常驻 CPU1 worker 先绘制房间，CPU0 同时清理离屏深度、剔除并准备面片；房间任务完成后，同一个 worker 再处理下半屏光栅，framebuffer composite 始终等待房间结束，因此绘制顺序确定。

共享 PSRAM 争用使并行 room work 自身增至约 8.3 ms，深度清理与准备也略有变慢，但 wall time 仍改善：65% draw 从 106.390 降至 104.999 ms，含 present 周期 116.757 ms（约 8.57 FPS）；100% draw 从 140.426 降至 138.794 ms，周期 150.521 ms（约 6.64 FPS）。这证明非重叠任务并行有效，同时也把共享内存带宽确定为后续框架优化的核心约束。

移除基准后的正常 Launcher 固件 SHA-256：`917e9eed0f842c8ae05a97f60f6f0b3685e5311b95fd3d87e9fa008c89bc5898`。

## 否决项

- 交错 `[depth16|color16]`：100% blit 29.72→23.84 ms，但 32-bit 清屏抵消收益；65% draw 143.25→151.63 ms，100% 194.58→199.69 ms。
- 最近邻重复行缓存：bitset 扫描和分支抵消读取节省，真机无稳定收益。
- 直接重关联深度平面：6,720-case 中出现 1 个 framebuffer 像素差，否决。
- 带量化边界回退的深度平面：6,720-case 精确一致，但 RX-78 主机 65% 从约 950 µs 退化到 1,062 µs，未刷真机。
- 保守 early-Z 深度平面：像素一致，但真机 raster 在 65%/100% 分别慢 4.7%/5.6%。
- 8-bit 索引色平面：110 色、无溢出，但 65% draw 150.114→154.953 ms，100% 188.431→202.495 ms。
- 无像素中心面片跳过：整屏哈希一致；65% draw 125.339→125.047 ms（噪声级），100% 180.248→180.499 ms（略慢）。
- front-to-back 中心深度排序：首个 RX-78 姿态改变 88 像素；部件级排序改变 14 像素；加入严格深度区间约束仍改变 4 个 Q13 等深边界像素，全部回退。
- 4-bit 片内粗深度：完整 88 KiB 在正常 App 创建后的最大连续 internal block（69,632 B）下无法分配；缩为 65% 专用约 37 KiB 后可分配且哈希一致，但 65% draw 124.299→129.623 ms，回退。
- 2% 量化边界回退深度平面：6,720-case 与真机哈希一致，但 65% raster 83.361→85.570 ms、100% 131.240→136.891 ms，回退。
- 稀疏 framebuffer 背景恢复：使用上一帧模型占用位图恢复模型像素，并以背景色重画旧房间线；哈希仍为 `2718444083`，但零散写使 65%/100% background 从约 12.4 ms 增至 23.9/39.7 ms，draw 增至 116.1/166.1 ms，回退。
- 65% 半屏 internal-RAM 深度：在创建 CPU1 worker 前成功分配 76,176 B 连续内部内存，将 276×138 下半屏深度随机读写留在片内；24 姿态 A/B 的整屏哈希完全一致。worker 从 50.625 ms 降至 49.538 ms（约 1.09 ms），但将深度连续回写 PSRAM 需要 2.012 ms，`project_raster` 从 70.204 ms 增至 71.447 ms。继续尝试不回写、合成时直接读取占用 bitset，虽保持哈希一致，却使当时的逐目标像素位测试合成明显变慢（候选 `blit` 18.961 ms；原生深度连续读取基线约 15 ms）。该“镜像+回写”实现完整回退；后续 sparse composite 改为由置位源像素驱动后不再读取深度，使无回写的权威深度带重新具备净收益，见下文。
- 逐行占用范围清理：记录每行首末占用，将下一帧逐置位深度清零改为连续跨度清零。96+96 帧真机 A/B 哈希一致，`depth clear` 4.563→1.864 ms，但记录边界使 raster 56.183→56.956 ms，最终 draw 86.541→86.436 ms，仅快 0.105 ms 且增加约 1.7 KiB 常驻状态，按收益门槛回退。
- 预计算纯色面片最终颜色：尝试在串行准备阶段只做一次光照调色，避免 CPU0/CPU1 各自重复。96+96 帧哈希一致，但 panel prepare 13.174→13.209 ms、raster 55.275→55.306 ms、draw 84.941→84.974 ms，未产生收益，已回退。
- 稀疏合成源行复用：将同一 65% 源行只解码一次，生成目标 span 后 memcpy 到 1–2 个目标行；48 姿态哈希一致，但候选 `blit` 9.365 ms 与已接受实现的 9.383 ms 等价，同时增加约 3.4 KiB 栈临时量和 span 复杂度，完整回退。A/B 参考值 11.141 ms 是实验中移除 `destinationLast` 缓存污染热循环所致，不作为生产基线。
- 双核光栅非对称分区：针对 65% 模型分辨率扫描 44%/46%/48%/50% 上半区，24 姿态整屏哈希全部一致；`project+raster` 分别为 70.183/67.489/66.159/64.385 ms，draw 分别为 106.403/99.560/98.255/96.409 ms。50% 仍明确最优，结合此前 60%/70% 更慢的数据，说明两个核心的行工作量已基本对称；保持生产代码固定等分，移除诊断开关。
- 可见共享顶点并行投影：阶段分解先测得面片准备 19.606 ms、上下半屏光栅 42.879/44.542 ms。让 CPU1 完成房间后与 CPU0 各投影一半可见共享顶点，投影墙钟时间仅 2.489 ms，但标记、源索引和新增 32 KiB PSRAM 工作集使完整面片准备反增至 20.819 ms；draw 98.021→99.213 ms，完整回退。结论是当前 19.6 ms 主要不是顶点变换，不能以扩大冷数据换取其并行化。
- 导航 overlay 原生 framebuffer 直写：按 M5GFX 同样的 Bresenham 覆盖规则直写两个箭头，48 姿态整屏哈希一致，但 overlay 仅 122→96 µs、draw 86.992→86.964 ms，只省 28 µs。不为如此小的收益保留重复线段内核，仅保留 `overlay_us` 指标。
- 上下半屏面片索引：准备阶段为两个光栅分区分别写入有序 `uint16_t` 索引，单姿态将每核遍历量从 2,744 降到 1,130/830。18 轮各 96 帧哈希一致，CPU0/CPU1 光栅约 40.080/40.150→39.62/39.45 ms；但串行 panel prepare 12.498→约 13.17 ms、raster 53.381→约 53.51 ms、draw 82.489→约 82.64 ms，净回退。只有能在资产/命令生成期零额外外存写入地形成分带命令流时才值得重开。
- 扫描边不变量缓存：把大三角形逐行重复的边 min/max、水平判断和端点预存为三条 `RowEdge`，重心、覆盖和深度运算不变。主机 6,720 组及共享赛车测试通过，真机 5 轮各 96 帧哈希一致；但额外栈工作集/加载使 CPU0/CPU1 40.080/40.150→40.499/40.498 ms、raster 53.381→53.772 ms、draw 82.489→82.898 ms，已回退。Xtensa 上应以真实寄存器压力和访存成本评估常量提升，不能只按源码运算数判断。
- 重心循环递增 `pixelX`：避免每像素整数转浮点和重复构造横坐标，6,720 组主机与真机 6×96 帧哈希一致；但 raster 约 45.26→45.71 ms、周期约 74.42→74.89 ms，寄存器/依赖链成本反而更高，已回退。
- 连续 meshlet 粗剔除机会测量：2,736 面 × 96 姿态中，4 面组使用完美判据的理论跳过上限也只有总面测试的 6.03%，8 面组为 0.30%，16/32 面组为 0。相对仅 2.43 ms 的 cull 阶段，尚未计入包围体/normal-cone 成本的绝对上限约 0.15 ms，因此不引入新元数据和热分支。
- 剔除/命令生成融合：RX-78 剔除循环直接生成 pass-0 prepared panels、只让 pass-1 经过 staging，保持原 pass 顺序且不新增命令流。6,720 组主机和 7×96 帧真机哈希一致，但固件约增大 3.8 KiB，周期由约 74.42 ms 退化到 74.76–74.82 ms；减少一次顺序扫描未抵消热代码膨胀与 cache/流水布局变化，完整回退。
- 可信实体分带批量回放：把已完成 band selection 的有序 panel/index 数组一次交给 raster，每个行带只解析一次 split depth/color、sparse record 和固定快路径状态，旧通用单面包装器移回 flash。6,720 组主机与 23×96 帧真机哈希一致，CPU0/CPU1 光栅约 34.21/34.47→33.55/34.01 ms，raster 约 45.26→44.68 ms，周期约 74.42→73.86–73.91 ms；internal free 约增加 0.3 KiB，已接受为赛车等其他有序实体批次也可复用的框架原语。
- 52 B 最终光栅命令：`top/bottom` 只服务于分带选择，选择完成后不再让两核从 PSRAM 读取这 8 B；最终命令从 60 B 压到 52 B，不新增流且保持索引和提交顺序。6,720 组主机与 14×96 帧真机哈希一致，Museum 常驻工作集减少 32 KiB，panel prepare 约 10.15→9.80 ms、raster 44.68→44.13 ms，周期约 73.88→73.29–73.32 ms，已接受为“选择命令/执行命令”分层的框架 ABI。
- 直接生成执行 ABI：共享顶点投影缓存直接写 52 B `PreparedSolidRasterPanel`，纵向 bounds 只作为临时标量参与选带，删除 60 B 临时记录及其压缩复制。6,720 组主机与 11×96 帧真机哈希一致，panel prepare 约 9.80→9.44 ms，周期约 73.29→73.10–73.16 ms，固件再缩小约 272 B，已接受。
- 独立 RX-78 平面分类内核：把顺序 normal/plane-constant 分类从约 26 KiB 的单体 `render()` 提取成独立 O3 函数，使后续命令代码变化不再持续扰动剔除布局。6,720 组主机与 11×96 帧真机哈希一致，cull 约 2.52→2.27 ms；其他阶段回吐部分收益后，周期仍稳定到 73.02–73.08 ms，已接受。
- 生命周期级 sparse nearest scale-map：固定 276→424 路径的 source-X 目标跨度和 source-Y 行号不再由两个核逐帧重复计算，而是在 worker 创建时生成约 1.9 KiB internal 只读映射。6,720 组主机与 13×96 帧真机哈希一致，blit 约 5.05→4.90 ms，周期约 73.04→72.86–72.92 ms；internal free 约 19.2 KiB、最大连续块 7.5 KiB、worker 栈余量约 4.7 KiB，已接受为固定比例 nearest composite 的框架缓存。
- 放宽为“有限、稳定、肉眼不可感”后重验浮点语义：整个 `render()` 启用 `fast-math` 时，4,480 帧中 98 帧共 135 像素差，单帧最多 4 像素且无连续 yaw 差异，但真机周期恶化到 75.855 ms，已回退。两次 Newton 修正的近似倒数也无收益：扫描边斜率保持零像素差但周期 73.022 ms；`1/det` 最坏仅 4 像素差，却恶化到 74.522 ms。Xtensa 上近似倒数的算术/代码布局成本高于软除法节省。
- 深度/颜色 32-bit 交错写回：只将受 PSRAM 限制的上半屏改为一次合并写，下半屏保持两块 76 KiB 片内平面。6,720 组主机和真机哈希一致；raster 只小幅改善，但 composite 因不再能顺序读 color 由约 4.90增至 5.58 ms，6×96 帧周期平均 73.641 ms，已回退。框架数据布局要按完整生命周期评估，不能用单一写阶段的事务数做结论。

### 联合扫描实体四边形（主机否决）

为减少每个纯色面片的两次三角形 setup 和共享对角线 overdraw，实现过一次保持原 ABC、ACD 重心公式与先后写入语义的四边形联合扫描原型。288 个连续 RX-78 姿态与完整 6,720 组回归均逐像素一致；首版每个候选像素计算两组三角形重心时，主机均值 1,239.32→1,245.62 µs。利用 AC 对角线符号仅计算所属侧、epsilon 重叠区仍按原顺序处理后，均值进一步恶化为 1,245.11→1,287.05 µs。

### 上下半屏有序面片索引（否决）

双核按上下半屏光栅时，两个核原先都按原顺序遍历全部 2,744 张 prepared panel，再由纵向 bounds 快速拒绝不相交面片。实验在串行准备阶段同时建立两个 `uint16_t` 索引流：单个固定姿态的上半屏只需遍历 1,130 张，下半屏只需遍历 830 张，仍保持各自原始提交顺序。

18 轮各 96 帧真机基准均保持整屏哈希 `3117305473:2106701825`。相对片内占用位图基线，CPU0/CPU1 光栅分别从 40.080/40.150 ms 降到约 39.62/39.45 ms；但每帧向 PSRAM 写两个索引流使串行 panel prepare 从 12.498 ms 增到约 13.17 ms，完整 raster 从 53.381 ms 增到约 53.51 ms，draw 从 82.489 ms 增到约 82.64 ms。局部并行工作减少而总帧变慢，因此完整回退。

框架结论是：分带 binning 不能只计算消费者少扫了多少命令，还必须计入生产者的串行写入和新增工作集。若资产/命令构建阶段能直接产出各带有序命令流，或能复用已有元数据而不逐帧写外存索引，可重新评估；当前“先生成完整命令，再串行派生索引”的形式不成立。

### 双核面板命令准备（否决）

为继续压缩约 11 ms 的串行面板准备，实验先按最终 pass 顺序建立可见面索引，串行懒投影共享顶点，再让 CPU0/CPU1 各自生成一半紧凑命令。近裁剪或非纯色面仍自动回退原路径；主机 6,720 组回归和真机 10 轮 96 姿态的整屏哈希均保持 `2762865317:502579254`。

但新 staging 的代价超过并行组装收益：两个核的命令组装各约 5.6–5.8 ms，`panel prepare` 却从 10.931 ms 增至约 13.78 ms，`raster` 约 53.5 ms，完整周期稳定落在 94.90–95.19 ms，相对 92.238 ms 基线慢约 2.7 ms。该实现完整回退。框架结论是：把阶段拆成并行任务并不自动减少关键路径；若拆分前必须新建外存索引、改变共享顶点访问局部性或增加串行预处理，必须把这些 staging 成本计入 A/B。

### V-fin 端盖三角扇打包

RX-78 的两个 V-fin 刀片各有前后两个四边端盖，原先每个端盖以四张退化三角面板表示。它们共面、同材质且共享同一扇心，因此可按原径向对角线两两打包；面板总数从 2,744 降至 2,736，唯一顶点数不变。27 个 640×640 结构视图跨版本逐字节一致，6,720 组主机回归和真机全方位哈希也保持 `2762865317:502579254`。

共享顶点 `ready` scratch 固定为 16,384 B，但 RX-78 当前只有 2,670 个唯一顶点；每帧写一次、随后在两个 pass 中读取的 2,736 个 face pass 标记原本仍位于 PSRAM。两者生命周期相同且空间不重叠，因此把 pass 标记放入 `ready[count...]` 的片内闲置尾部，分配失败或容量不足时仍回退原数组，不新增 internal RAM。

### 实体三角形紧凑顶点 ABI

通用三角形内核原本按值接收三个 20 B `CarScreenVertex`，其中 `uDepth/vDepth` 只被贴图路径使用；RX-78 的 prepared solid 热路径仍为每个三角形搬运这 24 B 无用字段。现在让共享内核的顶点类型模板化，纯色专用实例改用只含 `x/y/depth` 的 12 B `SolidScreenVertex`，通用贴图、近裁剪和安全回退仍保留原结构与数学顺序。

6,720 组主机像素回归通过。真机使用完全相同采样器，按候选→回退→候选三次独立构建与重启：第一轮候选 8 组、回退基线 9 组、第二轮候选 9 组，每组 96 个全方位姿态；所有批次整屏哈希均为 `1794963570:3828763871`。两轮候选合并均值为 88.337 ms，基线为 88.662 ms，稳定净省 0.324 ms；raster 约从 49.27 降至 48.91 ms，固件同时减少 672 B。

这是一次小而稳定的调用边界优化：端到端约改善 0.37%，当前约 11.32 FPS。框架原则是：共享算法不等于共享最宽数据 ABI；应让纯色、贴图等编译期专用实例只携带各自真正消费的插值量，尤其是在按值传参且寄存器紧张的 MCU 上。

随后三项内循环实验均未保留。第一项为 prepared target 每行形成 depth/color 行指针，避免逐像素减 band offset；主机像素一致，但真机 raster 从约 48.91 增至 49.93 ms、周期约 88.34→89.36 ms。第二项把三个扫描边交点改成逐行增量，同时保留最终重心覆盖和深度计算；6,720 组逐像素一致，但 6 组真机 raster 约 49.96 ms、周期约 89.33 ms。两者都以更多长生命周期局部状态换取少量算术，在 Xtensa 热内核上因寄存器/栈压力反而退化。

第三项只对 prepared solid 内部 span 使用增量深度，主机首个 RX-78 65% 失败视图即出现 2 个最终遮挡像素变化，因此没有进入真机。边界候选可以近似后再由精确谓词裁决，深度却直接参与 Q13 量化与等深覆盖顺序；框架必须把这两类数值区分开，不能因为输出差异很小就合并接受。

raster 减少 1.215 ms，完整周期净省 1.302 ms；候选固件增加约 2.4 KiB。框架原则是：稳定的帧/命令级策略应在热循环外完成分派，并用独立编译实例消除每像素成员读取与分支；只特化真实产品热组合，冷路径继续共用安全实现，避免无界代码膨胀。

### 包络证明的近裁剪特化

共享顶点索引时额外累计模型的最大水平半径平方和 Y 范围。每帧结合 camera pivot，使用保守包围球判断 `7 - radius > nearPlane`；成立时，紧凑纯色命令生成不再为每个新顶点判断近面，也不再为每个面角读取投影深度并检查 `z==0`。包络不成立的模型、视角或未来几何自动使用原通用裁剪路径。

RX-78 的 Display/Salute/Saber、装备开关和两个 pivot 均验证：最坏相机深度仍大于 4.4，远高于 0.2 近裁剪面。6,720 组主机逐像素回归通过；设备 9×96 帧哈希仍为 `1794963570:3828763871`：

| 路径 | panel prepare | raster | draw | present | 周期/FPS |
| --- | ---: | ---: | ---: | ---: | ---: |
| 通用近裁剪检查 | 11.531 ms | 46.985 ms | 74.451 ms | 11.899 ms | 86.351 ms / 11.58 |
| 包络证明后专用实例 | 10.677 ms | 46.125 ms | 73.576 ms | 11.909 ms | 85.485 ms / 11.70 |

完整周期净省约 0.866 ms，几乎全部来自串行命令准备。框架原则是：只有可由资产包络与相机参数证明的不变量才能进入无检查热实例；证明应保守、廉价、在几何变化时自动重建，失败则回到完整裁剪，而不是靠场景经验删除安全分支。

同轮用 48 个连续 RX-78 全帧离线量化了新旧帧 dirty tile 并集。16×16/24×24/32×32 分别覆盖全屏 86.6%/95.2%/99.5%；8×8 可降至 71.0%，但平均约 410 个独立水平 run。旋转房间网格触及每个 tile row 的左右两侧，使“每 tile row 一个 bbox”直接退化为 100% 全屏。结合驱动每个矩形都需重新设置窗口和启动传输，面积收益不足以覆盖事务数量，按预设停止门槛不进入 HAL 多矩形实现。瓦片只有在场景的空间局部性也成立时才能降低提交成本；单看模型轮廓稀疏度会严重高估收益。

另外尝试在共享索引阶段证明整个 RX-78 资产全为纯色，以便后续每面紧凑路径不读 `paint`。主机 6,720 组像素回归和真机整屏哈希均一致，但10 组完整周期均值约 85.62 ms，相比 85.49 ms 基线慢约 0.14 ms。模型级状态、分支组合和代码布局成本高于一次可预测材质读取，因此已回退；可证明不变量仍必须以端到端帧时决定是否值得保留。

### 双 framebuffer 异步整屏提交

AMOLED framebuffer 原路径在外层 `endWrite()` 中把 468×466 RGB565 逐行拷入两个 DMA 缓冲并串行等待 QSPI，稳定占用约 11.9 ms。新的 HAL 可选模式额外分配一张 PSRAM framebuffer：完成帧交给 CPU1 常驻提交任务，同时主渲染器在另一张缓冲开始下一帧。模式只由 Museum 在停止 LVGL 后启用；分配失败自动保留同步路径，退出时等待末次传输完成并恢复最后已提交缓冲。

6,720 组主机回归通过；14 组各 96 帧真机整圈哈希均为 `1794963570:3828763871`。稳态平均：

| 路径 | draw | 同步 present | 实际 panel tx | background | 周期 / FPS |
| --- | ---: | ---: | ---: | ---: | ---: |
| 单 framebuffer 同步提交 | 73.58 ms | 11.91 ms | 11.91 ms | 12.36 ms | 85.49 ms / 11.70 |
| 双 framebuffer 异步提交 | 约 79.00 ms | 0.095 ms | 约 18.00 ms | 约 17.93 ms | 79.10 ms / 12.64 |

传输和下一帧连续清屏同时访问 PSRAM，使两者各自变慢；因此没有隐藏全部 11.9 ms，但端到端仍稳定净省约 6.39 ms。框架原则是：显示 DMA 流水化必须保证发送源在传输完成前不可写；同时必须用整帧时评估共享外存带宽争用，不能只看 API 返回时间。

在此基础上，将原来每行 936 B 的 DMA 提交改为打包 4 行后提交，仍使用双片内缓冲交替搬运，实际像素序列不变。10×96 帧 framebuffer 哈希全部一致：panel tx 由约 18.00 ms 降到 17.55 ms，周期由 78.63 ms 降到 78.519 ms（约 12.74 FPS）。4 行方案比单行多占约 5.6 KiB 片内 RAM，仍有约 23.4 KiB internal free/9 KiB 最大连续块。8 行方案将 panel tx 小幅降到约 17.51 ms，但 internal free 仅剩 15.9 KiB，收益几乎饱和，因此回退到 4 行。

随后将 RX-78 已证明的已选带、可信深度、split target 和稀疏记录合并为上/下带两个无运行时策略判断的回放入口。主机 6,720 组与真机 9 组整圈哈希一致，但周期均值约 79.24 ms，相比 79.10 ms 基线慢约 0.14 ms。这证明已经上升到面板级的可预测分支已不是足够大的优化单元；新 wrapper 和指令 cache 布局影响会抵消它，因此已回退。

### 预计算面剔除平面常数

RX-78 面法线和 anchor 原本以两条流存储，每帧剪枝计算 `dot(normal, eye-anchor)`。资产建立时新增 `dot(normal, anchor)` 常数流，RX-78 专用路径改为 `dot(normal, eye)-constant`；通用模型仍保留原计算。虽然浮点结合顺序改变，6,720 组主机测试与 9×96 帧真机整屏哈希均通过，未改变任何最终像素。

9 组稳态周期为 78.732/78.761/78.521/78.752/78.516/78.552/78.514/78.577/78.729 ms，均值 78.628 ms（约 12.72 FPS）；cull 均值约 2.617 ms，相比异步提交基线的约 3.49 ms 下降 0.87 ms。总周期净改善约 0.47 ms，差额主要来自与显存传输并行时的 PSRAM 竞争。代价是多 16 KiB PSRAM；不占额外片内 RAM。框架原则是：静态几何的粗筛应优先离线化面方程常数，但任何浮点重排都必须通过最终 framebuffer 一致性验收。

### Wi-Fi 生命周期隔离与光栅 IRAM

设备在无 AP 时以 10/20/40/80 s 退避周期扫描，日志时刻与基准中的少量慢批次对齐。Museum 现在只在进入时记录原 station 需求并暂停 station，退出时恢复；不擦除凭据，不干预配置 AP。11×96 帧内扫描日志完全消失，哈希一致，周期约 78.52→78.38 ms，且原扫描批次的尖峰被消除。

随后将包含 RX-78 实体三角形内核的 `preparedSolidPanelRows` 放入 IRAM。该实例约 5.3 KiB，大量浮点 literal 使默认链接超出 Xtensa `l32r` 范围；仅对 `museum_renderer.cpp` 启用 `-mtext-section-literals` 后链接通过，避免影响全局代码生成。9×96 帧哈希全部一致，raster 均值约 46.35→45.83 ms，周期均值 78.38→77.83 ms（12.85 FPS）。DIRAM `.text` 增加 5,428 B，稳态运行时 internal free/min/largest 约为 21.3/19.4/9 KiB。框架原则是：IRAM 只放经 profile 确认的高频内核，并同时验收连接段定位、字面量与运行时堆余量。

将整个 `museum_renderer.cpp` 从 O2 改为 O3 的对照则被否决。虽然两个核的纯光栅各快约 0.05 ms，但固件增大约 14 KiB，panel prepare 由约 10.77 增至 11.10 ms，blit 由 7.71 增至 8.90 ms，3 组完整周期为 79.636/79.550/79.562 ms。所有哈希一致但显著慢于 77.83 ms 基线，因此恢复 O2。框架应对 profile 确认的函数单独提升优化等级，不要用全翻译单元 O3 扩大 I-cache 工作集。

另一个逐像素对照在稀疏纯色专用内核中检查现有 Q13 深度与 RGB565 颜色，若两者都与新值相同则跳过 depth/color/occupancy 幂等写回。该规则不改变最终内存，6,720 组像素回归通过；但真机 raster 约 45.83→46.47 ms，3 组周期 78.597/78.583/78.583 ms。额外颜色 PSRAM 读取和每像素分支明显高于共享对角线的写回节省，已回退。

将法线和平面常数合并为 16 B 连续 `CullPlane` 的数据布局试验使 cull 从约 2.61 降至 2.49 ms，但 panel prepare/raster 均小幅变慢。10×96 帧哈希一致，周期均值约 77.83 ms，与原分离流基线无实质差异。该布局还会改变共用 `Mesh` ABI 并波及其他渲染模块，因此已回退；局部阶段改善不足以支持跨框架 ABI 复杂度。

### 双核原生稀疏 composite

65% 路径的光栅平面为 276×276，最后依据 occupancy 位图将可见颜色 nearest-expand 到 424×424 framebuffer。光栅上下带完成后 CPU1 原本空闲；新路径让 CPU0/CPU1 分别 composite 上下互不重叠的输出行。两核共享只读 depth/color/occupancy，仅写各自 framebuffer 行，每行的 sourceY/sourceX 采样、RGB565 字节序和覆盖规则完全不变。

13 组各 96 帧整屏哈希全部为 `1794963570:3828763871`。前 10 组周期为 75.351/75.289/75.305/75.301/75.280/75.301/75.287/75.330/75.280/75.314 ms，均值 75.304 ms（约 13.28 FPS）；blit 由约 7.71 降至 5.10 ms，端到端相对 77.83 ms 基线净省约 2.53 ms。框架原则是：不只光栅图元可分带，只读源+互斥输出区域的 composite 同样是低风险双核阶段；分带应按实际稀疏工作量而不是像素面积继续平衡。

## 正确性与剩余差距

- `tools/test_gundam_museum_perf.sh`：`pixel_identical_cases=6720`。
- `tools/test_gundam_museum.sh`：几何、构图、控制和重入通过。
- ASan/UBSan 两套测试通过。
- 65% 隔离设备基准在批量行带回放、紧凑索引光栅命令、独立 O3 剔除、生命周期 nearest 映射、异步显示阶段重排和精确四边形行内核之后，稳态 10×96 帧平均周期为 67.602 ms（约 14.792 FPS），固定序列哈希为 `1794963570:3828763871`。距离 15 FPS 的 66.67 ms 周期仍约差 0.94 ms；CPU 软件光栅仍是主要剩余项，尚不能宣告达到硬件上限。

精确四边形行内核单独计算 ABC/ACD 的精确行区间，再在同一行循环内按原顺序回放；因此没有联合外轮廓过扫描，也没有逐像素对角线分类。主机 6,720 组逐像素一致，真机则从 71.799 ms 改善到 70.228 ms；尽管主机微基准约慢 2%，MCU 端的实际访存和分支行为使它稳定受益。

随后将 RX-78 命令改为 12 B 索引记录：四个 16-bit 键指向已在片内 RAM 的共享投影点，不再为每张面向 PSRAM 复制四个 float3。索引和通用 52 B 命令在同一 union 中互斥使用，因此最终无新增 PSRAM 工作集。主机 6,720 组与 ASan/UBSan 逐像素回归通过，真机 10×96 帧由 70.228 降至 68.264 ms，panel prepare 约 10.09→8.40 ms，panel DMA 约 13.90→12.87 ms。这证明“紧凑命令 + 片内共享顶点池”比“完整投影顶点命令”更适合双核嵌入式软件光栅。

继续将活跃的 2,048 条 12 B 索引命令优先放入 24,576 B 片内缓冲，分配失败或命令溢出时会完整回退到 PSRAM union。主机 6,720 组逐像素回归通过；真机稳态 10 组 draw 为 67.991/67.994/67.985/67.987/67.994/68.004/67.985/67.989/67.967/67.986 ms，均值 67.988 ms（14.708 FPS），全部哈希 canonical。相比 68.264 ms 再减少 0.276 ms；internal minimum free 约 26.3 KiB、largest block 约 14.8 KiB、worker stack free 约 4.6 KiB。这进一步确认命令流的存储层级也是框架性能约束，但需用显式回退保护紧张的片内内存。

索引命令生成继续删除了每面四顶点的水平 `left/right` 求界：并行行带只需 `top/bottom`，水平裁切已由光栅内核精确执行。主机 6,720 组逐像素回归通过；真机 10 组 draw 为 67.633/67.592/67.602/67.605/67.598/67.599/67.599/67.611/67.601/67.583 ms，均值 67.602 ms（14.792 FPS），panel prepare 由约 8.40 降到 8.01 ms，哈希全部 canonical。这项相比前一基线再减少 0.386 ms，不改变实际屏幕边界覆盖。

后续已用 20 行、22,080 B 片内深度/颜色工作集验证微带路线。候选在上半屏带内完成后直接扩展到最终 framebuffer，没有 PSRAM 中间回写；现有片内索引尾部容纳了每帧约 2,414 个有序带成员。它将帧尾 composite 从约 5.15 降到 4.04 ms，但跨带图元的重复 setup/回放使 panel prepare 升到约 11.4 ms、主核阶段升到约 36.7 ms，8×96 帧稳定约 75.08–75.15 ms；固定序列哈希也变为 `2103724662:3711746231`。候选已完整回退。片内带本身不会自动提高 FPS；只有持久化跨带 setup/边状态、同时保留原覆盖顺序时才有重开价值。不再重复已否决的单项 early-Z、索引色、分区比例和 strip/微带回放路线。
