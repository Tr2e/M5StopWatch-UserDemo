# GRAND SPIRAL 03：大型立交回环赛道

基线为 `d2d4a58`。本轮新增第三条可选择、可跑三圈并记录独立最佳圈速的赛道；原来的 SKY LOOP 和 TRI CROSS 保留。

## 构型与实现

以[田宫 Japan Cup 2024 的 Hurricane Coil](https://www.tamiya.com/japan/mini4wd/mini4news_01)上升 360° 构型为参考，制作原创路线。它由完整螺旋上升、抬升直道、上层发卡弯、高架横跨、外圈下降和低位 S 弯连接而成；实际起终点位于低位进入螺旋的位置。没有独立分车道、强制换道或腾空跳台。

[生成脚本](../../../tools/generate_grand_spiral.py)以连接位置、切线和端点曲率约束构造五次曲线模块，离线生成 512 段等距 Hermite 节点。运行时沿程查表和插值，避免在帧内生成全程曲线。生成物是只读 C++ 数据，数值不依赖第三方 Python 库。

- 中心线约 232.517 游戏单位，为 TRI CROSS 的 1.66 倍；不等同于官方实际赛道长度。
- 三处投影交叉；主机 1440 段采样中，非相邻近邻中心线高度差最小 3.824，水平检查半径 3.75，覆盖路宽及余量；420 次其他路段附近镜头检查通过。
- 最大坡度的正弦约 0.485，最大横向曲率约 0.276；沿路姿态连续、没有内边缘折返。当前物理仍为沿轨道运动，没有坡度重力或跳跃模拟。
- 新赛道渲染使用 160 段，弯曲较大的路段分配更多样本；中心线与渲染段弦的离线采样最大偏差约 0.0455。旧赛道仍以原始 96 段采样。
- 三角形投影前，用进入赛道时缓存的包围球做保守视锥剔除，包含桥底和护墙。空间上可见、沿程很远的高架仍参与绘制与遮挡。
- 遮挡容量从 624 增为 1008；线条与车辆候选数组移出任务栈，有内部 RAM 工作缓存和对象内后备存储，不按帧分配。
- 新赛道全景按包围范围取景；保留实体道路、护墙、桥底和桥墩，省略远景细线装饰。比赛分辨率和已有边缘修整策略不变。
- 成绩结构升到 V3，显式迁移 V1 的一个圈速和 V2 的两个圈速，保留车型；新赛道成绩独立保存。

## 主机验证

`SANITIZE=1 bash tools/test_lets_and_go.sh` 覆盖几何、流程、运动、成绩迁移、三赛道 192 个有界比赛场景，以及原有 Racer/Vector Run/Launcher 输入与渲染检查。

渲染检查包括新赛道 144 个细节等级/沿程视角组合；剔除开关比较同时验证画面和可见面数量；全景 48 个细节/转角组合验证圆屏文字留白；另有实际设备策略的 128 个三车姿态，覆盖侧移边界和近裁剪。主机图像不代表已真人操纵验收。

对 356 张旧采样参考图的检查，349 张完全相同，7 张只在赛道页的计数数字处变化；变化区域见 [old-frame-comparison.json](old-frame-comparison.json)。这不表示开启边缘修整后的比赛图与关闭时一致。

## 设备实验

实验入口源码保存在 [spiral_device_benchmark.cpp](spiral_device_benchmark.cpp)，仅在测试固件中加入，全局声明后在 HAL/Wifi 初始化完成处调用，源文件以 `-O2;-fno-builtin-memset` 编译。使用正常 App 的 234×233 场景、468×466 呈现、原生玩家、近处对手和边缘修整；同时打开车库以接近正常 App 的内存占用。

8 车型 × 3 赛道 × 13 个快照，首帧预热，每赛道每模式 96 个计时帧；同一快照轮换剔除开/关执行顺序，312 次 CRC 对照在计时外。另对三条赛道分别采 12 个全景转角，将原有细线装饰与简化样式配对计时。两条旧赛道保留相同样式，作为控制组。

第一轮比赛结果接近旧赛道，但全景高细节约 1.15 秒，且最小栈余量仅 108 B，未作为交付版本。第一轮原始记录保存在 [first-pass](first-pass/summary.json)；第二轮移出线条候选数组并简化新赛道全景，再完整复测。两轮耗时不能直接拼接为同一次样本。

最终数据从 [ab-device.log](ab-device.log) 运行 `python3 docs/assets/grand-spiral-lab/analyze.py` 生成 [frames.csv](frames.csv) 和 [summary.json](summary.json)。设备正常固件构建、哈希及启动证据以最终交付记录为准。

本轮只在核验后的 StopWatch `/dev/cu.usbmodem83401`、序列号 `44:1B:F6:C1:8A:00` 上写入 `0x20000` 应用分区；另一个设备端口不参与。固定快照与正常启动不替代十分钟带音频的交互稳定性、真实外设操作和主观镜头舒适度验收。

## 最终实测结果

第二轮同固件对照，单位 ms；完整样本见 summary.json。

| 场景 | 平均整帧 | P95 | 最大值 |
| --- | ---: | ---: | ---: |
| 两条旧赛道控制组（合计 192 帧） | 160.219 | 186.184 | 207.151 |
| GRAND SPIRAL，关闭预剔除（96 帧） | 164.682 | 191.240 | 217.427 |
| GRAND SPIRAL，启用预剔除（96 帧） | 161.979 | 191.312 | 208.617 |
| GRAND SPIRAL 全景，细线装饰开启（12 帧） | 1151.768 | 1185.729 | 1185.729 |
| GRAND SPIRAL 全景，简化装饰（12 帧） | 262.608 | 290.385 | 290.385 |

新增赛道平均整帧比本次旧赛道控制组高 1.10%，P95 高 5.128ms。预剔除本身节约平均整帧 2.702ms（1.64%），道路阶段从 20.101ms 到 17.289ms；P95 基本持平，不能把该优化说成所有慢帧都改善。不同赛道的视角和道路覆盖不同，控制组比较用于容量评估，不是对任意布局的性能保证。

全景的简化装饰将平均整帧减少约 77.2%，保留主体几何。对应样例是 [赛道全景](track-2.png)，比赛设备策略图见 [逐段画面](device-quality-contact.png)；图片来自生产渲染器的主机捕获，不是设备屏幕照片。

312 次设备剔除开/关 CRC 一致。新赛道设备样本最多 541 个可见面，主机广角/细节组合最多 797，均在 1008 容量内。第二轮最小剩余任务栈 2060 B；内部 RAM 开局可用 76895 B、结束 76887 B，PSRAM 均为 5493908 B。这是固定序列的观测，未证明所有真实调用链与长期运行的最坏边界。

主机 ABI 下常驻 renderer 对象为 garage 7128 B / race 8040 B，打开时表面缓存为 763176 B / 828992 B；不要将主机 sizeof 当成 ESP32 的实测字节数。设备运行仍沿用原 8192 B 主任务栈，没有通过扩大系统栈掩盖候选数组问题。
