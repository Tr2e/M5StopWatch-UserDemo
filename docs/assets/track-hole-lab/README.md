# 弯道三角形黑洞：复现与修复

问题在 GRAND SPIRAL 的上层回转附近复现；TRI CROSS 的部分带坡弯道也有同类缺口。输入为沿程位置、跟车镜头和侧移，不需要纹理加载失败或快速操作。

## 原因

`drawPencilTrack` 原先用四边形一角的法线决定整段应画路面还是桥底，再将四边形拆为两个三角形。坡度和侧倾变化会让四个点不共面；同一镜头可能在两个三角形平面的不同侧。共用朝向会把其中一片误选为下移 0.22 的桥底，产生暗面及露出背景的三角缺口，转过角度后又恢复。

修复为逐三角形计算自身的法线和朝向，再选择对应的路面或桥底。仍只提交每片的一个面，没有改成生产全双面绘制，也没有扩大缓存、降低分辨率或关闭剔除。原有桥底遮挡保留。

## 证据和验证边界

- [同角度对照](comparison.png)：左侧为修复前，右侧为修复后。用生产道路绘制函数生成，234×233 场景按最近邻放大以看清缺口，省略车辆/HUD；不是设备照片。
- 精确复现：GRAND SPIRAL，`distance = length * 265 / 720`，横向偏移 0，234×233 跟车镜头，Low 道路、关闭装饰。参考固件为上一轮 BIN `82424a546c3e9a073a54910b74f546922aa828aacddba82f3347017f99c7778f`。
- 三赛道 × 720 沿程位置 × 3 横向偏移（-1.36/0/1.36），合计 6480 个姿态。用绘制路面与桥底全部面的参考图做深度解析，检查被错误留为背景的路面像素；参考不依赖正反面判定。
- 修复前，所测最大缺口为 283 个场景像素；修复后最多 1 个边缘舍入像素。指标检查区域为 x=[15,220)、y=[80,225)，不表示全屏所有颜色逐像素相同，也不证明任意未来道路均无问题。
- 新增持久回归 `validateTwistedTrackDecks`：222 个重点弯道姿态，对独立双面参考检查路面覆盖；另继续执行既有桥底遮挡、近裁剪、剔除一致性、三车和完整游戏回归。
- 之前的剔除开/关 CRC 检查只证明剔除没有改变画面，两边共同复用的错误正反面判定不会被发现。本次以独立参考补上该缺口。
- 深度平面扫描最坏相对误差约 3.53%，没有复现整片负深度；直接修复面朝向后缺口消失，因此没有顺带修改深度插值算法。

`pencil_scene.before.h` 保存修复前绘制器；`holes.cpp` 为密集扫描工具，`capture.cpp` 通过 `SCENE_HEADER` 选择前后版本生成指定角度画面。编译使用仓库的主机 HAL、`overpass_track.cpp` 和 `track_types.cpp`，修复前头文件的相对依赖从生产 view 目录解析。原始扫描见 `holes.log` 与 `holes-fixed.log`。

本轮没有重跑完整设备性能基准，不将上一轮平均帧时间当成此固件新实测。正常构建、完整主机检查、StopWatch 烧录与启动分别记录，真人连续转弯的体验仍由实际使用复验。
