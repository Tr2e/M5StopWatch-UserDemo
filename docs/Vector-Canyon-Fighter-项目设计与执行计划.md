# Vector Canyon Fighter：项目设计与执行计划

> 目标设备：M5Stack StopWatch（466×466 圆形 AMOLED，ESP32-S3，8 MB PSRAM）
>
> 本文是项目的执行基线。任何设计、代码、资源和验收结果必须能追溯到本文的目标、约束或已批准的变更。
>
> 当前版本：`v0.1 / 设计基线`

## 1. 项目定义

`Vector Canyon Fighter` 是运行在 StopWatch 上、以第三人称追尾为默认形态的线框战机穿梭游戏，并提供无座舱边框的第一人称全屏 HUD 模式。

玩家驾驶一架原创未来机甲战机，在巨大、起伏、连续生成的线框峡谷中飞行。默认追尾镜头下，战机位于圆屏下中部且尺寸克制；进入沉浸模式后，战机视觉层隐藏，相机完整跟随机体姿态，整块圆屏成为第一人称 HUD。两种模式均由远方消失点、地面网格、峡谷岩壁和障碍共同制造高速穿梭感。

视觉语言借鉴早期飞行模拟与矢量图形的可读性：黑色负空间、有限几何、荧光线框、清晰透视和少量稳定 HUD。它不追求照片级渲染，也不以随机字符、扫描线或高强度光晕填充画面。

## 2. 已冻结的体验意图

| 项目 | 决策 |
| --- | --- |
| 镜头 | 默认第三人称追尾；K1 沉浸模式为无座舱边框的第一人称全屏 HUD |
| 战机 | 原创、具航空/机甲结构感的线框战机；不复刻特定作品机体 |
| 战机占比 | 约为可见圆直径的 12–18%，位于下中部 |
| 环境 | 连续线框峡谷、地面网格、起伏坡面、可读的前方航道 |
| 飞行感 | 以近景几何快速扩张、远景消失点收束、地形推进和有限镜头响应体现 |
| 姿态反馈 | 战机滚转、俯仰、横移与喷口反馈必须可见；镜头不应频繁剧烈摇摆 |
| 临时输入 | IMU + StopWatch A/B 键 |
| 最终输入 | Unit Joystick2 + Unit Dual Button；保持与临时输入同一动作语义 |

外设电气拓扑已另行记录在 [科技游戏外设接线设计.md](科技游戏外设接线设计.md)。

## 3. 目标与非目标

### 3.1 成功标准

1. 玩家在 3 秒内看懂：战机正向前飞行、前方航道的风险、当前速度和可执行输入。
2. 静止截图也能识别战机、峡谷深度和前进方向；关闭装饰特效后仍成立。
3. 速度、转向、爬升和滚转均有可预测、低延迟、可观察的反馈。
4. 在真机最复杂场景中保持稳定交互，不因绘制、内存或外设读取造成卡顿。
5. 外部控制器接入时只替换输入提供者，不重写游戏规则或渲染逻辑。

### 3.2 非目标（v0.1）

- 不实现照片级光照、纹理贴图、实时阴影或通用 3D 引擎。
- 不制作可变形、可切换为人形的机体；战机以单一飞行形态实现。
- 不在首版加入联网、排行榜、复杂剧情、关卡编辑器或多机战斗。
- 不用高频闪烁、随机数据字符或 CRT 效果替代空间、速度和状态表达。

## 4. 不可违反的设计约束

### 4.1 圆屏与可读性

- 所有核心战机、航道、危险提示、速度和主操作位于圆形安全区内。
- 战机不能遮挡消失点或主要障碍预判区。
- HUD 只承担状态，不与峡谷线框争夺最高亮度。
- 灰度下仍能区分战机、可飞行区域与危险。

### 4.2 输入通用性

游戏核心只能接收规范化动作，不能直接依赖某个 GPIO、I2C 地址或按键型号。

```text
InputProvider → FlightInput → FlightModel → SceneState → Renderer
```

`FlightInput` 的规范化语义固定为：

| 动作 | 范围/类型 | 语义 |
| --- | --- | --- |
| `steer` | -1.0 ~ +1.0 | 左/右转向或横移请求 |
| `pitch` | -1.0 ~ +1.0 | 爬升/俯冲请求 |
| `throttle` | 0.0 ~ 1.0 | 持续速度目标 |
| `boost` | 持续状态 | 按住期间加速，释放后衰减 |
| `actions.pressed` | 动作位集合 | 暂停、重置、沉浸、重新校准、油门步进等一次性请求 |
| `actions.held` | 动作位集合 | 可跨固定模拟步保持的动作状态 |

轴设备和动作设备独立表达，首版至少实现以下来源：

- `ImuAxisSource` / `BodyButtonActionSource`：当前临时控制。
- `Joystick2AxisSource` / `DualButtonActionSource`：最终外设控制。

Provider/Router 必须输出相同的 `FlightInput`，并用 `InputStatus` 分别报告轴与动作来源、连接、校准和错误。外设未连接、I2C 读取失败或输入失效时，游戏退回安全的中性输入并显示明确状态。

### 4.3 性能与可靠性

- 渲染只使用有明确预算的线段、切片、文本和可选特效。
- 地形使用循环/复用数据，禁止按帧分配大量对象或无限追加路径。
- 降级顺序固定：装饰特效 → 次级地形线 → 次级 HUD → 主体细节；战机、航道、主状态不得消失。
- 所有外设读取、输入校准和异常处理均不得阻塞 UI 更新。

## 5. 阶段路线与门禁

后续工作严格按下列顺序推进。未满足当前阶段的退出条件，不开始下一阶段的实现工作。

### G0：项目基线（当前阶段）

**目的：** 冻结意图、范围、输入语义、硬件边界与验收方法。

**产物：**

- 本文档。
- 外设电气接线文档。
- 已确认的现有工程基线与目标设备。

**检查表：**

- [x] 明确第三人称追尾为默认模式；K1 沉浸模式切换为无座舱边框的第一人称全屏 HUD。
- [x] 明确战机为原创线框机甲战机，尺寸为圆屏直径的 12–18%。
- [x] 明确峡谷是核心空间表达，非静态背景。
- [x] 明确临时与最终输入的动作语义一致。
- [x] 明确外设红黑共享、黄白隔离的电气方案。
- [x] 项目和 Launcher 显示名统一为 `Vector Run`，使用独立图片图标 `icon_vector_run`。

**退出条件：** 产品方向、控制语义与硬件接线没有未决的矛盾。

### G1：UI / UE 设计

**目的：** 定义一帧就能读懂的画面结构，以及飞行操作全流程的体验反馈。

**必须产物：**

1. 圆屏安全区、第三人称追尾主画面及第一人称全屏 HUD 模式线框图。
2. 战机正飞、滚转、爬升、推进、碰撞风险、暂停、故障/外设未连接的基准画面。
3. HUD 令牌：速度、能量/护盾（如采用）、推进状态、暂停与连接状态。
4. 交互状态机：标题/校准/飞行/暂停/结算或重试。
5. 关键动效的首帧、中间帧、末帧与反向或中断路径。

**检查表：**

- [x] 战机、消失点、近景峡谷、可飞行通道已经过多轮真机构图 Review。
- [x] 飞行、风险、碰撞和暂停已建立明确的一级视觉优先级。
- [x] 巡航与 Boost 由实际速度、地形流速、推进线和马赫环共同区分。
- [x] 滚转、俯仰、局部偏航和世界参考 HUD 已分离并通过双视角 Review。
- [x] 输入异常、风险方向、碰撞、暂停和推进均同时使用文字/形状语义，不只依赖颜色。
- [x] 圆屏安全区、速度/AGL/航向极值、俯仰标签裁切和暂停状态已有固定布局与测试。
- [x] H2 语义审计已删除无数据来源元素，常驻 HUD 均可追溯至真实模型状态。

**退出条件：** UI/UE 基准画面和状态机被确认，可直接作为实现视觉验收基线。

### G2：技术设计

**目的：** 将体验设计转换为低风险、可测试、可替换输入的实现架构。

**必须产物：**

1. 模块边界与数据流图。
2. `FlightInput`、`FlightModel`、`TerrainStream`、`SceneState`、`Renderer` 的职责和接口草案。
3. 线框峡谷的切片/投影算法、裁切规则和固定绘制预算。
4. 输入校准、死区、低通滤波、按钮去抖、失联降级规则。
5. 内存、帧时间和地形复杂度预算；真机基准测试方案。
6. 资源命名、配置常量和调试显示策略。

**检查表：**

- [x] 游戏模型不包含 LVGL、GPIO、I2C 或具体 Unit 类。
- [x] Renderer 只读取场景状态，不读取 IMU、按键或 I2C。
- [x] 临时 IMU/表身按键与 Joystick2/Dual Button 均输出同一 `FlightInput`。
- [x] 外设读取使用独立任务、超时、连续错误计数和安全中性输出，不阻塞游戏循环。
- [x] 显式峡谷使用固定种子、段编号和确定性事件可重放。
- [x] 投影缓存、模型、事件窗口、线段及栈均有编译期/测试上限，每帧无动态场景分配。
- [x] H9 三级地形保护均保留完整横截面、结构纵轨、远景、战机、HUD 和风险反馈。

**退出条件：** 接口、预算和验证策略已经评审；不存在“实现时再决定”的核心架构问题。

### G3：垂直切片实现

**目的：** 先得到从输入到画面的最小可玩闭环，再逐层完善。

**实施顺序：**

1. App 外壳、进入/退出、固定帧循环与调试叠层。
2. 静态战机 + 静态线框峡谷 + 圆屏裁切。
3. 速度驱动的地形推进与循环复用。
4. IMU/表身按键输入、校准和安全中性状态。
5. 姿态、碰撞风险、暂停与重试。
6. HUD、反馈、音效/振动（如采用）和视觉细节等级。

**每个切片检查表：**

- [x] G3 各切片均有 G1/G2 依据和独立评审资产，无未记录玩法。
- [x] 真机可从 Launcher 反复进入、退出和重新校准。
- [x] 生产地形种子锁定为 `0xC4A71001`，Host 重放和真机场景一致。
- [x] 完整 ESP-IDF 5.5.4 构建、固定内存门禁、主/异步任务栈水位和无阻塞输入均已验证。
- [x] 地形、战机、双视角、HUD、风险、暂停、巡航和 Boost 均已经多轮截图/录像/真机 Review。
- [x] App/Launcher 进退、K1/K2 系统组合键和 LVGL 停止/恢复生命周期保持不变。

**退出条件：** IMU + 表身按键状态下完成可玩闭环，并通过真机性能基线。

### G4：外设接入与兼容验证

**目的：** 接入已完成电气连接的 Joystick2 + Dual Button，而不改写游戏核心。

**检查表：**

- [ ] 通电前接线文档的万用表检查全部通过。
- [ ] Joystick2 在 GPIO10/11 的 I2C 总线上稳定识别为 `0x63`。
- [ ] Dual Button 在 GPIO3/4 上有稳定的按下/释放与去抖结果。
- [ ] 外设断开、重连和 I2C 读取失败均进入安全中性状态。
- [ ] 临时输入与外设输入可切换，飞行模型和渲染器无修改。
- [ ] 外设接入后帧率、输入延迟与耗电记录未突破 G2 预算。

**退出条件：** 最终外设在真机上稳定可用，且 IMU 备选控制仍可工作。

**目的：** 将设计、实现、性能和可恢复性作为一个整体验收。

- [ ] 目标设备录像覆盖最长持续飞行和最复杂峡谷段。
- [ ] 输入延迟、帧率、内存和耗电测量已记录。
- [ ] 所有默认设置均可安全退出或恢复。
- [ ] 文档、常量、实现与截图使用同一版本号。
- [ ] 未完成项明确列入后续版本，不伪装为已支持功能。

## 6. 路线偏移防护机制

为避免自动化编码或临时灵感使项目偏离，采用以下硬规则：

1. **规格优先：** 没有 G1 画面/状态依据的 UI 改动，以及没有 G2 接口依据的架构改动，不直接实现。
2. **一项一追溯：** 新功能必须标记其关联的阶段、需求和验收项；无关联项即为范围蔓延。
3. **输入隔离：** 禁止在 `FlightModel` 或 `Renderer` 内直接访问 `GetHAL()`、GPIO、IMU 或 I2C。
4. **基准对比：** 每次改变视觉或运动参数，保留固定随机种子、相同输入序列的前后截图/录像。
5. **小步提交：** 一个改动只跨越一个垂直切片；不得把新玩法、重构与美术重绘混在同一变更中。
6. **门禁失败即回退设计：** 验收失败先判断需求、视觉或接口假设，不能仅靠继续堆叠补丁掩盖问题。
7. **变更记录：** 改变本文已冻结决策时，必须记录“原因、影响范围、替代方案、迁移与新增验收项”。
