## 已验证的原型方案

以下内容是清理前验证过的技术方向，生产代码中已经不存在这些类型和接口。如果未来恢复，应依据当时的代码基线重新实现，不应直接假定接口仍然兼容。

- `MelodyNote` 使用 MIDI 音高、十六分音符时值和连音标记；音高 0 为休止，时值范围 1–255。
- `legato` 连接到下一颗有音高的音符；相同音高形成延音线，不同音高保持包络连续。末音也可连接循环首音，连接休止时正常收音。
- 主旋律与伴奏独立计时。音符和伴奏步进均累计不足一个采样的余数，避免短音符长期循环后节奏漂移。
- 自定义比赛曲谱可设置 30–300 BPM；最后一圈保持原有 176/152 的提速比例，延续音符进度和振荡器相位。
- 暂停恢复保留播放位置；无效或未指定曲谱使用原有安排。车库、结果页面不受比赛曲谱影响。
- `RacerAudio` 构造函数可传入曲谱，由现有音频任务播放。音符数组须在播放器整个生命周期中保持有效且不可变，通常使用 `static constexpr`。

未来可采用类似下面的数据表达；示例只演示格式，不是目标歌曲，也不是当前可编译接口：

```cpp
static constexpr lets_and_go::MelodyNote exercise[] = {
    {69, 1}, {0, 1}, {72, 3, true}, {72, 1, true}, {76, 2}, {0, 4}
};
lets_and_go::MelodyScore score{exercise, std::size(exercise), 137};
// 恢复实现时可提供 valid() 检查音高、时值和速度范围。
lets_and_go::RacerAudio audio(sampleRate, score);
```

原型只替换比赛主旋律。若恢复完整编曲，还需按实际曲谱调整现有 A 小调八小节贝斯/琶音和声、乐句长度及循环衔接；三连音等非十六分音符整数倍节奏也需要在曲谱核对后扩展时间单位。

## 原型验证结论与资源边界

- 清理前的实验性音频测试曾通过 ASan/UBSan：四种采样率、分块一致性、休止采样长度、长音与延音线等价、跨音高连音、分数采样累计、提速中的相位和休止进度、无效曲谱回退、14 种提示音、暂停恢复及幅度边界。
- 清理前的音频生命周期实验曾通过 ASan/UBSan：100 次并发打开/关闭，其中 50 次使用自定义曲谱，同时覆盖不可用和竞争流。
- 由修改前后生产合成器生成的原有场景串联 WAV 经 `cmp` 比较逐字节一致。
- 当时的 ESP32-S3 固件编译通过，但未烧录原型，也未做设备音频与比赛并行性能验收。
- 主机 `sizeof(ChipSynth)` 从 76 增至 128 字节；这不是 ESP32 结构体大小的实测值。音符表只保存指针，渲染期间没有新增动态分配，没有新增声部、音频缓冲区或音频解码器。
- 主机初步微基准：`-O2`、44.1 kHz、每块 512 样本，每次合成 60 秒比赛 BGM，五次中位数为旧版 17.52 ms、新版默认曲 19.85 ms、自定义练习曲 20.48 ms。三组范围分别为 14.79–25.71、17.06–33.99、17.81–35.75 ms，存在明显主机波动；不能据此宣称 ESP32 帧率不受影响。

原型测试曾放在 `tools/lets_and_go_audio_test.cpp` 和 `tools/lets_and_go_audio_lifecycle_test.cpp`；其中实验用例现已移除，两个文件恢复为现有原创 BGM 的基线测试。未来恢复曲谱功能时，应重新加入上述时值、连音、节奏累计和生命周期覆盖。

## 未来恢复条件与实施顺序

只有在重新明确音频方向并取得合法、可核对的曲谱素材后，才应恢复实现。建议顺序如下：

1. 获取可用素材，确认版本、主旋律音高、时值与目标片段，不根据不完整和弦页猜旋律。
2. 先输出主旋律试听，核对辨识度，再编排贝斯、鼓点与循环衔接。
3. 按原型结论重建定长曲谱数据、分数采样累计、休止、连音、最后一圈无缝变速和无效数据回退；音频回调中不得动态分配。
4. 恢复主机回归，确认默认原创 BGM 逐样本不变，并覆盖四种采样率、分块一致性、幅度边界和并发生命周期。
5. 检查频繁碰撞/加速提示音下的 BGM 压低与恢复效果。
6. 在正确识别 StopWatch 串口后，比较比赛帧耗时、音频回调耗时、任务栈和断续情况，再决定是否实机交付。
